# 跨模块写作：一条跨模块链路或一个跨仓契约

任务 spec 中 `type` 为 `chain` 或 `contract`，`item` 是规划阶段给出的条目，其中 `questions` 是必须回答的问题。

## 通用要求

- 先读涉及模块的 README.md、interactions.md 和相关子功能文档。**已有文档讲过的内容只引用，不重复**；你要写的是它们之间的部分。
- 去代码里确认模块之间的连接点：调用、消息、共享数据、通知或订阅机制。每条结论要有代码引用。
- 用领域问答工具（如已配置）追问设计原因和历史问题。
- 回答不了的问题写入待确认问题。

## type = chain → `knowledge/chains/_cross/<id>.md`

使用模板 `cross-chain.md`。重点：
- 因果关系：谁的什么动作，经过什么机制，引起谁的什么变化。
- 时序与一致性：两边的周期是否对齐、中间状态会不会被另一方看到、并发时怎样。
- 故障传播：一边出问题时另一边会表现出什么现象——这对问题定位极有价值。

## type = contract → `knowledge/contracts/<id>.md`

使用模板 `contract.md`。**接口定义本身在代码里，不要复制字段列表**，只给出定义位置。重点写定义看不出来的：
- 字段取值的业务含义与合法范围，特殊值（0、-1、空）的含义。
- 调用顺序、频率限制、幂等性。
- 版本兼容规则：哪一侧先升级、新增字段如何处理。
- 失败语义：超时、部分成功时双方各自怎么处理。
