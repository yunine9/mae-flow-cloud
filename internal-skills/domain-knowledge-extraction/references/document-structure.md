# 领域知识的两层组织

下面是首次生成时的建议结构。已有文档组织优先，默认根目录见 [默认归档位置](archive-defaults.md)。萃取阶段平台提供逻辑归属和根目录；用户在归档阶段选择实际目标仓与目录，平台统一映射。不能把工作区父目录当作归档仓。

## 领域知识仓

```text
<领域归档根目录>/
  README.md                 # 本领域概述、业务模块与知识入口
  glossary.md               # 术语、代码对应物、容易混淆的概念
  architecture.md           # 跨仓依赖、分层职责、每跳协议
  domains/<业务域>.md        # 实体、状态迁移、完整场景、规则归属
  interfaces/<方向>.md      # 跨仓超时、重试、幂等、版本约定
  external/<系统>.md        # 已证实的外部依赖与限制
  decisions.md              # 有真实来源的历史决策，按需创建
```

领域文档围绕业务能力组织，列出规则由哪个仓或模块实现、条件与例外、重要失败路径，以及可核对的来源。无法从来源证明的迁移或原因留在问题记录中。简单主题可合并，不为凑齐目录创建空文件。

## 业务代码仓

```text
AGENTS.md                    # 仅增补知识发现入口，保留已有指令
<仓内文档根目录>/
  module-map.md              # 用户功能词 → 模块 → 代码入口 → 文档
  rules/                    # 仅在有跨模块约定时创建
  modules/<模块>/
    <模块>.md                # 能力、依赖、边界、业务场景、规则与流程
    experience/<机制>.md     # 多步真实排查案例，有证据才建
```

模块主文档按实际需要包含：本模块向用户提供什么、依赖谁完成什么、重要职责边界；典型场景的参数/校验/执行/结果；不可忽略的异常、状态或资源约束；典型实现或测试入口。简单排查经验一行写在主文档，复杂经验链接 `experience/<机制>.md`。

仓内规范只收跨模块约定；已有工具强制的格式规则引用配置即可。跨仓规范引用领域知识，不复制整段正文。

AGENTS.md 可增补如下入口并填入实际路径：

> 本仓 `<文档根目录>/` 维护业务知识与排查方法。需要业务事实时先查模块索引及相关文档，未命中时继续查代码；引用时标明文档路径，文档与当前实现冲突时记录差异。跨仓知识见 `<领域知识入口>`。

## 链接

同仓链接相对当前文件计算，不相对仓根猜路径。跨仓链接使用平台提供的仓库 URL、分支与路径生成的可访问地址；本地工作区路径仅用于本次阅读，不写成可移植的归档链接。目录或目标仓未确定时保存逻辑引用，交给平台渲染与核验。

跨仓 MR 未合并时，界面可链接草稿；正式文档不得假装目标分支已存在文件。平台需在提交前确定跨仓引用的处理方式并提示合并依赖。
