# 本方法如何安排工作

这里的研究顺序属于本 Skill。主会话通过 knowledge_work 自行安排、执行和记录，不等待平台创建阶段，也不能因平台没有自动提示就省略工作。各阶段的具体写法仍使用 phase 文件。

## 接续与范围

先查看工作列表、已有文档及本轮反馈。存在旧进度时用 legacy 读取：保留已通过结果和人工稿，围绕未完成项建立新的工作记录。上下文压缩后同样先查记录，不能凭记忆从头重做。

普通讨论直接读取选中文档和必要依据后回答，不建立全量研究计划。局部修订和更新只围绕选中内容，先核对来源变化，保存建议；不安排无关模块研究。

单模块验证只研究 probe.module。资料和源码中出现其他模块时仅核对必要依赖，不扩展研究范围。以下全量安排要据此缩小，省略全域跨模块阶段。

## 全量萃取

1. 安排盘点步骤。instructions 指向 phase-inventory.md，要求按需查看构建单元、读取源码入口，结合上传资料和豆包梳理模块。结果 data.modules 记录模块编号、业务名称、范围、公共/业务类型及依赖。不要拿目录名直接当业务模块。
2. 核对依赖，公共能力优先；相互依赖无法拆开的模块合并后说明。逐模块安排规划步骤，使用 phase-plan.md。结果 data.subfeatures 记录子功能和各段待回答的问题；每段应能在一次独立会话中读透。
3. 对每段安排研究步骤，使用 phase-hop.md，保存 data.findings、实际资料编号、代码引用、待确认问题和可用于组装的内容。每一步的 instructions 写清仓库与资料起点、输入结果编号及排除范围，不只写阶段名称。
4. 本模块各段通过复核后，按 phase-common.md 提炼公共内容，再按 phase-assemble.md 逐子功能保存文档。没有公共内容时如实记录结论，不能凑篇数。
5. 按 phase-wrap.md 生成模块导航、必要的子功能交互与仓内设计知识；没有实质内容的文件可省略。前两个业务模块完成并通过复核后保存 paused 结果，说明请用户检查哪些文档；接续计数增加后继续，不能以等待超时代替用户接续。
6. 全量研究按 phase-cross-plan.md 识别跨模块链路和跨仓契约，再按 phase-cross.md 逐项写作。没有实质跨模块关系时记录检查范围与结论，不生成空文章。
7. 按 phase-synthesis.md 汇总术语、需要专家确认的问题和文档导航。检查实际覆盖、文档链接和资料冲突；只保留有内容的文档。过程报告放最终 summary，知识正文保持独立可读。

## 独立复核与返工

上述写作和规划每完成一项，主会话安排一个 readonly=true 的独立复核步骤，instructions 指向 phase-review.md，并给出作者步骤编号、文档编号和要回答的问题。复核者用工具读取原文与原始依据，不依赖作者会话；代码引用用 knowledge_source_check 核实。

复核结果放 data.pass 和 data.feedback。通过后才安排依赖其结论的写作；退回时主会话新建修订步骤，附具体反馈和原文版本，再独立复核。同一问题三次仍未解决时记录缺口，明确放弃不适用的步骤或保存暂停结果；其余没有依赖的工作可以继续。平台不会替本 Skill 判断反馈含义或自动重试研究。

工作编号和结果格式由本方法自行定义。通过 steps.depends_on 表达已存在步骤的依赖，逐批安排即可，不预先引用尚未创建的编号。与当前范围无关的已安排项用 discard 说明原因。
