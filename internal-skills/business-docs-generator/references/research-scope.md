# 确定源码研究范围

首次规划，以及检视意见要求调整研究范围时读取本页。范围以业务模块说明、scope、instructions 和本轮 message 为依据；后续明确的用户要求优先。关联仓表示可用来源，不表示整个仓都属于本业务。

## 自动定位各仓的相关目录

1. 先读业务说明、用户要求和相关资料摘要，提取已有依据的业务入口、接口、实体、配置及其代码名称。用户明确指定目录时以其为主要研究范围；明确禁止读取的目录保持排除，不因追依赖进入。
2. 逐仓用 `component_source list` 查看当前层目录（默认非递归），结合 `search` 搜索上述关键词。沿命中路径读取入口、注册关系或调用实现，确认哪些目录承载本业务。需要分页时只继续与定位有关的结果，不为列完仓库而递归展开全部目录。目录名、仓名和单次搜索无命中都不足以证明业务归属。
3. 将每个仓区分为**本业务实现目录**与**按需依赖路径**。前者覆盖本业务在该仓的完整入口和功能；后者只读取本业务实际使用的函数、类型、协议与必要配置。某仓全部源码确属本业务时可使用全仓范围，保留入口或构建关系依据；公共仓不能仅以 `src/` 或“公共组件”代替尚未定位的业务目录。
4. 在调查结果的 `data` 中保存仓编号、实际目录/文件、归属依据、已确认入口、按需依赖及待核实问题；主会话将简要范围表写入 current-plan。没有本业务实现的仓说明已核对的入口/依赖，只记录其实际角色，不为它安排其他业务的整套文稿。范围仍不清楚时登记具体定位问题，不把“待定位”改成“研究全仓”。

完成标准是：每个关联仓都有本业务的实际目录与入口，或有证据说明只提供依赖/没有本业务实现；尚未确认的归属单独保留。无需证明每个无关目录都无关，也无需用户逐仓填写范围后才开工。

## 范围确定后再深入

调查、写作和核查步骤的 instructions 都传递本项业务目录、必要依赖、用户限制与来源结果编号。新会话按编号回读范围和原始依据，不重新推导成整仓研究；主会话只保留简要范围、发现与引用。

在本业务实现目录内穷举入口及场景，再沿真实 import/include、函数调用、IDL、注册或配置引用追踪共享实现。扩展到新路径时记录“哪个本业务入口需要它、要核对什么”；读取所需实现后回到业务链路，不把被调用公共库的全部功能扩成研究对象。只调用一个公共函数，不能据此为该库其他功能另建业务文稿；公共实现包含本业务关键规则时仍须读清实际分支。

`component_source list/search/read` 可按 `path` 定位目录和文件。构建配置只读取确认业务入口、构建目标或真实依赖所需的文件与片段，不逐个读取公共仓的全部构建文件。

当前 `knowledge_structure` 省略 repository_id 仅列仓；指定 repository_id 会扫描该仓并读取其构建文件，include_dependencies=true 会扫描全部关联仓。公共仓按上述 list/search/read 方法调查；只有已确认整仓属于本业务时才使用该仓结构扫描，只有全部关联仓都符合此条件时才使用全仓跨仓依赖扫描。按实际接口与调用双方核实跨仓关系，无需为获得构建候选而扫描公共仓。

当前 `knowledge_source_check` 校验代码引用前也会扫描所有关联仓及其构建文件。任务包含公共仓时，用 component_source read 核对所引用文件、行范围和符号即可，不为校验几处引用触发整仓扫描；工具校验本身也不能证明业务结论正确。

“完整覆盖”指已确认业务范围内的完整场景，不是仓库所有目录。核查遗漏时对照该范围及真实业务入口；有新证据表明业务还涉及其他路径时再扩展，不能把未展开无关目录本身当成失败。

## 用检视意见纠正已有成果

用户反馈范围过宽、漏目录或混入其他业务时，在原任务按 revise 处理：

1. 读取最新意见、已有文稿清单和受影响正文；能读取原规划和调查结果时沿用其编号与证据。旧规划中的过宽范围随意见修正，不作为要求继续整仓研究的依据。当前会话没有旧过程记录时，用现有文稿的源码引用定位，不重建全套调查。
2. 先给出受影响文稿与处理方式：保留、局部删改、补充缺失场景、建议移除整篇。混合文稿只去掉范围外段落；完全属于其他业务的文稿按平台支持的待确认删除流程处理，保留原稿历史。范围外实现若仍是本业务必要依赖，保留实际使用部分及调用关系。
3. 仅为受影响文稿及引用它们的导航安排修订与独立核查，沿用文稿 ID，保留正确正文和已完成调查；缺少的依据只在修正后的目录与调用链补读。无需重新萃取、清空文稿或对所有仓重新盘点。
4. 有可读取的当前规划时同步范围和文稿清单，排除项注明用户意见或业务依据；旧步骤与历史调查保留。核查应同时确认范围外内容已移除、本业务关键链路未误删、索引和链接一致。最后按既有建议采纳/确认发布流程交给用户，不把提出修改意见当成批准发布或删除。
