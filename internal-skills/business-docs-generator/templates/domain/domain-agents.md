# domain-docs 领域共享知识

> 本目录是多仓共享的领域知识**单一事实来源**。
> 模板来源：`templates/domain/domain-agents.md`

## 一、目录结构

```
domain-docs/
├── AGENTS.md                  ← 本文件
├── glossary.md                ← 术语表（业务词 ↔ 代码实体，易混称，错误码）
├── architecture.md            ← 架构全景（调用链、分层、协议、部署拓扑）
├── domains/
│   └── <域>.md                ← 业务域全链路（链路、规则归属表、场景时序图、排查路径）
├── interfaces/
│   └── <仓A>-<仓B>.md         ← 跨仓接口契约（协议、方法签名、超时/重试/幂等、变更记录）
└── external/
    └── <外部系统>.md           ← 外部系统画像（接口、数据格式、依赖关系）
```

## 二、维护规则

1. **单一事实来源**：跨仓知识只在本目录维护一份，各仓文档通过引用指向此处，不得在各仓复制
2. **变更同步**：接口变更时，必须同步更新 `interfaces/` 下对应契约文档；业务规则变更时，必须同步更新 `domains/<域>.md` 的规则归属表
3. **新增域文档**：当识别到新的跨仓业务域时，在 `domains/` 下新增 `<域名>.md`，并在根目录 `AGENTS.md` 的领域知识路由表中补充关键词
4. **术语先行**：新增术语时先更新 `glossary.md`，再在各文档中使用；根目录 `AGENTS.md` 的领域知识路由表同步补充术语关键词

## 三、检索指南

| 我想... | 看哪个文件 |
|--------|-----------|
| 对齐术语，查工单用语对应的代码实体 | `glossary.md` |
| 了解系统整体调用链、分层架构、部署拓扑 | `architecture.md` |
| 理解某个业务域的完整链路、规则归属、排查路径 | `domains/<域>.md` |
| 对接某两个仓的接口（协议、方法、超时/重试） | `interfaces/<仓A>-<仓B>.md` |
| 了解外部系统依赖（接口、数据格式） | `external/<系统>.md` |

## 四、与根目录 AGENTS.md 的关系

- 根目录 `AGENTS.md` 的「领域知识路由」表是本目录文件的**关键词索引**，用户通过关键词定位到本目录下的具体文件
- 本文件是本目录的**内部维护说明**，面向文档维护者；根目录 `AGENTS.md` 面向所有使用者（开发者、排查者）
- 新增文件时两处都要更新：本目录新增 `.md` 文件 + 根目录 `AGENTS.md` 路由表追加关键词行
