# domain-docs 领域共享知识

本目录集中维护 <项目名称> 的领域知识。业务仓中的文稿通过目标仓和仓内路径引用这里，避免重复维护同一跨仓事实。

## 一、目录结构

```
domain-docs/
├── AGENTS.md                  # 本文件
├── glossary.md                # 术语、代码实体、易混概念和错误码
├── architecture.md            # 架构、协议、调用链及部署依据
├── domains/
│   └── <实际业务域>.md         # 域边界、完整场景和排查路径
├── interfaces/
│   └── <调用方>-<被调用方>.md  # 双端核实的接口契约
└── external/
    └── <实际外部系统>.md       # 角色、交互与已知约束
```

## 二、维护规则

1. 跨仓业务事实在本目录统一维护，各仓文稿引用对应位置并说明本仓实现。
2. 接口变更时核对 `interfaces/` 下的对应契约；业务规则变更时核对 `domains/` 中相关域边界、端到端场景及配置说明。
3. 新增、移动或删除文稿时，同步更新本目录索引与本知识仓根目录 `AGENTS.md` 的路由，确认真实目标和章节存在。
4. 术语变化时核对 `glossary.md` 及引用该术语的文稿，记录适用范围与实际来源。

## 四、与根目录 AGENTS.md 的关系

- 根目录 `AGENTS.md` 提供业务仓及领域关键词的总入口；本文件提供本目录内的实际文档索引和维护约定。
- 两处路由使用同一组真实产物，最终同步时核对文件、章节和适用范围。
