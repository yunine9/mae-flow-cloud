# 领域文稿写作

## 一、职责与输入

本提示词供领域层的独立写作、修订或导航步骤使用。先读 [平台执行约定](../references/platform-execution.md) 与 [共同质量要求](../references/document-quality.md)。只处理 step.instructions 的范围，普通写作生成一篇；明确的导航同步可修改全部 expected_document_ids。

先核对本项的文稿编号、target_id、仓内 path、具体模板、业务范围、依赖步骤及证据索引。主会话应已把这些规划字段放入 step.instructions；按 id 读取本项调查结果，重新打开原始依据。只有边界、路径或关联项需要核实时才用 knowledge_work read_document 读取 current-plan；该工具返回整份规划，不支持按章节读取，不要每篇都无条件重读全计划。

涉及上传资料、无线术语或相关业务结论时，读取 [来源方法](../references/business-sources.md)，根据本项 source_index 回读资料原文/图片与必要的无线检索正文。资料所述意图要核对版本和适用范围，无线背景只用于解释概念；新增依据、冲突和缺口保存到步骤结果供独立评审接续，不把主会话摘要当成已读资料。

使用 extraction_skill 读取具体模板。下方“业务域”专项流程仅用于 templates/domain/domain.md；其余六类按对应读取重点与模板生成，不强加域边界、存储、DFX 或逐业务场景章节。DFX 在本文指可靠性、安全性和可观测性等运行保障能力。

## 二、七类文稿的读取与写作范围

| 模板 | 必须核对的范围 | 产物重点 |
|------|----------------|----------|
| root-agents.md | 全部配置仓的职责与实际归档路径、完整规划及导航覆盖的已完成文稿 | 仓路由、关键词路由、真实目标位置与使用方式；不发布过程规划，不伪造同目录多仓 |
| domain-agents.md | 领域层真实目录、已生成文稿、根导航与维护关系 | 领域目录索引和维护说明；最终同步时核对全部路由目标 |
| glossary.md | 全部范围内仓的核心实体、枚举、字段、错误码、协议术语及相应业务资料 | 术语到代码实体的映射、易混概念与命名差异；只读与词义相关的定义及使用，不为术语表重读无关实现 |
| architecture.md | 各仓构建文件、运行入口、注册/发现、真实调用双方、部署配置与外部交互 | 真实分层、完整仓关系、协议、技术栈与可证实的部署拓扑；缺少部署材料时明确未知 |
| domain.md | 本业务域全部场景涉及的各仓入口、实现、模型、状态、存储、清理与配置 | 按下方业务域专项流程逐场景展开，保留模板全部主要章节 |
| interface-contract.md | 对应仓对的实际调用与实现、IDL/请求响应模型、错误处理、超时重试与幂等实现 | 逐真实接口写参数、响应、时序、错误传播、条件与副作用；不把建议写成调用方已实现的处理 |
| external-system.md | 对接该系统的真实客户端、协议/编码、配置、异常和重连、适用资料 | 系统角色、接口方向/格式、实际约束与依赖；只确认对接侧可见事实，不推测外部内部实现 |

所有仓、接口和场景按实际清单展开，不按模板示例数量凑数。调用双方在同一仓时如实描述，不为领域文稿制造第二个仓。第三方进程内库列为技术依赖，实际独立服务、存储或设备才生成外部系统画像。

接口契约按已确认的调用方→被调用方组织，双方都有独立调用时分别说明方向。参数是否必填、约束和字段变换以实现及协议定义核对；认证、幂等检查、状态写入和副作用的顺序必须写清。超时、重试和错误码逐接口读取，不把某客户端设置推广到所有调用。缺失变更历史时明确无可核实记录，不补造日期或人名。

## 三、业务域专项流程

1. **确认域边界。** 从用户意图、真实业务入口和规划范围说明本域负责什么；相邻但目标不同的功能写明不属于本域的原因及已知归属。边界先按规划定位，再用源码核实，不能以猜测先排除业务。
2. **列出全部独立场景。** 对照去重的页面、API、命令、定时任务和事件入口，把每个入口映射到场景。触发意图、链路或结果不同才分开；参数不同但链路相同写成分支。完成场景列表后再逐场景追踪。
3. **逐仓、逐跳读取。** 从场景入口读参数准备、业务实现、数据模型、状态、持久化、下游调用和返回后的处理；继续到业务终点。跨仓调用两端均读取，包含异步消息、回调、文件传输与失败传播。源码长文件按返回范围继续分页，不能把默认首段当全文。
4. **核对环境机制。** 读取影响该链路的配置和实际使用点，区分默认值与现场值；识别存储位置、容量限制、临时数据/缓存清理、流量控制、超时重试、权限/安全、审计与监控。不存在的机制给核查范围，不为表格补造值。
5. **填充各场景。** 在本场景内说明触发条件、核心实体/字段、必要状态流转、完整时序和关键分支。领域时序图以真实仓或外部系统为参与者，仓内处理用可回查的自调用简写；内部类/方法细节可指向仓级文稿，但不能省掉业务条件、异常传播或整个次要场景。
6. **汇总跨场景信息。** 保留域概述、域边界、域架构图、端到端链路、环境存储、临时空间与删除机制、DFX、排查路径和关联文档。各章内容以实际源码/资料为准，真正不适用的章写明原因及核查范围；不要留空表。
7. **补报新发现。** 写作时发现规划未覆盖的功能、外部系统或仓关系，先在本篇如实记录有关事实，在步骤结果中交回主会话登记新产物。只修改本步骤允许的文稿，不自行改共享规划或别篇导航。

逐仓核对时至少覆盖以下适用层次：

| 层次 | 读取内容与需要回答的问题 |
|------|-------------------------|
| 入口 | IDL、Controller、Handler、页面/命令/定时/消息入口；触发方式和请求校验是什么 |
| 业务实现 | Service、Delegate、Manager、Processor 或真实函数；为何调用、如何处理、返回后如何使用 |
| 数据与状态 | DTO、Entity、枚举、状态写入与确认；数据如何变换，谁改变与确认状态 |
| 跨仓与外部 | Client/Proxy、协议、消息、文件传输；真实方向、参数、返回和失败传播是什么 |
| 存储与容量 | 数据库、文件、缓存、中间目录、路径及限制配置；各阶段保存什么、多久及上限是多少 |
| 清理 | 事件清理、定时任务、TTL、缓存淘汰；执行方、周期/触发、对象与清理范围是什么 |
| 运行保障 | 并发/排队/拒绝、超时重试、安全校验、审计、查询进度、日志和监控；何时生效及边界是什么 |

以上是阅读检查范围，不强制每个业务拥有每种机制。搜索不到某个关键词不能单独证明不存在；沿实际实现、调用配置和注册点核对，再表述查到的范围。

## 四、导航与关联文稿

根导航、领域导航按 step.instructions 区分初稿和最终同步。初稿只引用规划确定的路径并标明待生成；最终同步必须读取相关文稿并核对实际路径、关键词、职责和章节，不能把尚未生成的目标写成已存在。

同仓使用相对链接；跨仓写实际仓名和仓内路径，已知真实 URL 才链接。知识仓没有业务源码目录时，不能把逻辑多仓布局当作真实目录树。current-plan 是过程记录，不列为待归档文件。引用的章节名称以当前模板及实际目标为准，不能引导读者查找不存在的章节或表。

只有主会话登记最终导航同步及其真实依赖。普通领域写作者不能自行回填根导航；导航步骤可按 expected_document_ids 修改多篇，并在候选结果中列全。

## 五、保存、自检与退回处理

- 自检所选模板的全部适用要求：完整清单对应、无遗漏场景、方法/参数与条件有源码依据、必要时序图与状态表达完整、配置/清理值及限制准确、引用和导航有效。图表按共同质量要求核对，不以固定节点数裁减真实链路。
- knowledge_draft save 的 document 使用稳定 id、实际 target_id、仓内 path、layer=domain、完整 content 和字符串 sources。正文是完整候选，不能仅保存变更片段；sources 记录本次实际读取的位置与对应结论。
- 保存后调用 knowledge_diagram_check，参数 document_id 为本篇编号，按 next_start 读取全部报告。invalid 按实际 error 修正图、保存后重新查；首次绘图或有语法疑问时按需读 [PlantUML 指南](../references/plantuml.md)。unavailable 保留候选并在步骤结果记录依赖阻碍，不删图、不冒充语法错，不宣称校验通过。
- 需要额外范围调查时继续完成当前可核实内容，将具体缺口、已读范围及所需来源写入步骤结果；没有依据时不编造或自行声称本篇已通过。
- 调用 knowledge_work_result 提交 summary、已保存的全部预期文稿编号及必要的 data，注明图表校验与实际阻碍。宿主在候选后先做真实图表校验，再启动评审；普通回复、保存成功、语法 valid 与作者自检都不等于语义评审通过。
- 平台按登记的 review.instructions 启动只读评审。收到反馈后先回读当前候选和涉及依据，修改原编号、重新提交候选；写作会话不代替评审返回 pass=true，也不安排子步骤。
- 因真实资料缺口不能完成的内容标明影响。能从现有源码继续核对的内容应继续核对，不能以“未知”结束可完成的调查。
