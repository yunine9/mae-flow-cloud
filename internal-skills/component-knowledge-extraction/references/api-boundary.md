# 受支持接口与接入配置

“受支持”指组件向使用团队提供的入口，包括公司内部团队。结合接口声明、实现、发布配置、实际调用和测试判断；可访问、可链接和被调用分别是线索。

## 核对入口

从 interface、idl、include、api、SDK 门面或实际 exports 定位入口，继续读取构建与发布配置。IDL、proto 等协议需追踪生成入口、对应产物和依赖。组件配置中的说明可帮助定位，读取仍限制在已配置路径内。

内部实现、测试 helper、fixture、mock 和仅内部协作的公开符号用于解释行为。正常使用示例采用受支持的调用入口；单元测试在真实测试环境中使用其专用设施，并说明相应依赖。

## 按真实构建方式接入

- Java：配置范围内存在 sdk/pom.xml 时读取并追踪 modules、子模块、parent、properties、profiles、发布插件及脚本。区分聚合、依赖与发布，核对 groupId、artifactId、version、packaging 及必要 classifier。父 POM 和 BOM 按配置产物说明，运行时依赖对应实际 JAR。
- C/C++：核对公开头文件安装布局、库产物和链接目标。使用示例给真实 include；integration 给真实目标、依赖、头文件和链接配置。区分构建 target、链接库名和文件名；纯头文件库说明其实际依赖。
- 其他技术栈：按项目的包入口、exports、构建及发布方式提供配置，沿用实际工具和依赖名称。

发布配置描述构建和发布条件；版本已经发布的结论另需实际依据。真实依赖尚未确定时把缺口保留到任务结果，确认前不提供虚构坐标、目标或安装路径。

integration 面向使用方给出可采用的配置。配置之间的查证过程及来源位置写 evidence，代码示例保留可携带的项目相对路径和实际依赖名称。
