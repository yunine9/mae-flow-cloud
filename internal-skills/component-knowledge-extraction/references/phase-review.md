# 独立评审

通常先读取当前章节全文，再独立读取基础仓引用以及全部 usage_evidence、test_evidence 原文。用 component_work evidence_id 回读历史会话取得的代码，并继续展开影响结论的函数、fixture、mock、断言、helper 和依赖。synthesis 评审读取概述及支撑它的章节。

pitfalls 作者报告没有确证误用且未保存章节时，读取 component_work_result 的核对范围和结论，回查相关源码及真实调用，判断是否存在被遗漏的确定误用。以 pass、feedback 完成评审，不要求补出空白章节；发现确证误用时给出代码依据和修改建议。

对于 kind=paradigm、status=recommended 的正式用法，逐项检查：

- 正文是可独立使用的组件指南，标题符合 schema.md，使用场景与规划一致。
- 接口受到组件支持，正常接入配置来自真实发布和构建方式；测试专用入口留在测试环境。
- 使用代码包含必要导入、初始化、调用、错误处理与清理，API、返回语义和生命周期与实际代码一致。
- 用法的 unit_tests 给出完整断言、真实 fixture/mock、必要依赖和运行配置；正常路径及本场景适用的边界、失败、异步和清理行为均得到核对。
- 每条测试证据确实展开过测试代码，断言支持文中期望；用例名和检索摘要只作为定位线索。
- 使用约束说明确定的条件与行为。常见误用只有确证条目，替代主张保留其适用边界。
- 正文仅包含已确认知识，研究问题和运行事实保留到结构化记录；阅读代码或编写示例没有被描述成测试通过。

unverified、legacy 以及 contracts、pitfalls、index 是任务内的研究记录。核对其中已知事实、真实来源、已查范围与证据缺口；没有依据的接口、使用代码或 UT 可以留空，不要求它们满足正式用法模板，也不要求补造代码。未验证条目如实保存缺口即可，不能作为推荐用法进入正式指南。

发现影响正确使用的问题，在 component_work_result feedback 中给出位置、具体代码依据和修改办法；用 pass 明确评审结论。评审会话保持只读，作者在后续会话修订。独立评审完成于全部相关代码已回读且结论逐项核对。
