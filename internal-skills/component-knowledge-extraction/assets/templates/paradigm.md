# 范式正文结构

## 何时使用

说明具体需求、使用前提和适用版本。结构化 need 与 applicability 必须表达相同条件。

## 推荐步骤

按真实 API 的调用顺序说明初始化、调用、失败处理和清理。

## 不要这样写

给有依据的错误写法、发生条件、后果和正确替代；允许场景明确保留。

## 为什么

用简短因果解释使用约束；不要附证据编号、哈希和源码行号。查证依据保存到结构化 evidence。

公共接口、接入依赖、完整示例由各自字段保存并统一导出，content 不要再重复这些章节。来源仅保存到结构化字段；不要生成来源段落或工作过程说明。平台按 schema.md 导出 Markdown 与独立 JSON 并重新解析校验。
