# 检视意见的定位、修订与闭环

## 先明确本轮改什么

本轮提供 knowledge_review_notes 时，先用 list 分页取得本批全部摘要，沿 next_start 到末页；再按职责用 read 和 id 读取所处理意见的完整原文、引用、前后文及批注时行号。不能只处理 message 预览中的前几条，也不能把历史行号直接套到已经变化的正文。没有该工具时按 message 与 human_replies 读取实际意见，不调用不存在的反馈接口。

将用户意见拆成可以分别核实的事项；保留工具或原文中的原编号作为 note_id，一条原意见拆成多项时沿用原编号加分项，不更换或漏掉原意见对应关系；无编号才用 R1、R2 等作为本轮稳定 note_id。编号只组织本轮工作，不要求用户改写意见或逐项确认。保留“哪里有问题、期望怎样、依据或示例”，未指定页码时自行用已有文稿定位。同一意见可影响多个文稿，同一文稿也可对应多条意见。

先采用最小能解决问题的修改范围，再按真实关联扩大：事实修正追踪引用该事实的文稿；术语修正核对同义词和导航；接口修正核对调用双方；拆分合并核对入口及引用。扩大的是受影响内容，不是重新研究整个业务模块。发现直接影响本轮正确性的关联问题时登记并处理；无关问题记录为本轮范围外，不借机重写全部文稿。

| 意见类型 | 定位与核实重点 | 修订边界 |
|----------|----------------|----------|
| 事实、接口或流程错误 | 相关正文、已有来源、真实调用双方与必要分支 | 改错误结论及引用该结论的内容，保留仍成立的事实 |
| 业务范围过宽或过窄 | 用户最新范围、相关目录/入口、实际共享调用 | 删去无关业务或补齐遗漏场景；共享依赖按实际链路保留 |
| 遗漏、深度或可读性问题 | 用户指出的读者问题及对应功能，现有材料能否回答 | 在原稿补充或重组相关内容，必要时新增文稿，不按模板重写全套 |
| 拆分、合并、归类或移动 | 内容职责、重复关系、稳定编号、前后引用关系 | 调整对应文稿及导航，保留来源与历史，按当前目标路径保存 |
| 术语、命名或链接问题 | 受影响概念及同任务引用、实际标题/路径/章节 | 同步有关文稿，记录同名异义，不作无差别全文替换 |
| 图语法或图文不符 | 实际错误报告、图所解释的正文及必要源码 | 修正受影响文稿的图和有关说明；语法问题不要求重查整条无争议业务链 |

用户意见之间冲突时，按最新明确要求处理并记录被替代的旧要求；仍无法判断且会改变结果时，只暂停依赖该判断的事项。既有资料与当前源码冲突时写清版本、范围与结论限制，不以用户希望的结论替代事实。

## 索引与台账保持简短

用 knowledge_draft read 不带 id 分页取得文稿摘要，沿 next_start 到末页，不能把第一页当作全任务。结合 knowledge_draft action=search 检索本任务当前候选正文及 sources：query 匹配完整字面短语，keywords 数组匹配任一字面词，用 start/limit 分页并沿 next_start 继续。返回的编号、标题、路径和有界命中行用于定位，不能当作已读完整正文或事实已确认；对命中文稿按 id 读取。

先按意见中的概念、旧/新称呼、接口符号和路径检索，再顺前后引用关系定位相关文稿；无命中时检查别名、表达差异和导航，不直接判定无需改。主会话只保留编号、标题、目标、当前路径、版本和关联原因等索引，不堆积命中文稿全文；独立单元分别读取其相关正文。本轮步骤结果按编号读取；旧来源记录可通过 knowledge_evidence 或现有文稿 sources 定位。knowledge_work 只提供本轮记录，不能假定能读到上一轮全部调查步骤；旧结果不可读时只补核与意见有关的依据，不因此重跑原调查。

台账 `revision-plan` 的可见标题为“检视意见修订进度”，是本轮过程文稿，不进入知识发布。首次登记意见时立即保存；完成定位、每组修订或评审返回、关联核查及暂停时更新。阶段用“待定位、核实中、修订中、待评审、已通过、待解决”，同时说明具体处理的文稿和下一步，未核实的信息保留未知。沿用原“研究过程”的步骤与过程文稿展示，不另建页面，不用普通回复代替保存，也不要求每次读取都重写台账。保持以下信息，表格可分章节或按组另存过程文稿，主台账只放引用：

| 意见 | 原意与验收结果 | 直接修改/关联核对文稿 | 依据与待核实点 | 修订组/步骤 | 当前结论与结果引用 |
|------|----------------|-----------------------|----------------|-------------|--------------------|
| R1 | 按实际用户意见填写 | 稳定文稿编号，不填整篇正文 | 源码/资料/旧调查位置 | 实际步骤编号 | 已改、依据核实无需改或待解决 |

每个文稿组另记录：初始写入集合、实际改动/新增/删除集合、路径或替代关系、相关意见、必要前序、最新候选与通过的评审版本。主会话负责共享台账，子会话将发现、证据索引和改动映射提交到 knowledge_work_result.data，避免并行覆盖台账。

大任务不在每轮重读所有文稿或累积全文：主会话保留台账和结果编号；每个子会话只接收本组意见、文稿编号、需保留内容、关联问题、模板/方法入口和证据位置。相关文稿过多时按业务关系继续拆分；同篇多意见合并给一个写作者，防止互相覆盖。

## 并行定位和修订

先安排互不依赖的 readonly=true 定位单元，省略 expected_document_ids 和 step.review；结果 document_ids=[]，summary 写判断，data 保存受影响编号、位置、依据、建议动作及未核实项。只读结果不写知识正文、不改共享台账、不安排后续步骤。

依据定位结果合并相交写入集合：两个意见都需要修改同一正文时放入同组，或按明确依赖串行。跨仓但独立的文稿可并行，不按仓数机械串行，也不把同仓无关文稿绑成一个大步骤。knowledge_work run 默认 concurrency=3，可用 1～4；schedule 单批最多 100 项，分批只为工具容量，不代表每批都重新规划。

下面只展示一个修订组；编号、意见和路径需替换为本轮实际值：

```json
{
  "action": "schedule",
  "steps": [{
    "id": "revise-R1-import-contract",
    "title": "修正导入失败处理及其调用说明",
    "instructions": "按本轮修订方法处理 R1：当前接口契约把部分成功写成整体回滚。读取文稿 import-contract 与 import-module 当前正文及来源，并读取定位步骤 locate-R1 结果；回查失败处理实现与调用方。修正涉及的返回、重试条件和图示，保留其余正确内容与编号。提交全部实际改动编号、证据和意见对应关系，发现新增关联影响时说明位置及所需同步。不要重新萃取。",
    "depends_on": ["locate-R1"],
    "readonly": false,
    "expected_document_ids": ["import-contract", "import-module"],
    "review": {
      "instructions": "按修订方法独立评审 R1；读取全部预定及实际改动文稿当前正文、来源和图表报告，回查失败处理双端。核对 R1 是否解决、保留内容是否被误改、跨文稿返回和重试条件是否一致；只按本轮影响范围判断，不要求补写其他业务或整套模板。提交全部已核对编号与 review:{pass,feedback}，反馈标明意见编号、文稿位置、依据及修正方向。"
    }
  }]
}
```

expected_document_ids 是初始分工，不是最初点击文稿的权限边界。写作者发现需要联动其他同任务文稿时，先核对该文稿是否由其他步骤写入；正在被修改或需等待前序时交回主会话调整分工、依赖或追加步骤。无并发冲突且实际工具支持时可完成必要关联修订，结果列全实际改动编号并交独立评审；不能只修改了正文却隐去关联写入，也不能靠多次碰撞重试覆盖别人的候选。评审范围覆盖实际写入集合。

写作者提交 knowledge_work_result 时，document_ids 包含全部实际修改及工具要求引用的文稿；data 记录意见→文稿→改动/证据、删除项和新增影响。子步骤正常结果省略 status；有问题也保存具体结果交主会话，不提交 paused。写作者不返回 review.pass=true 代替评审。

## 对既有成果进行增删与重组

- **修改或移动：** 沿用原 id，读取当前候选、人工修改和已有建议，保存完整正文、sources 及实际目标 path。保存返回的当前路径为准，移动后同步前后引用关系和导航；历史规划中的旧路径只作历史记录。
- **新增或拆分：** 先确认现稿无法清楚承载所需内容，再为新增部分分配稳定 id。拆分时原 id 保留其主要职责，新增文稿记录来源关系；核对原内容是否遗漏及相互引用。新稿只使用与其职责相关的模板，不为了文稿类型数量补齐无关模板。
- **合并：** 选取职责最匹配的原 id 承接保留内容，记录来源稿编号，保留各来源支持的真实事实和证据。原稿作为待删除项处理，先修订承接稿、引用本稿的文稿及导航，不能简单覆盖其中一篇后丢失其独有内容。
- **删除：** 使用实际支持的 knowledge_draft delete 按原 id 标记待确认删除，记录对应意见、移除理由、替代去向或确无替代的原因。以用户范围和业务依据核实整篇确实无关、重复或已被取代；仅部分无关时修正文段。核对同任务引用本稿的文稿与索引，移除引用或转到保留稿。删除项需独立核实依据、保留内容及引用处理，按工具支持返回其编号，不渲染已删除稿的旧图；不物理删除历史或源码。

同任务可用目标由平台给出，path 使用该目标当前 docs_path 内的完整仓根相对路径。仅目录归档位置调整由平台的目录确认能力处理；不为了改路径重新调查业务。模型不修改平台生成的 AGENTS.md，改业务 README.md/index.md/module-map.md 等普通导航即可。

knowledge_draft save 的 sources 是字符串，保留仍支撑正文的原来源索引，增加本轮实际核实的位置；不能只记录本轮新读代码而抹掉保留正文的来源。正文保存完整候选，变更说明放结果或台账；候选通过独立评审后结束本轮，提交 MR 及合入后的正式知识同步由平台处理。

## 独立评审与关联一致性

评审先读本组用户意见、定位结论、修改映射以及全部预定/实际改动文稿当前正文，按对应意见核实原始依据。检查修改是否解决问题、是否引入错误、是否误删有效事实、关联导航和调用双方是否一致。删除项核对移除依据及原事实是否有必要保留或已被承接；不把待删除状态当作已正式删除。

按 [共同质量要求](document-quality.md) 和 [评审提示词](../prompts/verify-doc.md) 使用事实、引用及图表检查方法；模板只约束本轮新增或改动内容所需的结构，不据此要求旧稿补齐无关章节，也不重新开展全量规划核查。既有内容存在直接影响本轮结论的错误时明确报告并纳入关联修订；无关的历史写作偏好不阻止本轮通过。

本轮修改的未删除文稿读取当前 knowledge_diagram_check 全部分页报告。invalid 按具体文稿/图序号/error 修正并重查；unavailable 保留候选并报告真实依赖阻碍，不能宣称通过，也不以删图绕过。图语法 valid 后继续核对受影响的业务关系。纯图语法修订不查未改文稿的图，不要求重读无关源码。新绘图或语法疑问按需读取 [PlantUML 指南](plantuml.md)。

评审使用 knowledge_work_result 提交已读文稿编号及顶层 review:{pass,feedback}。通过反馈写明对应意见、核对范围与版本；退回反馈必须定位到意见编号、文稿/章节、依据、影响和修正方向，区分业务错误与运行依赖。作者候选、自检或步骤 done 都不证明 review.pass=true。平台自动修订最多三轮；没有新事实或修订方案时保留阻碍，不换编号循环同一意见。

最后按台账合并实际写入集合及其前后引用关系、业务术语和接口关系，安排相应一致性核查。共享导航同步等待实际目标最后修订，多个互引导航可以放入同一组，避免循环依赖。只读核查不改正文；发现问题由主会话安排对应修改，再核查受影响关系。完整性针对本轮意见与实际影响，不要求一两百篇全部重评。

## 恢复与结束

中断后先 read 工作摘要，再按 id 读取 `revision-plan`、相关步骤结果及当前候选；依据台账核对哪些意见已处理、哪些版本已评审。正文和来源未变化且已通过的结果可复用，未完成步骤按原 id 接续。新证据或实质改变分工时创建新步骤并记录替代关系，不覆盖原步骤历史；未受影响的研究与文稿保持复用。

每条意见最终记录以下一种结论：

- **已改：** 说明具体改动、实际文稿/路径、候选或删除状态、评审结果及必要关联同步。
- **依据核实无需改：** 给出实际核对的正文、源码或资料位置，解释为何现稿满足该意见或意见前提不成立；不是无依据地驳回意见。
- **待解决：** 指明尚缺哪项来源、权限、用户判断或运行条件，已完成什么，条件满足后从哪个步骤继续。

全部意见已改或有依据无需改，实际改动及关联核查通过后，主会话提交 complete。仅存在需用户确认发布的候选不构成研究未完成，但 summary 要明确尚未发布。待解决事项无法推进时先完成独立项，再保存 paused、候选与台账；不要求重建任务、不删除三四天积累的调查，也不把“换 Skill 重新萃取”当作恢复方案。
