# 按检视意见修订业务文稿

在当前任务的已有文稿上修订，不重新萃取：文稿可以是尚未合入的萃取产物，也可以是从正式知识库创建检视任务时固定的远端版本。最初选中的 document_ids 是用户指出问题的起点；可处理同任务内实际受影响的关联文稿。修订范围由最新用户意见及事实依据决定，不按原点击数量、原文稿数量或历史规划限定。

先读 [修订工作方法](references/revision-workflow.md)。工具参数、文稿路径、候选与正式版本的关系按 [平台执行约定](references/platform-execution.md)；其中首次萃取的全量规划与产物要求不属于本轮修订任务。源码只读，修改结果保存为当前任务候选，平台提交 MR，合入后正式知识库同步。

## 按会话职责执行

- **reviewing=true：独立评审。** 读取本组的意见、改动清单、全部预定及实际改动文稿的当前正文与来源；删除项读取当前删除状态、原内容/来源及移除依据。按修订工作方法的评审要求，结合 [事实与图表检查](prompts/verify-doc.md) 核实修改及关联影响，提交 knowledge_work_result.review。评审保持只读，不安排下一步。
- **有 step 且 readonly=true：定位或核实。** 只处理 step.instructions 指定的意见与关联问题，返回文稿/证据索引、建议写入集合及具体结论；document_ids=[]，不保存知识正文或共享过程文稿。需要返回通过判断时在 knowledge_work_result.review 中说明实际检查范围。
- **有 step 且 readonly=false：修订或关联同步。** 从意见与当前正文开始，处理主会话分配的文稿组，保留仍正确的内容、稳定编号与来源。声明并返回全部实际修改的编号、删除项及新增关联影响，提交候选后交独立评审；不替评审宣告通过。
- **没有 step：主协调。** 维护意见台账和分工，定位关联范围，安排互不冲突的并行工作，处理新增影响并提交本轮结果。只有主会话安排步骤、修改共享台账或决定整轮完成/暂停。

## 主会话的修订顺序

1. **恢复与登记意见。** 先读取本轮已有工作摘要和修订台账，复用已完成结果。本轮提供 knowledge_review_notes 时，主会话用 list 沿 next_start 读完本批全部意见摘要，登记全部原编号；处理某条意见前用 read 按 id 读取完整意见、引用及前后文，子会话按分组读取，不把 message 的有限预览当作全部意见。没有该工具时以 message 和 human_replies 中的实际意见为准；已有编号沿用，否则为每条可独立判断的意见分配本轮稳定 note_id。保留原意、预期效果和最初文稿线索。首次登记即用 knowledge_work save_document 保存 id=revision-plan、title=检视意见修订进度，未知范围先标“待定位”，不等待全部定位完成才保存。最新明确的 human_replies 和用户意见优先；`continued` 只是接续次数。用户要求调整目标、范围或表达时按新要求处理，涉及事实仍回查依据，不把改写要求当作事实证明。
2. **建立受影响索引。** 分页读取同任务文稿摘要，记录编号、标题、目标、当前路径与版本等实际返回字段；结合 knowledge_draft search 按业务词、旧/新术语、接口、路径和意见中的短语检索当前正文与 sources，沿 next_start 读取匹配索引，再按编号读取相关正文。定位出本轮直接改动、关联核对及无需改动的文稿，不将一两百篇全文搬进主会话。命中多时按业务关系分组交只读会话核实，不要求用户逐篇指定；无命中不等于意见不成立，需更换词形、别名或从已知入口核实。
3. **并行核实问题。** 将独立意见或业务关系分成只读定位单元，传意见编号、文稿线索、待判断问题与已有证据位置。复用已有研究，只回读与争议或改动有关的源码/资料。公共仓定位和范围纠正读取 [源码研究范围](references/research-scope.md)；相关上传资料、无线背景或版本冲突读取 [来源方法](references/business-sources.md)。纯图语法、链接或排版问题不触发无关业务研究。
4. **更新本轮分工。** 用 knowledge_work save_document 更新 `revision-plan`，只记录本轮意见台账、受影响文稿索引、文稿组、步骤和结果引用，不改写历史 current-plan，不登记全套文稿输出计划。按文稿之间的事实、引用和写入关联划分修订组；同一文稿只分配一个当前写作者。独立组并行，存在读取前序候选的真实依赖才设置 depends_on。每组返回后及时更新进度，列明已定位、修订中、待评审、已通过及待解决项；让已有“研究过程”入口能持续查看，不只在最终回复汇报。并发与登记示例见修订工作方法。
5. **修订与独立评审。** 每组登记 readonly=false、初始 expected_document_ids 和具体 step.review.instructions，写明意见、改动目标、保留内容与评审边界。新增、拆分、合并、移动和删除使用实际工具支持的动作，不修改源码、其他任务文稿或平台生成的 AGENTS.md。新增关联影响由主会话协调；正常关联修订无需用户逐篇确认。候选保存后核对改动文稿当前图表报告，平台启动独立评审并携带明确反馈接续；纯图语法修正也只处理本轮改动文稿。
6. **统一关联结果。** 核对各组结果中的新增影响，安排受影响导航、术语、接口描述、链接与引用同步。共享导航集中处理或按不交叉目标分组，等待实际目标的最后修订完成。最终只读一致性核查覆盖本轮改动及其关联关系；可分页核对标题/路径索引，不因此逐篇重写、重评未受影响文稿。
7. **逐意见结束。** 台账中每条意见以“已改”“依据核实无需改”或“待解决”结束，附文稿、版本、证据及评审结果引用。全部意见有明确结论、实际改动已通过独立评审、关联一致时提交 status=complete；summary 只报告候选与评审的实际结果，MR 是否创建或合入由平台事实决定。存在无法推进的实际阻碍时先完成独立项，保存 paused 并列出具体缺口及接续条件，保留全部候选和记录。

本轮结果 document_ids 列出实际改动及按工具要求需引用的文稿，删除项同时在 data 中说明原编号、原因和替代去向；work_document_ids 引用已保存的修订台账。不能以保存成功、步骤 done 或图语法 valid 替代语义评审，也不能把修订完成表述成已发布、已归档或现场验证成功。
