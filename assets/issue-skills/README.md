# issue-skills:平台技能目录(来源四分法与准入)

本目录的技能随每个问题会话**整包物化**到工作区 `skills/`(fail-loud:
缺 SKILL.md/目录名重复/整树零技能都启动即响),Pi 注册 name+description
进系统提示词,**正文按需 Read**(渐进式发现,ADR-0014/0015)。

## 来源四分法(放哪、怎么改)

| 来源 | 位置 | 改动纪律 |
|------|------|----------|
| 平台契约技能 | 本目录顶层(`issue-analysis` 等) | 与宿主工具同仓同版本演进:改工具必须同 commit 改技能;措辞随时可改 |
| vendor 原封照搬 | `vendor/<上游>/<分类>/<名>/` | **原封不本地改**——上游更新整目录覆盖同步,git diff 即上游变更;环境差异与阶段点名写在我们自己的编排技能与阶段简报里(适配=简报点名+编排技能环境对照,不建独立适配层,2026-09-08 拍板),不碰上游原文 |
| 团队货架 | `dataDir/skills/`(管理页上架) | 不进本目录;渐进式发现按需读,不占每会话上下文 |
| 业务仓 skill | 业务仓 `.cac/skills`、`.agents/skills` | 仓自治;描述含糊是维护者的 bug,分析会在报告里点名 |

## 准入判据(新技能想进来,按顺序问)

1. 是**问题流的阶段纪律/行为契约**(不遵守=流程跑偏)吗?→ 平台契约技能;
2. 是**外部成熟方法论**,想保持与上游同步吗?→ vendor,原封+适配层;
3. 是**团队沉淀的通用方法论**,按需取用即可吗?→ 团队货架(管理页上架);
4. 是**某个业务仓自己的排障知识**吗?→ 业务仓 `.cac/skills`,不进本目录。

## 物化与边界

- 物化目的地恒平铺 `workspace/skills/<名>/`(源目录可分类层递归组织,
  深度封顶 8)——技能正文里写死的 `./skills/<名>/` 引用不因源分层漂移。
- 技能目录 `skills/` 是会话账本:AI 只读,写不进去(gate 账本目录)。
- vendor 技能正文里的 ZCode 工具引用(AskUserQuestion/并行 sub-agent、
  /tdd 这类斜杠命令)由编排技能(issue-analysis/issue-delivery)与阶段
  简报做环境对照与点名——触发靠简报(必达),对照靠编排技能;子 Agent
  派发已开闸(2026-09-06),业务工具只在主会话。
