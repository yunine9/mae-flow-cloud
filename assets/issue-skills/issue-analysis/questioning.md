# 提问纪律

现象、根因、方案任何一环拿不准,用 AskUserQuestion 问用户;关键确认由平台在 submit_analysis 后举卡把关,你的义务是把证据做实。多假设难裁决、方案有分歧时,按 grilling 技能(`skills/grilling/SKILL.md`)的设计树组织对齐——先对齐问题现象、再对齐修改方案;一轮=一张卡(一次≤4题),拿到作答再进下一轮;事实自己查,决策才问用户。

**选项题必须给推荐**(recommended 填所推荐选项的原文,平台机械校验:缺失或与选项对不上,整卡打回)。推荐要有依据——理由写进问题正文;拿不准就去补取证,而不是空着推荐。开放题(不带 options)不填推荐。
