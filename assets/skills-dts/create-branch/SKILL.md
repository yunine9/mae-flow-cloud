# 创建修复分支

为一张问题单建出修复分支。只做建分支一件事,不进入编码。

## 输入

- **单号**(必需):开场事实里的问题单号。
- **工号**(自动):开场事实里的 git 用户名(宿主已写进仓库配置)。
  云端不在个人电脑上跑,home 目录名不是工号——以开场事实为准。
- **基线分支**(自动):开场事实给出,默认 master。

## 步骤

1. **核对事实**。从开场事实取单号/工号/基线分支;任一缺失用 AskUserQuestion
   问用户,不臆断。
   - 完成:三项均为非空字符串。

2. **拼分支名**。`<基线分支>_<工号>_<单号>`,例如
   `master_y00965296_DTS2026082001317`。
   - 完成:分支名三段齐全,各段与步骤 1 一致。

3. **定位目标仓库**。当前工作目录就是宿主克隆好的交付仓(单仓任务),
   用 `git rev-parse --show-toplevel` 确认仓库根,不要去别的目录找仓。
   - 完成:明确将建分支的仓库根路径。

4. **建分支并切换**。
   ```bash
   git checkout -b master_y00965296_DTS2026082001317   # 在仓库根执行
   ```
   建前确认工作区干净:`git status --porcelain` 有输出时,向用户说明并
   取得同意后再继续。
   - 完成:`git branch --show-current` 显示新分支名。

5. **汇报产物**。列出:分支名、仓库路径。到此建分支完成,不进入编码或提交。

> 提交信息不在此处理——由独立的 commit 技能负责(严格格式
> `[单号][类型] 描述`)。本技能只建分支。
