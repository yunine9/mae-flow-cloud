# issue-prompts:问题流提示词文案目录(ADR-0016)

直接嵌进 AI 提示词的**自然语言文案**住这里,服务加载时一次性挂载
(`src/issueFlow/promptCopy.ts`),按锚点取段、`{{var}}` 替换。改文案
只改 md,不碰 TS;锚点改名必须同 commit 改取用处。

## 文件按消费方分类

| 文件 | 放什么 | 典型锚点 |
|------|--------|----------|
| `opening.md` | 会话入口词:固定流程开场契约、转正继承注、开场收尾、续聊词 | `fixed.contract`、`resume.header` |
| `notices.md` | 平台主动通知:催办、闸门裁决后的交接词、流水线结果、环境通知 | `nudge.body`、`pipeline.green.remind` |
| `receipts.md` | 工具回执与门禁拒绝的返回人话 | `push.no_ticket`、`mrgate.awaiting` |
| `briefs.md` | 阶段简报的自由引导语(进入阶段时随简报注入) | `stage.analyze`、`stage.fix` |

## 放哪的判据(新写一段话,按顺序问)

1. 是**出口条件、可用工具、产出物硬要求**吗?→ 不放 md,进
   `stageRegistry.ts`(与工具门禁同源,ADR-0016 历史实锤);
2. 是**某个阶段的方法论节奏提示**吗?→ 本目录 `briefs.md` 的
   `stage.<名>`;
3. 是**某次工具调用/违规的现场话术**吗?→ `receipts.md`(回执,
   模型动作的直接返回);
4. 是**平台主动开口的通知**吗(无工具调用,服务侧 continueWith)?
   → `notices.md`;
5. 是**跨阶段的工作流方法论或纪律**吗?→ 不放本目录,进
   `issue-skills` 对应技能正文(准入见 assets/issue-skills/README.md)。

判据的边界案例:回执里引用阶段简报(`{{stage_brief}}`)是投递不是
复述,契约句仍由代码拼接;违规现场的纠正话术(receipts)与主动通知
(notices)不互相搬家——发起方不同(回执=回应模型动作,通知=平台
主动开口),文件与消费方代码模块一一对应。

## 锚点规则

- `## <域>.<名>[.<变体>]`,全小写下划线;域=工具名/闸类/场景。
- **锚点是代码协议**,不是文案:改名=改协议,要与代码同 commit;
  改文字零协议后果,随意。
- 锚点重复、缺失、变量缺失都在加载/调用时**当场抛错**(fail-loud)。

## 变量规则

- 语法只有 `{{snake_case}}`,纯字符串替换,无表达式/条件/循环。
- 可为空的槽(如 `{{supplement}}`)由代码传空串;多行内容(清单、
  阶段简报)整体作为变量的值传入。
- 需要新变量 = 代码与 md 同 commit。

## 不进本目录的(分层拍板,ADR-0016;阶段简报引导语 2026-09-06 起移入,ADR-0017)

- **阶段简报的契约句**(出口条件/可用工具清单):仍是 `stageRegistry.ts`
  阶段表的列,与工具门禁同源防漂移——历史上"简报说能用、门禁不放行"
  的漂移就是文案与结构分家造成的。ADR-0017 把简报里**自由引导的部分**
  (不含工具名与出口条件的纯方法论/节奏提示)外置为本目录 `briefs.md`,
  渲染时由代码把契约句拼在引导语之后——漂移防护不因外置而失效。
- **工具 schema 的 description**:与参数定义共演进,留在工具工厂。
- **举给用户的问题卡文案**:那是 UI 文案不是 AI 提示词。
- **修复派发回合的逐段拼装**(graded/mismatch/previousFailure 等):
  与派发逻辑逐段耦合,锚点化收益低,暂留代码。

## 与 skills 目录的分工

`assets/issue-skills/` 是**方法论**(怎么分析/怎么交付,长文,按需读);
本目录是**平台说话的措辞**(契约条文、通知、回执,短句,整段注入提示)。
两边同一纪律:静态 md、启动挂载、缺文件就炸。
