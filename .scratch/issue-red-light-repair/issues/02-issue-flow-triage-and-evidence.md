# 02: 问题流红灯接入不可修分诊与证据评估——可修照修,不可修停机请人

**What to build:** 问题会话的 MR 流水线红灯结算升级为需求流同款的分诊判定:红灯先过不可修工具分诊(失败项全部是名单内工具的 CODECHECK 告警=改代码解决不了,不派回合,停表请人工:stage_note+反馈账本留痕+小鲁班通知,名单经启动旗接入问题流);再过证据评估(逐维度三路取证:失败摘要/检查结构化明细/镜像产物),回合指令按结果分级——全部维度有证据照常派修;部分缺→点名"有证据的维度照修、缺口维度不许猜改"并同时请人补原文;全部缺→不开修复回合,请人直接粘贴报错原文回灌(人发的消息就是续聊回合,天然通道)。可修复→照常平台回合让 AI 修(文案带第 N/M 次红灯),不变。

**Blocked by:** None (can start immediately,与票 01 并行;若消费票 01 的公共盲输入纯函数则在其后合并即可)

**Status:** ready-for-agent

- [ ] 不可修工具分诊接入:名单经启动旗配置,不配置=不分诊照常派修;命中时不派回合、停表、反馈账本留痕、通知人话

- [ ] 可修复路径回归:现有红灯→修→绿全链测试不破
- [ ] 测试:假平台红灯场景(含带工具明细的 CODECHECK 失败、缺证据失败)钉住分诊与分级文案
