# 02: 意见注入与自动修复(修得掉)

**What to build:** 门禁红(存在未解决讨论)时,新检视意见以平台通知注入 AI——不举卡、不打断(并行哲学,2026-09-08 拍板),汇总"文件:行号 + 正文"清单喂给上下文;AI 按问题流现成返工路自主修复:同分支追加修改、重推、重建 MR、重新申报验绿。`resolve_discussion_passed` 门禁转绿后,意见记录统一标闭环("MR 检视门禁已由平台确认通过")。关闭自动修(repair 预算=0)时不退场:留在监看环里只把红项如实亮给人。

**Blocked by:** 01-discover-discussions.md

**Status:** ready-for-agent

- [ ] 新意见 → 平台回合通知注入(一次汇总全部未解决新意见;模型侧语义:这就是待修清单,修完按既有出口重新申报)
- [ ] 修复走现成基建:同分支 push_branch → create_mr(重建)→ complete_stage 重新申报,零新通道
- [ ] 通知注入不占举卡:用户在反馈面板与协作流能看到意见与修复进展;不新增人工确认点
- [ ] 门禁转绿 → 意见记录统一闭环标注;此后同 id 不再注入
- [ ] 自动修关闭(预算=0)时:不派修,意见保持可见并如实标注"待人工处理"
- [ ] 与既有机制不冲突:闸在场(如 pipeline_evidence)时注入让位;收口/归档即停
- [ ] 测试:意见到达 → 注入发生 → 修复重推 → 重新申报 → 门禁绿 → 闭环标注,全链路(假件驱动)

**边界:** 检视修复与流水线红灯修复共用回合与并发额度,不另设预算旋钮;若实测互相挤兑再议拆分。
