# Spec: 问题会话查看模式——团队可见、归属人操作

> 状态: **ready-for-agent**(本地记录;GitHub Issues 因网络不可达暂不发布,恢复后是否回迁由用户决定)
> 来源: 2026-09-01 grilling 五问拍板(1a/2a/3a/4a/5认可)
> 词表: 「查看模式」已入 CONTEXT.md(与「现场记录」相邻)

## Problem Statement

团队看板(团队任务视图)里,任何人都能看到所有人的问题会话卡片(列表走 `scope=all`),但点「进入问题工作台」却被 403 挡下:「只能访问自己的问题会话」。想协作看一眼同事的问题现场——分析报告、工作区变更、日志、执行时间线——必须喊归属人截图或投屏。这个校验把"团队协作排查"堵死了:问题会话的**现场记录**本来定位就是"复盘与问题定位的原始凭证",凭证却只有归属人能看。

## Solution

问题会话工作台对所有登录开发者开放**查看模式**:全部信息面(概要+时间线、材料页签、事件流、耗时卡点)纯只读可看;一切写操作(续聊、作答、取消/归档、绑单、检视、材料修改/解压、环境配置、补充、转正)仍仅归属人。非归属人进入时操作控件隐藏/禁用,顶部一条「查看模式:归属人 xxx 的会话」标识。与需求流"人人可看、归属人操作"(TaskCard `canOperate=false`)同一约定。

## User Stories

1. As a 开发者, I want 在团队看板点开同事的问题卡片后能进入工作台看到会话概要与阶段进展, so that 我不用打断对方就能了解问题处理到哪一步。
2. As a 开发者, I want 只读查看同事会话的现场记录(时间线、事件流), so that 我能独立复盘问题的定位过程。
3. As a 开发者, I want 只读浏览同事会话工作区里的分析报告与代码 diff, so that 同类问题出现在我名下时能直接参考已有结论。
4. As a 开发者, I want 查看同事会话抓取的日志材料, so that 排查共享环境的问题时能看到同一份证据。
5. As a 开发者, I want 非归属人视角下工作台不显示任何操作控件, so that 我不会误触发给归属人添乱。
6. As a 开发者, I want 页面明确标出「查看模式:归属人 xxx 的会话」, so that 我随时知道自己在看别人的现场而不是自己的。
7. As a 开发者(归属人), I want 我对自己的会话保留全部操作(续聊/作答/取消/归档/绑单/检视/材料修改/环境配置/补充/转正), so that 问题处理的责任边界不因可见性放开而模糊。
8. As a 开发者(归属人), I want 别人只能看不能动我的会话(后端硬校验,不只是前端隐藏), so that 即使他人绕过界面直接调接口也动不了我的现场。
9. As a 管理员, I want 保持现状的只读视野而不获得写权限, so that "管理员不处理问题单"的角色边界继续成立。
10. As a 开发者, I want 通过深链(/issues/:id,如小鲁班通知)打开他人会话时直接进查看模式, so that 分享的链接对任何人都能用。
11. As a 开发者, I want 查看模式下事件流(SSE)照常直播, so that 我盯同事正在跑的分析时看到的是实时现场而不是快照。
12. As a 开发者, I want 团队看板的问题卡片入口对非归属人不再 403, so that "看得到"和"进得去"不再自相矛盾。
13. As a 开发者, I want 终态会话(已归档/已取消)同样可被他人查看, so that 历史问题的复盘不依赖归属人在线。
14. As a 开发者, I want 查看他人挂起中的会话(等待关联单号/等人作答)能看到卡与等待说明, so that 我能替归属人判断卡在哪、值不值得催。
15. As a 平台维护者, I want 每条写路由都有归属闸成为被契约测试钉死的不变量, so that 将来新增接口时漏配权限会当场被测试拦下而不是悄悄敞开。

## Implementation Decisions

- **闸的形态**: 后端对 `/issues/:id/*` 的整体归属闸从"本人或管理员"收窄为"只挡写方法"——GET(概要/时间线/材料/事件历史)与 SSE 事件流对所有登录用户放行;非 GET 逐条走仅归属人校验。
- **写路由第二道闸补齐**: 逐接口盘点现有写路由,凡仅靠整体闸保护、缺 `own()` 二道闸的(预期含取消/归档 control 等),一律补上。收窄后"非归属人(含管理员)零写操作"由结构保证,不靠枚举自觉。
- **权限语义**: 读=登录即可;写=会话归属人本人。管理员写权限不放开(与「管理员不处理问题单」「管理员不发起任务」同一角色边界)。
- **前端查看模式**: SessionView 增加"是否归属人"判断并下传各面板;非归属人隐藏全部操作控件(续聊输入框、问题卡作答、取消/归档、绑单、检视、材料快速修改/解压、环境配置、转正),顶部呈现「查看模式」标识。对齐 TaskCard 的 `canOperate=false` 模式;TeamIssueCard 的「进入问题工作台」入口行为不变(点击即进,不再依赖归属身份)。
- **错误语义**: 绕过前端直调写接口的非归属人收到明确的 403 人话(沿用各路由既有文案);不再出现笼统的「只能访问自己的问题会话」盖住全部场景。
- **不改的**: 凭据与口令的暴露面不变(凭据只进模型上下文与 vault,本就不在可读接口的返回里);团队看板列表的 `scope=all` 行为不变;问题会话的发起/拉单仍按现有角色边界(管理员不发起)。

## Testing Decisions

- **只测外部行为**: 断言"某身份调某接口得到某状态码/某内容",不测内部函数调用关系。
- **接缝一(行为主接缝,最高)**: `handleIssueRoutes` 路由级——用既有测试帮手(issueGet/issuePut/issuePost 形态)以非归属开发者身份打读接口(概要/时间线/材料/事件)断言 200,打每条写接口断言 403 且文案明确;归属人全操作不受影响。先例: issueFlowService.test.ts、dtsModuleBindings.test.ts。
- **接缝二(源码契约)**: 断言"每条 `/issues/:id` 写路由分支都带归属闸"——对路由源码做正则契约,新增写路由漏配归属闸时测试红。先例: issueUiContracts.test.ts 的源码正则风格。
- **接缝三(前端契约)**: SessionView 查看模式(归属判断下传、操作控件隐藏、查看模式标识)与 TeamIssueCard 入口语义,用源码契约测试钉住。先例: teamDashboardLayout.test.ts、issueUiContracts.test.ts。

## Out of Scope

- 部分写操作的开外(如让任何人补检视意见)——牵扯检视记账语义,另立一票。
- "同模块/相关人"粒度的可见性(系统无团队实体成员关系模型)。
- 管理员获得任何写权限。
- 问题会话凭据在可读接口里的进一步脱敏(暴露面本就不变)。
- 需求流任务可见性的任何调整。
