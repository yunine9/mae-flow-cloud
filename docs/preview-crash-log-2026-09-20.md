# 本机预览异常日志失控

2026-09-20 定位 `.ui-fixtures/crash.log` 的重复写入：预览服务 PID 94582（8838 端口）已经运行四天多，短时间观测中目录从约 2.0 GiB 增到 2.4 GiB。停止进程时文件为 2,570,792,193 字节；用户要求清空后，目录已清空。

现场日志为相同 `write EPIPE`，栈指向 `executionRuntime.ts` 中异常记录函数的 `console.error`。输出管道失去读端后，记录异常的 console 写入再次异步触发异常；同步重入标志已复位，无法阻止下一轮。进程级异常日志也没有容量上限。

修复：

- 移除异常记录器中的异步 console 写入，使用可同步捕获 EPIPE 的 stderr 写入；落盘和输出失败均不再次抛错。
- stdout/stderr 的永久错误监听不因已经存在其他临时监听而跳过，并且重复安装不会重复注册。
- 30 秒内连续相同异常只记第一笔，下一笔记录合并数量。
- 单条详情最多 64 KiB；`crash.log` 与一份 `.1` 备份分别最多 5 MiB。旧超大日志首次轮转时截断到上限，不复制全量大文件。
- UI 预览结束清理进程，删除数据前先停写入者；不要靠异常处理器掩盖长期遗留的预览。

回归使用独立 Node 子进程，真实关闭 stdout/stderr 管道，触发未捕获异常及 Promise rejection，验证进程仍能结束且不循环刷盘；另验证万次重复异常、不同异常轮转、超大历史日志，以及日志目录无法写入。

该上限针对进程异常日志，不代表所有业务日志都自动具备相同上限。已运行的旧进程必须停止或重启才会使用修复。
