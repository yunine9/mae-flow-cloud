# 分享稿配图说明（编辑用）

正文保留既有观点与用户逐句确认的表述，用一张协作总览图和四组实战截图补充。正文中的“实战截图”引用块是编辑提示，图片到位后替换为图片与图注。

## 选图建议

优先选同一项真实需求贯穿模块分工、检视意见和交付反馈，读者更容易看清前后关系。没有对应记录的环节可以省略，不为凑数量拼出一条并未发生的流程。

| 正文位置 | 建议画面 | 需要读者看到的事实 |
| --- | --- | --- |
| 从编码提速到端到端交付 | 流水线反馈、修复记录、后续验证 | 反馈是否进入处理，以及当前版本实际结果 |
| 人的注意力应该花在哪里 | 原意见、Agent 回执、相关改动、Owner 处置 | 人的要求怎样影响执行 |
| 以全局设计支撑多 Agent 协作 | 整体架构图与模块分工 | 需求怎样分工，职责和依赖是什么 |
| 将实践经验沉淀为团队资产 | Skill 或知识条目与使用记录 | 具体资产如何提供给当前任务 |

一张图只讲一个重点，保留辨认上下文需要的部分，减少导航和空白。适当标出关注区域，不修改状态、时间和原始结论。外发前遮盖真实姓名、内部地址、客户信息与凭据；处理后再检查一次。建议保留内部原图，对外使用单独副本。

## 图注写法

结合实际画面填写一到两句：这是什么需求或意见，图里发生了什么，结果到哪一步。不要仅写“平台支持某功能”，也不要把模型回执当作人工验收或把读取记录当作提效证明。

建议截图文件名：`02-delivery-feedback.png`、`03-review-feedback.png`、`04-module-plan.png`、`05-knowledge-use.png`，放在 `docs/assets/external-sharing/`。目前尚未收到内网截图，未生成或补造实战画面。

## 协作总览图

概念图只说明人、Agent、平台和团队资产之间的职责关系，不是部署拓扑，不声称所有能力都已自动闭环。生成图的文案以当前代码和正文为依据。

生成方式：内置 imagegen。生成提示词保存在 `assets/external-sharing/01-collaboration-overview.prompt.txt`，图片保存在同目录的 `01-collaboration-overview.png`。已检查图中文字与布局。正文使用仓库相对路径，拉取仓库后可直接预览。单独分发 Markdown 时，同时携带 `assets/external-sharing/` 图片目录并保持相对位置。
