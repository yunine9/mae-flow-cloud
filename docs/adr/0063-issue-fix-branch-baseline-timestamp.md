# 修复分支命名:真实基线前缀 + 秒级时间戳,同单重跑改走新分支新 MR

2026-10-15 拍板(grill-with-docs 会话):有单会话的修复分支名从写死的 `master_<工号>_<单号>` 改为 `<会话真实基线>_<工号>_<单号>_<yyyymmddhhmmss>`。时间戳取首次建分支时刻(宿主本地时间),生成即持久化进会话状态——同一会话内所有仓、推送、MR 全程同名,不随时钟漂移。起因是命名撞车:人工干活的分支命名习惯本来就是 `基线_工号_单号`(沿用需求交付格式),平台一跑就把这个自然名占了——流程改得不好时,用户想自己用这条分支,分支里已是平台的半成品。时间戳让平台分支彻底让出自然名;前缀同时纠正为会话真实基线(克隆/检出早就在用真实基线,唯独分支名前缀自问题流 v2 起写死 master,是个没改完的角)。

**理由**:基线在有单会话必然在场,写死 master 的历史包袱可以安全拆掉——手工登记缺版本 409(2026-09-18)、DTS 发起按配置中心映射硬闸「没有分支就不发车」(ADR-0038)、自动接单带的是已匹配的版本行,配置中心入库另校验分支名合法。基线缺席只可能来自绕过路由直调服务,报错不回退,与「未配置分支」同一哲学。

**连带取舍(拍板)**:同单重跑语义从「同名覆盖」改为「新分支新 MR」——重跑不再复用旧分支,按新时间戳直接重新发起一个 MR;旧分支与旧 MR 留在平台上由人处置(平台无自动关 MR 的通道,不为本次新增)。**遗留警报随名词撞车一起退役**:它防的 2026-08-28 事故(上次运行推的同名分支让重跑在 push 时 non-fast-forward 拒收)在新命名下结构性不可能再发生,`divergedRemoteBranch` 与拉仓回执警告作为永远不响的死代码删除;`remove_repo` 的「远端还有修复分支拒移」门禁维持精确名匹配(护住本会话足够);`push_branch` 的 force 参数保留,防平台侧罕见异动。老会话升级兼容:升级时已按旧格式推送过的在途会话沿用旧名(从推送账识别),新会话一律新格式。

**保留**:`ensureBranch` 幂等语义(已检出=通过、在=切换、不在=从起点建,绝不 reset 已有分支);单号门禁(push 与 MR 源分支机械校验与会话分支同名);提交格式 `[单号][类型] 描述` 平台钩子不受影响。知识库发布的分支命名与补单纠正不动:前者本就用真实目标分支,后者按子串替换单号,对新格式天然兼容。

曾考虑:(a) 命名空间前缀如 `ai/master_工号_单号`——同样让出自然名,还保住「同单同名」的全部重跑语义(遗留警报、覆盖即更新旧 MR);拍板选时间戳,因为重跑新 MR 的卫生成本被明确接受,「每次运行一条独立分支」的语义更直白,不需要向用户解释命名空间。(b) 分钟粒度时间戳 + 拉仓时 ls-remote 探测候选名被占则顺延一分钟——否,为现实里不存在的「同分钟双起」加探测机制不值,秒级直接消掉问题,真撞上还有既有 non-fast-forward 报错兜底。(c) 基线缺席回退 master——否,基线被三道闸硬保,回退是给到不了的场景留机制。(d) 拉仓回执按 `<基线>_<工号>_<单号>_*` 模式扫描列出历史运行遗留分支——否,与遗留警报同理由退役,历史遗留交平台人工管理;真要找回,模式扫是一次 ls-remote 的事。
