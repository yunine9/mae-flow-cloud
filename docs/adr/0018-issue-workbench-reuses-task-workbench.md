# 问题工作台复用任务工作台骨架:对话聚合接口 + 卡入流(2026-09-07 拍板)

问题处理侧工作台 UI 对齐需求开发侧(workspace-studio 改版后)的形态:**头部进度条
+ 左栏一级标签页组 + 右栏「与 Agent 协作」对话框**。这不是一次皮肤微调——它换了
问题工作台的骨架(右栏 NEXT ACTION 栏退场)、新增一条对话聚合接口、把举卡的呈现
从"侧栏卡"改为"流内卡"。三个子决策各有被否掉的备选,记下防翻案。

## 背景与取舍

需求侧 2026-09-05 完成工作台 studio 改版(见 docs/handoff-frontend-workbench-
2026-09-05.md),形成成熟骨架:`ws-head` 头部(进度条在头部)+ `ws-body` 两栏
(左 `ws-evidence` 材料标签页组、右 `ws-side` 协作对话流)。问题侧此前是自成一体的
双栏:进度条横贯双栏上方、材料是"顶层页签(材料/现场)→ 面板内二级页签"两层嵌套、
右栏 IssueRail 六态互斥(举卡/等待/状态提示都在侧栏)。

用户在两个工作台间切换,布局语法不一致的维护成本已经超过"独立分包"省下的耦合成本
(材料页签的问题侧变体与任务侧 `ws-source-switch` 的样式漂移是实锤前兆)。

**决策一:复用组件而非只对齐布局。** 曾考虑"位置对齐、组件各留各的"——否决:样式
漂移正是要消灭的东西。复用 `ws-head/ws-body/ws-evidence/ws-side` 骨架类与
ConversationStream/Composer 组件;**主题色除外**——全部走问题域配色变量
(含每页签一色的 `--workspace-tab-color` 取问题侧色值),两域"同构不同色"。

**决策二:新增 `GET /issues/:id/conversation` 聚合接口,而非前端拼装。** 曾考虑
前端把 SSE 现场流与过程问答两个数据源合体——否决:任务侧 ConversationStream 的
消息类型、时间线去重、卡片回放全部吃 ConversationItem 形状,前端拼装要重造一遍
分拣逻辑且以后每加一种回合类型都改两处。服务端把现场记录投影为同形状数组,投影
本体是纯函数(问题域"事件→回放"投影传统的超集,扩展 card/decision/steer/回执
成员);现场直播 SSE 保留给「对话现场」标签的实时性,对话流走聚合+轮询(任务侧
同款节奏)。

**决策三:举卡从侧栏迁入对话流,而非保留双入口。** 曾考虑"侧栏卡照旧+流内只读
回放"——否决:同一张卡两个呈现位置迟早漂移。当前卡钉在消息流末尾的 Agent 气泡内,
提交按钮经 portal 挂到输入区 dock(任务侧同款);四种问题域卡变体(env_needed
表单/skill_select 多选/流水线红灯与证据/通用决策)**字段保留问题域语义,只换呈现
壳**。历史卡与人的裁决在流内只读回放。右栏 IssueRail 整体拆除:发言输入并入
Composer,等待/状态提示、挂起转正并入对话流。

## 边界(刻意不做)

- 进度条只复用视觉(task-progress 节点+词签+当前脉冲),数据仍走 `stage_states`
  (有单五阶段/无单三节点),**不做**需求侧的点击弹阶段计划弹框——问题侧没有阶段
  计划概念,两域阶段词表不同,数据模型不归一。
- 查看模式语义零变化:`canOperate` 门继续管一切写口,需要我处理的事实卡对查看者
  只读呈现。
- 逐仓交付卡、耗时卡点、反馈面板暂留头部下方原位,不顺眼另行迭代。
- 周边页面(登记列表、归档视图、DTS 发起入口)不动。

## 后果

- 问题域新增一条只读聚合接口,形状与任务侧 ConversationItem 对齐——两域对话形状
  从此互为兼容目标,**改任务侧 ConversationItem 必须同步评估问题侧投影**(新增
  回合类型时尤其)。
- MaterialsPane 二级页签、顶层"材料/现场"页签、IssueRail 成为拆除对象;其上的
  既有 UI 契约断言随拆除同步重写。
- 两域工作台"同构不同色"成为后续问题侧 UI 需求的默认约束:新功能先问任务侧有没有
  同类件,有则复用换色,无则问题域自建并回补本 ADR。
- 修正(2026-09-07 实测):Agent 卡的账源不是事件——tool_requested(AskUserQuestion)
  的 waiting_id 恒空、且重放/子会话拒绝会重复落同名词事件,拿它当卡源,等待中的卡
  在流内多出误标"已决定"的影子、还会成倍繁殖。卡条目改以 waiting.json 记录
  (HumanGate.all)为唯一账源,与任务侧 fromWaiting 同源;事件只配对转录用。
