# 检视意见内联化与分析报告版本化——过程文档页签收敛为「分析报告」

2026-09-14 拍板(grill-with-docs 会话):问题控制台「过程文档」主页签改名「分析报告」,其下只留报告本身——「过程问答」子页签(events.jsonl 投影,与对话现场主页签重复)连同投影 API、「检视」子页签(圈注草稿面板)、Agent 动态落的其他顶层 .md 页签一并彻底删除,不留隐藏后门。提意见的入口内联进分析报告视图:行尾圈注交互照旧(ADR-0007 的块级锚点:行号+原文快照+自由文本,同行可多条),草稿清单与「提交」按钮常驻报告视图内,不再是独立页签。

**意见号**:每条检视意见在控制台内自 1 单调递增、永不复用(软删也不回收),展示与 AI 引用统一用它(「意见3」);跨批次连续不重置,保证带号的回应在整个控制台内唯一定位。发给 AI 的意见清单按意见号编排(意见号+行号+锚定原文+要求)——renderReviewNotes 的既有编号机制改为以意见号为序,内部 an- 前缀台账 id 不对外。

**分析报告版本(平台冻结)**:提交检视意见时平台把当前报告快照入账(复用 reviews/ 快照机制,此前快照无任何 UI 消费),AI 修订重新 submit_analysis 后成为新版;版本页签「初版 / 修订1 / 修订2」,修订N = 第N批意见处理后的版本,默认进最新版,只有初版时不渲染页签条。每批意见处理完必出新版——「检视意见回应」段(按意见号逐条答复:改了什么/答了什么)是修订版开头的软性章节,靠 renderReviewNotes 护栏要求,不进五章节机械门票。已提交意见不再渲染在新版上:归属冻结版锚点+回应段,新版是干净纸面(reanchor 四态检测自此只服务草稿)。闸卡「补充意见」等非检视通道的报告重写不出版本,只更新最新版内容。提交守卫与整体回退语义不变(空闲/等用户可提交、运行中禁用、检视回合中不可叠加、提交即回退 analyze 重跑)。

理由:用户的工作流是"通读报告→行上圈意见→一口气发给 AI→按号对照答复→新旧版并看",圈注的行级锚点是定位刚需(自由文本框答不了"问题在哪一行");版本是平台的记账行为,不该指望 AI 自觉落版本文件,而快照地基已在(ADR-0007 提交检视时就在冻快照,只是无人消费);过程问答与对话现场是同一份事件账的两套投影语义,砍一份少一份漂移面。

曾考虑:(a) AI 自落 issue-analysis.r2.md 之类作为新版本——否,要在提示词里教、AI 忘落即丢版本,还得改 documents 契约;(b) 自由文本框空行分段替代圈注——否,行号锚定与"每行多条"是拍板要求;(c) 已提交意见重锚跟随新版渲染——否,文本已被修订,旧意见钉在新文上易文不对题;(d) 「分析报告2/3」式数字页签名——否,呆且不表意,定「初版/修订N」;(e) 运行中排队提交意见——否,会引入"意见对应哪一版报告"的歧义,插话走对话现场。
