# 工作区变更人工修改退役:问题流回归纯 Agent 主理

2026-09-14 拍板。「工作区变更」页签不再允许人工修改,相关内容整链移除:快速修改编辑器(选文件/编辑/保存)、「请 AI 复核」按钮、人工修改记录陈列、`GET|PUT /issues/:id/materials/file` 路由、`manual-edits.jsonl` 台账的记账与读口、wire 上的 `manual_edits` 字段。

**理由**:人工改 AI 正在工作的代码仓,天然与 Agent 的阶段账、diff 基线、推送门禁相左——运行中的覆盖风险提示、改后请 AI 复核的往返,都是在给一个高危写口打补丁。Agent 主理原则(ADR-0023 立 project 原则)走到彻底:人对问题的全部影响力走意图类写口(调整关联仓、拉取日志、检视意见、续聊插话),代码变更唯一执行者是 AI(推送仍走 `push_branch` 单号闸,门禁照旧)。

**边界**:历史 `manual-edits.jsonl` 文件保留在盘(磁盘治理台账永不回收的口径不变),只是不再记账、不再陈列;存量会话的旧记录不迁移不删除。`src/annotations.ts`、检视链路、diff 视图与变更清单(只读)不受影响。

曾考虑:保留台账陈列(只删编辑器)——否,账不再增长,陈列是一块只会变旧的死面;保留 GET 读口——否,唯一消费方是编辑器,留路由不留死口(与 ADR-0026 收旧路径同款纪律)。
