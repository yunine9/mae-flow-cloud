# DTS 统计仓维度并入特性树:按会话事实分组,按代码仓页签退役

2026-10-21 拍板(grill-with-docs 会话)。DTS 页签的观察维度自 ADR-0048 起固定为三维:按特性/按会话/按代码仓。特性与代码仓本是一对多绑定(业务模块元数据 `repositories`),但按代码仓页签是独立平铺表,看「某特性的交付落在哪些仓」要在两张表之间人肉对账。本次把仓维度并进特性表,成为树状表格:外层特性行,展开后是该特性的仓行;按代码仓页签整体退役。这推翻 ADR-0048 描述的三维结构(观察维度剩两维)。

决定:

1. **树按会话事实分组,不按绑定配置分组**:展开特性列出的是「该特性的会话实际改过的仓」,各仓行数只计该特性的会话——内层之和恒等于外层,每行可继续下钻到构成它的会话。落选方案是按绑定列表展开、内层显示仓的全局聚合数字:那样内层会混入其他特性会话的行数(内外对不上)、绑定外仓的改动在树上无落点、绑定了但范围内零交付的仓出空行。绑定配置不决定树结构,但作为偏差信号出现:内层仓行不在该特性绑定列表时标「绑定外」。
2. **数据通道**:`once-generated` 端点的 `per_session` ok 行新增可选 `by_repo`(各仓 first/rework/external,跳过不可得仓与零行仓),树与过滤都从它前端聚合;特性聚合本就在前端(`onceGeneratedFeatureRows`),树内层数字与外层、按会话表三处同源。全局 `by_repo` 聚合字段原样保留(页面常驻旧版前端,#353 字段纪律;加字段可选,消费方按缺省处理)。每仓明细的数据源是伴生快照——详情端点与行归属证据面板本就逐仓展示,本次只是让统计端点也携带。
3. **点击语义=数字下钻**:点特性行跳按会话页签并过滤该特性全部会话;点仓行跳按会话并过滤「该特性 ∩ 该仓」的会话——跳转后看到的会话集严格对应刚才看的数字(全局仓视角随按代码仓页签一起退役)。跳转设置的过滤以可清除的筛选条呈现(仓库不在列头过滤清单,避免九列表格再撑宽);特性名点击从「原地切换过滤」改为「跳转+过滤」,原行为废止。
4. **按会话列头过滤**:会话=关键字(匹配 ID/标题),特性/发起人=单选可搜索枚举(共用 `HeaderFilter` 壳,对齐 DTS 列表筛选表头化惯例);时间不再设列头过滤——页签顶部日期范围与之同维度,不造第二道闸。登记问题页签按会话表同款:会话关键字、模块/登记人/责任人枚举,时间同上。
5. **呈现细节**:树默认全折叠,不记忆展开状态;内层仓行按工作行合计降序;内层不显示一次解决率(会话级裁决不设仓维度,原按代码仓页签口径,显示 —),涉及会话数、首次生成占比、返工/平台外行照显;外层特性行沿用现有列并补返工/平台外行,便于内外对账。

理由:统计页的第一职责是数字自洽——树上任何一个数字都该能答出「由哪些会话构成」。事实驱动分组让树、会话表、下钻证据共享同一套口径,绑定漂移(改了绑定外的仓)自然显形为「绑定外」标记而不是丢数据;配置驱动分组本质上回答的是另一个问题(「绑定的仓里全团队交付了多少」),与外层特性数字并存必然互相误读。点击即下钻同理:跳转后看到的就是刚才那个数字的明细,不需要用户再对一次账。

后果:后端仅加可选字段,旧前端消费不受影响;按代码仓页签消失,端点 `by_repo` 字段保留但新前端不再消费(留待后续退役决策)。特性行点击行为变化(跳转替代原地过滤)是对既有交互的破坏性修改,以本 ADR 为准。

修订(2026-10-21 同日):决定 1 的「绑定外」徽标撤掉——偏差信号从显式标签改为排序语义:绑定列表内的仓在前、绑定外的沉底,各自再按工作行合计降序;仓行呈现与其他代码仓完全一致。绑定漂移的可见性从「一眼看到标签」弱化为「注意到排序异常」,换取树面更干净。比对仍走归一(`repoIdentity`),模块目录取不到时视同全部绑内,退回纯行数降序。

二次修订(2026-10-21 同日,grill 会话):仓行一次解决率从「—」改为实算,三率统一交付尝试口径,并引入角色粒度。

1. **三率同分母**:特性行的会话数/一次解决率/一次定位率/一次验证率,分母一律=交付尝试(完成交付含待算/无源码/起算日前 + 负面原因终止,与一次解决率环严格同口径——各特性行按会话数加权即环的数字;「问题已处理」终止两端都不进)。终止行三率记失败(它没有判定事实,展示口径记失败是拍板,端点字段纪律不变:键仍缺席,#540);仓行只含有交付事实的 ok 会话,三率分母=该仓 ok 会话数。此前环与树分母不一致(环=尝试、树=ok)引发的"哪个是真的"困惑,以树并入环口径终结;三率同分母同时保证一次解决率 ≤ min(定位率, 验证率),不再出现两率高而解决率低的观感矛盾。
2. **角色粒度(前端判定)**:普通用户=一次解决率单环 + 树表 3 列(特性/代码仓、会话数、一次解决率);admin=双环 + 7 列(多一次定位率/一次验证率/首次生成占比/首轮返工平台外合并列)。首轮/返工/平台外由两列合并为单列(与按会话表同款)。落选:端点按角色裁剪(内网工具,先不做);按会话视图与行归属证据收敛(用户只要"首页信息少一点",按会话保持现状)。其他页签(需求交付/登记问题)不在本次范围。
