# 问题单「一次生成占比」:终态后行级归属,后台伴生快照

2026-09-20 拍板(ADR-0042 冻结快照的后继,问题单统计的行级归属层)。给问题单补行级一次生成指标:单会话「一次生成占比」=最终合入的源码行中,首轮生成且存活到合入的行占比;团队「一次生成达标率」=占比达标的会话占完成交付会话的比例(达标线是参数,首版 90%)。定位是管理 KPI,口径宁缺勿假。词条见 CONTEXT「一次生成占比」「一次生成达标率」。

**口径**:

- 分母=最终留存全部源码行(源码=扩展名白名单,复用快照的 SOURCE_CODE_EXTENSIONS);平台外提交的行计入分母、不计入分子——人工在平台外改的,算 AI 没一次生成。多仓会话每仓单列 + 按行数加权聚合,达标按聚合值判(不是每仓都达标)。
- 逐提交三分类:首轮(在推送账且早于返工边界)/返工(在推送账且晚于边界)/平台外(不在推送账)。行级归属对最终差异的新增行逐行 blame 到引入提交,按该提交的分类记账。与需求侧「首次实现占比」三分类同构,但源码口径不同(白名单 vs 路径排除),两域百分比不直接并排比较。
- 返工边界=首个反馈事件所回应的那笔推送头(与需求侧修复区间同构:区间=该推送头..下一笔推送头)。反馈触发集=平台检视批次送出、流水线红灯(仅「按失败处理」结局;随合入取消、随头变丢弃不算)、环境验证发现问题(ADR-0043 后绿后返工必经此作答)。回退轮不单独立触发:验证失败回退已含在前项,纯人工回退是重做不是修反馈,算进去会稀释「首轮」。
- 分母会话集与一次率同款(完成交付=有单+结论 delivered;无单流程不产出 delivered,天然排除,无需另设过滤)。
- 不设「暂计首轮」宽容档:需求侧 no_repair_found 档是描述性页面的覆盖率取舍;本指标当 KPI 用,账不全或现场取不到一律「不可得」,绝不猜成首轮。

**执行模型**(后台伴生,不破冻结纪律):

- metrics.json 纯投影、归档同步冻结的行为不变;新层算完写伴生文件(如 metrics-code-origin.json),同样只写一次、永不重写。读侧拼接:伴生缺席=不进达标率分母,在场=每仓明细+聚合。
- 归档响应不等计算:任务挂后台串行通道(需求侧交付观测的同款形态),Git 一律走异步口(runSafeWorktreeGitAsync——同步 spawn 会阻塞 Node 事件循环拖死整个服务,safeGit.ts 已有明文纪律)。
- 终态现场回收让路:归档后的当场回收等通道任务收尾再删现场;进程崩溃的缺口由每日清扫器兜底——回收终态现场前,伴生文件缺失且属支持期(上线后终态)的先补算一次再回收。
- 超时只作挂死保险,不作性能约束:后台不赶时间,慢就慢慢算;单命令超时放宽到分钟级,真挂死超时该仓降级「不可得」。blame 逐文件进行,单文件行数与整层时长设上限,同属挂死保险。
- head 优先级:fetch 到的 MR 分支头 > 账面合入头 merged_sha(非 squash 合入时两者等价;squash 时前者保有真实提交序列)> 本地末笔平台推送头(缺平台外提交)> 都取不到=该仓「不可得」。fetch 与凭据复用提交归属层(commit_attribution)的会话——平台外提交的对象只有远端有,不 fetch 等于变相把平台外行剔出分母。

**边界与已知偏差**(接受,不修):

- 平台推送后 rebase 改写提交号,对不上推送账被记平台外,占比系统性低估;不做 patch-id 内容匹配兜底(场景罕见,不值得)。
- 只删不改的返工不拉低占比(留存语义,与需求侧一致);合入时人工解冲突改的行在目标分支上,两边都不计。

**存量与呈现**:

- 上线前已归档会话永远没有该层,不进达标率分母;呈现处带起算日期说明(界面小问号)。在途会话上线后归档即自动获得。起算日期是代码里唯一一处常量:清扫器判定"哪些终态会话该补算"与界面文案共用,上线前的终态会话不试算。
- metrics.json 内容不变、无版本迁移(新层在伴生文件里,自带版本号);一次率读侧对存量快照照常命中,零兼容动作。

**曾考虑**:复用需求侧逐推送采样管线——否,问题侧已有账记事实纪律,终态一次算清即可,逐推送重算没必要;推送工具逐次记 diff 统计——否,ADR-0042 已否(归档前现场都在,单点计算,推送路径零负担);rebase 改写用 patch-id 认回——否,罕见场景;归档时同步算带预算——否,归档按钮不该等分钟级 Git,后台通道加清扫器兜底更稳。
