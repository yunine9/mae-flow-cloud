# 问题会话接入平台统一知识检索:只读消费,不接生产口

2026-10-13 拍板(grilling 一轮八问):问题单流程接入平台的 knowledge 统一检索工具,让问题会话能像需求任务会话一样查到正式团队知识(已发布文档、业务模块知识、已采纳经验)。**只接消费,不接生产**——问题会话拿到的工具是只读子集(search/read/component_context),没有「发起组件研究」,没有「沉淀经验」;知识库往里写东西的每一条路,问题会话一条都不碰。

**背景**:需求任务会话有完整的知识通路(统一检索工具、业务模块知识索引、编码前组件分析、每轮经验注入);问题会话此前只有三条轻通道——货架 skill 按问题口径圈选(ADR-0005)、业务知识定格成提示词行(ADR-0012/0021)、全局知识仓整仓只读克隆(ADR-0033)。问题处理恰恰是「踩在别人踩过的坑上」的场景,却查不到权威正本:知识仓克隆是归档旁路的人读副本,可能滞后,也可能缺斤少两。

**检索口径(拍板)**:与货架 skill 匹配同源——登记的关联仓 + 绑定的业务模块,补产品版本按知识声明收窄。单源纯函数 `issueToolKnowledgeContext` 从 `issueKnowledgeContext` 派生,改口径只动一处;repo 用 slug 形态,与需求侧经验归属匹配同语义。

**装配形态(拍板)**:复用需求侧同一个 `createKnowledgeTool` 工具函数,经 `extraTools` 通道挂载(这条通道本来就是为问题会话递平台原子能力设计的);后端共享同一个 KnowledgeSearch 实例——全进程只有一个 memsearch 常驻子进程,由 executionRuntime 以惰性闭包晚绑定传入(issueFlow 装配点在 TaskService 之前,闭包到会话回合才调用)。不传 plan/research 即自然成为只读子集,缺席动作的降级话术工具自带,索引不可用时「继续当前任务」不阻塞处理。

**指引裁剪(拍板)**:工具的教学条目里有一条教 Agent 发起组件研究,问题会话没有这个动作。`createKnowledgeTool` 改为 research 后端缺席时自动不输出该条——需求侧传了 research 行为不变,问题侧 Agent 不会被指向一个注定「暂不可用」的动作。这是工具函数级的能力,两条流程共用同一份代码。同一边界顺带修正一处隐性旁漏:派发工具(Task)上的「编码前派 component-plan-agent」指引原本以「挂了 knowledge 工具」为条件,问题会话挂上只读检索后会被顺带点亮——现改为以「会话配备组件能力目录(componentAnalysisContext)」为准,需求侧语义不变。

**开场词引导(拍板)**:开场词加一行引导:正式团队知识优先用 knowledge 工具检索;知识仓克隆在场时声明主次——工具检索的是平台权威正本,克隆是可能滞后的人读副本,只作补充。阶段交接词里的知识仓提醒不动,等足迹数据说话。

**知识足迹(拍板)**:写侧随本期落地——每个问题会话落 `knowledge-events.jsonl`,只记宿主可观察事实(货架 skill 装载、知识文件阅读等),写失败只记日志不拖住会话。读侧投影(工作台足迹卡、knowledge-insights 聚合)后置:先攒真实数据,UI 做不做、做成什么样,等静态原型看了效果再拍板。

**经验是否可查(拍板)**:包含。检索范围与需求侧同口径,已采纳经验都在;不加「排除经验」的过滤——采纳闸门(人工确认后才可检索)就是成色控制,若实际使用发现噪音大,再加过滤不迟。

**曾考虑**:(a) 以 Skill+CLI 形态挂载——否,检索能力在宿主进程内(memsearch 子进程),包成 CLI 要么再造进程间访问面、要么让 Agent 用 Bash 调新二进制,结构化观测、fail-open 降级话术、参数校验全部丢失;平台能力走工具、团队经验走 Skill,两条通道的语义本来就该分开。(b) 全量对齐需求侧知识通路(组件编码前分析、改码回注、经验推送)——否,这些深度绑定任务侧语义(implementation 文档、组件计划、交付基线),问题单的等价物未定义,先不做语义发明。(c) 排除已采纳经验——否,理由见上节。(d) 让问题会话也能发起组件研究或沉淀经验——否,这改变「问题流不生产」的立场(ADR-0033 只读机理的延伸),涉及经验审核归属与萃取并发名额的跨流分配,值得单独一轮决策,不搭本次消费接入的车。

**验收(实现期)**:定向测试——检索口径纯函数(登记仓/绑定模块/产品版本/slug 归一)、开场词引导行两形态(知识仓在场/缺席)、指引裁剪两侧形态(缺席不教学、在场保留);根 typecheck。需求侧回归零变化:同一函数传 research 时指引与行为不变,已有组件知识测试按需求侧形态补 research 注入后原断言全绿。
