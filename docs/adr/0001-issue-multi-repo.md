# 问题会话多仓:仓平等、AI 裁决交付、拉仓工具化

问题单常跨多仓(如客户端+服务端同一根因)。2026-08-28 拍板:关联仓彼此平等(废除主仓/参考仓分法,目录平铺为 `repo/<仓名>/`);固定流程阶段保持会话级,多仓循环藏在阶段内部;交付是"一仓一 MR",但**对哪些仓交付由 AI 裁决**——平台不做机械 diff,只提供工具;把仓加入会话的方式是 AI 调拉仓工具(宿主侧带凭据克隆,AI 只见结果事实),而非程序自动克隆。

理由:平台的职责是框架+工具集合,选择权与意外处置(如某仓缺基线分支)归 AI——它提问,用户拍板。曾考虑"平台机械查变更仓再校验 MR 齐全",被否:平台无从知道变更集,机械校验必然伪造一个全集。
