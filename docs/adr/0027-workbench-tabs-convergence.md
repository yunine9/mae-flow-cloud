# 工作台页签收敛:五签定局,逐仓交付融入元信息,对话现场降末位

2026-09-14 拍板(grill-with-docs 会话)。第二次页签收缩(前次:ADR-0026 拉取日志页签退役);修订 ADR-0023 立的元信息页签构成。

**五签定局**:元信息 / DTS单据 / 分析报告 / 工作区变更 / 对话现场(末位)。默认签从「对话现场」改为「元信息」(含换会话重置)——右栏协作区本来就常驻直播会话流,「看 AI 干活」的刚需由右栏兜住;右栏工具步骤上的「对话现场」跳转按钮成为完整事件流的唯一入口,跳转语义不变。

**逐仓交付页签退役,交付事实融入元信息的关联仓行**:角色徽标(变更仓/未交付)、流水线徽标、MR 链接与推送记录(branch@sha)、失败项、转正前账,全部降维为仓行上的行内缀——头行「仓名 + 角色标 + 流水线徽标 + 模块绑定标 + 移除按钮」,URL 次行,交付事实第三行(有才渲染,不占位)。逐仓交付本就是纯读面(零写口、零独立接口,数据全部来自会话详情既有字段),repoDeliveryRows / repoPipelineBadge / repoRole 三个纯函数原样复用,无新数据源。区块名保持「关联仓清单」,副标题删除。依据:交付事实本来就是一个关联仓的属性,不配一个一级页签;元信息升为会话名片后,「这个仓交付到哪了」正是在元信息里看仓时想顺手看到的事。

**DTS 单据签无单隐藏**(原为禁用 + tooltip):无单场景没有单据可看,屏蔽即诚实——禁用钮是噪音。

曾考虑:(a) 交付事实保留卡片式整卡塞进元信息——否,元信息是一仓一行的清单节奏,卡片是页签时代的排版惯性;(b) 默认签保持对话现场——否,右栏直播已兜底,元信息(场景化平铺后)才是首屏该回答的「这是什么会话、到哪一步了」;(c) 区块改名「关联仓与交付」——否,CONTEXT.md 的词条是「关联仓」「变更仓」「一仓一 MR」,交付事实是关联仓行的属性,不为区块标题造新名词。

契约钉同步:五签逐字表(无单场景为四签,dts 条件渲染)、默认签断言、tab-color 计数 5、`IssueWorkspaceRepos` 在场断言反钉,随代码同 PR 改。
