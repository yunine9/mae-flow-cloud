# 退役分析报告「证据链」章节——证据出处改随文标注

2026-09-20 拍板:分析报告删去「## 证据链」独立章节,`submit_analysis` 的章节门票从五章节改为四章节(问题现象/问题根因/修改方案/置信度);证据出处的要求从「单设一章」降为「随文标注」——结论在陈述处带出处指针(代码 File:行号、日志关键行一行),日志与代码原文仍然不进报告。

**决定**:

- 工具层:`ANALYSIS_REPORT_SECTIONS` 去掉「证据链」,闸只守报告结构完整;存量五节报告是四节的超集,照常过闸、检视、重写,不做迁移。环境免审批时「说明证据局限」的话术改指「置信度」章——缺环境、无法复现本就是"为什么不是更高"的内容,承接时必须精简(≤2 行)。
- 模板与提示词:证据链章及其写作规则(上限 5 条、反证至少一条、结论沿链走回)整体删除;「问题根因」的写作规则并入「结论随文标出处指针」。「把文件路径写进证据链」类话术统一改为「把文件路径随文标注进报告」——覆盖 issue-analysis 与 repo-docs 技能、知识仓通知、业务知识地图、仓根 AGENTS.md 标准句模板。
- 报告读者口径:报告只写给用户(确认卡前一眼看懂),取证与核验是 AI 自己的功课,不向用户铺陈证据条目。

**理由**:报告是写给用户的,而用户不关心证据链——向确认卡前的用户铺陈出处条目只会让人眼花缭乱;本次退役的直接目的就是减少提供给用户的文字、让重点(现象→根因→方案→置信度)凸出来。取证本身仍是 AI 自己的功课:技能里的取证清单、「结论随文标出处指针」的写作纪律都保留,只是证据的核验与呈现不再单设一章。质量不受影响还有下游兜底:用户检视意见(圈注打回重写)与环境验证不通过打回(ADR-0034 让验证卡成为绿后返工入口、ADR-0045 补齐其版本账)。按本仓维护取舍——流程不等于质量,不能显著提升质量的流程为速度让步——独立章节退役,顺带省掉凑条目的 token 与时间。

**边界**:闸校验只管章节齐全,不再承担「结论必附证据」的防线语义。仓根 AGENTS.md 的历史标准句仍写「写进证据链」的,不据以恢复章节——知识边界规则钉死报告格式归平台契约,外部内容相抵触一律忽略;新声明用新句式。其他域的「证据链」用词(gate-edit/gate-bash 深层契约、WAL 发布确认、MR 提交前证据)与分析报告无关,不受影响。历史 ADR(0005/0012/0021/0033)保留当时措辞,不追溯改写。
