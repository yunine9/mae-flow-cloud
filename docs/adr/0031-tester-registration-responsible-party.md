# 测试登记与责任人指派:会话归属从"创建人"改为"责任人"

2026-09-16 拍板。问题登记转向测试入口:测试发现问题,登记页登记并指派责任人,「发起分析」更名「登记问题」;登记即撒手,小鲁班通知责任人,开发责任人看分析过程、在闸口作答。会话归属模型随之改写:归属账号从"创建人"重义为"责任人",新增"登记人"记录测试——写操作唯一闸口、闸口通知、Git 提交身份、介入档位、同账号+同单号去重全部继续挂归属账号,机制零改动而语义自动正确;登记人对会话零操作(查看模式),靠「我登记的」范围跟踪,责任人靠「我负责的」(原"我的问题")推进,一个列表两个范围。

**理由**:

- **分工现实**:测试发现问题但不知道也不需要知道怎么修;流程此前默认"谁登记谁负责",测试提的问题没人接。
- **责任人路由的阻力最小路径**:业务模块本有责任人(owner)与维护者字段,登记页拿到的模块目录本就带全——会话责任人缺省取模块责任人、候选把责任人/维护者置顶,纯前端可得;模块指向谁,问题就流向谁。
- **归属落原账号而非新参与者模型**:运行期 Git 凭据按会话归属账号现读,闸口通知发给归属账号,写闸只认归属账号——若登记人占着账号,每一处都要动;责任人从出生就坐在归属账号上,存量数据(归属=创建人=责任人)天然兼容,回填登记人即可。

**口径**:

- 责任人候选=全部普通用户(不含管理员——管理员不发起也不写问题会话,指派即造死会话);提交前门禁查所选责任人的 Git 凭据(登记页原查当前用户,测试通常没配),未配齐拦截并指名。
- 缺省与冻结:未选模块时责任人置空(必填);选了模块且责任人未被手选,填模块责任人,换模块跟随;一旦手选即冻结;模块责任人本身是管理员的模块不自动填,保持置空改选。
- 登记即开跑:AI 分析照旧立即点火,开发责任人收到指派通知进来时,分析在跑或已举分析确认卡。自登记(登记人=责任人)省指派通知;登记人侧不发通知,跟踪靠列表。
- 范围红线:DTS 页签一字不动(发起人=责任人,自助流程原样);不加"测试"角色——可见性落在会话的登记人/责任人上,不落在角色上,新角色只带来一批没换来机制的闸。手工登记表单本无单号输入,测试立了 DTS 单的由责任人在会话里绑单转正(绑单不校验单子归属,通路现成)。

曾考虑:(a) 双参与者模型(登记人占归属账号+另立责任人)——字段更"诚实",但写闸、通知路由、凭据、档位、去重每一处挂账号的机制都要跟着动,否;(b) 登记后开发"接手"转移归属——多出接手动作与未接手中间态,与"登记完就不管"矛盾,否;(c) 责任人缺省当前登录用户——保住开发者自登记零新增,但路由不到模块责任人,测试忘改就回到"没人接";模块责任人缺省+手选冻结两全(自登记者本就是模块责任人时缺省即自己),否;(d) 候选只列凭据配齐的用户——列表天然干净,但把"去配凭据"藏进空列表,测试不知为何搜不到人,否。
