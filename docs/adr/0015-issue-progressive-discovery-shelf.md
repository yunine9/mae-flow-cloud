# 渐进式发现补全货架一翼:悬空索引引用落地,dts-diagnose 契约小节瘦身

2026-09-03 拍板:ADR-0014 拆除圈选闸后,渐进式发现的**发现面只补了
业务仓一翼**——issue-analysis 取用次序第 2 条仍写着「会话技能索引」
(全仓无实现的悬空引用,0014 未触及),货架 skill 装载为只读快照
`.mae-flow-work/host-skills/` 却没有任何机制告诉 AI 它在哪:扫描留痕
不扫货架,简报零提及,索引纪律没点名路径。结果就是"统一由 agent 自
行判定"对货架一翼落空——AI 只能靠运气撞见 dts-diagnose。本篇补全:

1. **取用次序第 2 条落地**:改为与第 1 条同款两步走——①先建索引:
   列出 `.mae-flow-work/host-skills/` 下每个 skill 的 name+
   description;②对相关性,相关才读正文;描述含糊同样点名维护者。
   悬空引用随之清除。
2. **词条对齐**:CONTEXT「skill 渐进式发现」从业务仓单翼扩为两翼
   同规;「通用定位 skill」的"对所有问题会话可见"落到快照路径与
   建索引自取的机制上。
3. **dts-diagnose 契约小节瘦身**:「执行纪律」小节(连续推进停机
   节奏/信息真缺才问的提问节奏/非问题合法性/轻量裁剪)退役为一条
   纪律归属指针,只留方法内迭代自由(分支可回退)——这四条全是
   所在会话工作流与平台契约已有的规矩,货架复述只制造第二真相源;
   知识边界条款从"靠逐条压制"变"物理不重复"。顺手修掉该节残留的
   「四要素」旧称与适用范围对已删小节的指针。

理由:渐进式发现的前提是 AI 知道去哪建索引。0014 把"描述没命中=
维护者的 bug"钉死之后,发现纪律本身就是唯一入口——入口里没写的
路径等于不存在。瘦身同理:外部 skill 复述外层契约,0014 之前靠
知识边界条款压制,现在直接删复述,边界物理成立。

**留痕扩展(代码落点,随实现带测试,本轮不动)**:analyze 入口扫描
同点扩扫 `.mae-flow-work/host-skills/`,货架清单**单独一行**进转移
账(如"货架通用 skill:N 个(...)"),不与业务 skill 混计——混计
会歪曲"业务 skill"的语义,也方便现场一眼分清两类来源。既有
issueSkillSelection 断言不受影响(空货架 fixture 不触发新行)。

## 与既定决定的边界

- **ADR-0014 不翻案,补第二翼**:渐进式发现是唯一取用方式、描述
  没命中是维护者的 bug、平台不举卡——全部原样;本篇只是把"去哪
  建索引"说全。0014 的留痕纪律(知情靠转移账)同样适用于货架行。
- **ADR-0005 不翻案**:依旧不装载正文(货架只读快照是既有形态)、
  不建门槛、Agent 普通 Read。
- **同日另一轮拷问的收束**:并行草稿曾拍「平台全量清单注入简报」,
  与 0014 已裁定的渐进式发现相抵,以 0014 为准;其与主干不冲突的
  残余增量(货架发现面、契约瘦身)收敛为本篇。

## 曾考虑

(a) 货架清单并入业务 skill 同一行留痕——歪曲"业务 skill"语义,
现场分不清来源,否;
(b) 把货架 skill 也写进开场词点名——路径属编排技能的索引纪律管,
开场词复述会漂移,否;
(c) dts-diagnose 整篇退役、方法论并进 issue-analysis——领域方法论
与编排契约分层是 ADR-0005 以来的既有结构,合并会让编排技能背上
五步法细节,否。
