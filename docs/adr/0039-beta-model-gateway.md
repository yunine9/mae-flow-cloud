# 模型网关双通道:Beta 白名单通道,不做用户自助 API

2026-09-18 拍板。平台模型接入立两套同形通道:平台网关(admin 现有配置,全员缺省)与 Beta 网关(admin 配的第二套,带人员白名单);白名单成员名下任务的模型调用全链路走 Beta,其余走平台网关。原议题「普通用户自行配置 API、仅对自己生效」被否决,改为 admin 托管。

**理由**:用户自助方案会同时踩三个坑——用户 apiKey 明文扩散进 N 个任务现场的 pi-agent/models.json(0600+现场回收的纪律按一个管理员密钥设计);任务 token_usage 分不清烧谁的钱(fail-open 回落平台网关=烧平台的钱,还掩盖用户配置坏);要另造闸门机制(总开关/白名单)。Beta 白名单通道把三坑一次消解:key 恒为两套且都在 admin 手里;账目恒归平台;名单本身就是闸门,无需新开关。代价是信任模型从「自助」变「托管」——成员的 key 要交给 admin 录入。团队内场景可接受;真出现「不想交 key」的诉求,解析函数多认一个按人输入即可,两案不冲突,到时再议。

**口径**:
- **覆盖**:白名单成员名下任务的全部模型调用全链路走 Beta(主会话/修复/预热/摘要/记忆起草/skill 提炼/prepush/开发助手),不按调用类型拆例外;Beta 配额紧张就收紧名单。视觉角色绑定不单独配,Beta 只有主模型四字段,vision 仍走平台网关。
- **解析时机**:会话启动现算——名单或 Beta 配置变更下回合生效,不进任务级 model_choice 的下单冻结。
- **失败回退**:fail-open,两级。解析级:Beta 配置残缺视同未配,静默走平台并出一行日志;运行级:网关运行期故障不做会话中途换道(会话引擎没有这机制),该回合按现有失败路径处理,下次会话启动现算自动落到可用通道。「Beta 好不好」靠 admin 手动点连通性测试验;已接受的盲区:连通性测试是时点检查,Beta 配坏后的回落可能长时间无人察觉——任务记录的 model_lane 标记是事后发现的主要线索。
- **协助归属**:跟会话归属(发起人)。A 协助 B 名下的单子,会话走 B 的通道;与「发起后归属仍是登录人、分支 master_{发起人}_{单号}」纪律同构。
- **与任务级 model_choice 的关系**:Beta 命中即整体替换,模型以 Beta 配置为准;任务级钦点仅在平台网关通道生效——钦点值来自平台网关的模型目录,跨目录兼容不做。
- **留痕**:任务记录记一笔本任务解析到哪条通道;fail-open 回落不回改标记(精确消耗看 token_usage 与网关侧账)。
- **实施**:两步走——先纯重构把约 9 处内联的「settings 压部署参数」fallback 链收拢成 resolveModelConfig(operator)(行为不变,现有测试钉住),再叠 Beta 通道(白名单命中=换一套 ModelsSettings)。散弹式直接叠功能会让回归面失控。
