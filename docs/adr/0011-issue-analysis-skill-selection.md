# 问题分析入口的业务 skill 圈选:月光关档的人为必读集合

2026-09-02 拍板:固定流程进入「问题分析」阶段时,若归属人月光关
(人工介入程度=全程把关/逐步确认),平台在阶段入口举「skill 圈选」卡:
机械扫描已拉仓工作区里的 `repo/<仓名>/.cac/skills/` 标准 skill,按仓
分组多选;选定集合写会话台账并注入 analyze 阶段简报,语义是**必读**
——选定的必须读,读完仍可按既有取用次序继续补充。空选或卡上明确
「都不用」= AI 按取用次序自主,不算异常。月光开(只看交付/全自动)
不举卡,AI 自主取用,维持现状。

理由:动机是控制权与知情——AI 用什么知识定位问题,人要过目,这与
「人工介入程度」的语义天然对齐:介入程度高的档位,人管的事就多。
挂过程轴(月光)而非字面四档,是因为圈选是分析阶段的过程行为,归
过程轴管;按字面"非全自动"会让「只看交付」档在过程段冒出人要答的
卡,与该档"过程自动放行"的承诺自相矛盾。一句话口径:**过程轴有人
(月光关)→ 人圈 skill;过程轴无人(月光开)→ AI 自主。**

时机锚在 analyze 入口而不是发起页,因为业务 skill 在仓里,仓是
prep_repo 才拉下来的——发起时仓往往不在场(无单场景未绑模块时必然
不在场),入口举卡则仓必然已落地,扫描就是读本地文件系统,无单场景
同样适用。

## 与既定决定的边界

- **ADR-0005(货架 skill)不翻案**:0005 否的是"治理驱动的平台化
  机械装载(仿需求侧 repositorySkills 只读快照)",留了"治理需要出现
  再加"的口子。本决定不装载、不快照、不建门槛——skill 仍在仓内,
  Agent 用普通 Read 读(工作区边界内的既有能力),圈选只收敛"必读
  哪些"。0005 的口子保持开放,两件事互不冒充。
- **ADR-0006(月光代答)现读现判照旧**:举不举卡看 analyze 入口
  时刻的月光现值;已挂起的圈选卡不因月光中途打开而追溯代答——多选
  卡本就不在代答范围(推荐项代答只认单选选项题,ADR-0006 扩展条款)。
- **货架通用 skill 不纳入圈选**:货架走治理过的发布通道(审核/版本/
  密钥扫描),"默认进所有问题会话"是 ADR-0005 拍过板的;给用户一个
  静默关掉团队通用方法论的口子与该初衷相抵。

## 会话生命周期内的行为

- **重走不重举**:整体回退、检视、确认闸补充意见回流 analyze 时,
  圈选集合会话内继承;要改圈选走检视意见(现场记录只追加不回写)。
- **无单转正**:集合随台账继承,前段视为已完成,不重举。
- **重启/续聊**:台账里的集合照旧生效,与"先读报告再继续"同一纪律。
- **扫描为空**:所有已拉仓都没有 `.cac/skills` 时不举卡,事件流留
  一行"未发现业务 skill,AI 按取用次序自主",直接进分析。

## 细节钉子

- **身份 = 仓 + skill 目录路径**:多仓同名 skill 不歧义;卡面按仓
  分组展示(与需求侧仓内能力发现同一惯例),台账存路径。
- **发现 = 本地扫描**,不复用需求侧网络发现:需求侧走网络是因为
  下单时仓没 clone、且资源加载先于 Gate 故只认 Git 已跟踪;问题侧
  举卡时仓已在工作区,读走的是已过工作区边界的 Read,威胁模型不同。
- **卡上无「AI 推荐」标注**:推荐的唯一机械消费方是月光代答
  (ADR-0004),而本卡只在月光关时出现、永远人答,推荐没有下游。
  将来月光开档若也要跑圈选(推荐被机械消费),再按 ADR-0004 接。
- **机械形态 = 台账 + 简报注入**:选定集合由平台写进会话台账
  (Agent 不可改),analyze 阶段简报列明必读集合。不做需求侧式快照,
  不动 stageRegistry 预留的 requiredResources 门槛列——"没读过不许
  出阶段"是另一个决策(0005 预留的伏笔),不与本轮捆绑。
- **知情面只动文案**:帮助中心「人工介入程度」词条与四档 hint 补
  一句"过程有人时,分析开始前会让你圈选仓内排障知识,不选则 AI
  自主";不加"跳过圈选"独立开关,卡上"都不用"即逃生口。
- **复盘不加归因机制**:问题会话没有需求侧那套知识足迹,读取事实
  在现场记录的工具调用账里;"选定的必须读"是本轮硬约束,违约看报告
  即知,归因标记等有消费方再做。

## 曾考虑

(a) 发起页多选——需复刻需求侧网络发现且无单场景死路,被否;
(b) Agent 用 AskUserQuestion multiSelect 当载体——卡面内容出自 AI
转述,发现结果少一层机械事实性,被否,定为平台闸;
(c) 封闭白名单(选后只许读选定的)——误伤真实场景(AI 明明看见
相关证据却不能读),被否,定为必读集合;
(d) 空扫描照举卡——浪费用户一次点击,被否;
(e) requiredResources 硬闸捆绑本轮——一个圈选功能长出硬闸,返工
代价大,被否;
(f) 读取事件归因标记——无消费方,被否。

## 落点(实现时触及)

新闸种(多选答复协议,现有闸裁决是单决策码)、service 在
prep_repo→analyze 交接处举卡、analyze 简报注入必读集合、台账字段、
帮助中心/四档 hint 文案。stageRegistry 的 analyze spec 加 gate 声明,
沿用"闸知识住注册表"的既有结构。
