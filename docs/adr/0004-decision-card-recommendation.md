# 决策卡推荐项:结构化字段、协议强制、只标注不预选

2026-08-29 拍板:AskUserQuestion 选项题必须带 `recommended`(所推荐选项的原文),校验器机械拦——缺失、对不上选项、自由文本题误带,整卡打回;服务端投影成推荐码随卡下发,前端「AI 推荐」徽标高亮但不预选,拍板权始终在用户。平台闸同款:宿主能定的在码表里定死,能从 AI 提案派生的(无单结论)按提案派生。

理由:推荐是将来**无审批全自动模式**的执行依据——机器要按推荐走,推荐就必须结构化、必有、机械校验;写进选项文本的"(推荐)"字样撑不住这三个要求。落点在共用校验器(sessionDriver)上,因此需求流的 AI 卡同样受"必须给推荐"约束——那是同一份工具协议,不fork;需求流前端暂不渲染徽标(UI 范围只做问题流,属既定裁量的省略,不是能力缺席)。

曾考虑"推荐可选、AI 拿不准可不给",被否:伪确定性的代价小于机器无据可依的代价;AI 真拿不准时应该补研究或给用户列全选项,而不是空着推荐。
