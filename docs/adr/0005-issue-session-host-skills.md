# 货架 skill 接入问题会话:通用豁免 + 报告章节门票

2026-08-31 拍板:问题会话装配(`IssueFlowService.openDriver`)补上
`hostSkillsDir`——团队货架 skill 按只读快照进问题会话,匹配走问题口径
(`knowledgeMatchesIssueSession`):任务口径上仅一处豁免,未限定仓库/
模块作用域的 engineering 通用知识进所有问题会话,技术栈维度不参与
过滤;未分类资产维持"不进"不变。同时 `submit_analysis` 的门票从
"报告文件在场"升级为"四章节齐全"(结论/证据链/置信度/下一步建议),
缺章节整单打回。

理由:问题分析质量此前几乎全靠仓内四个静态技能的文本约束——取证规范
与"结论必附证据"没有机械兜底,`submit_analysis` 只查文件存在;而团队
治理齐全的定位知识(审核/版本痕/密钥扫描)对问题会话完全不可见。通用
方法论走货架供给、分析产出设章节门票,是把分析质量从纯文本约定升级为
"供给线 + 机械关卡"。豁免的必要性:工程知识发布时必带 technologies,
而问题会话没有技术栈画像——严格沿用任务口径,通用定位 skill 永远
进不了会话;"每次发布记得打作用域标签"的替代方案被否,忘打标签即静默
失效,而通用方法天然没有仓库边界。

曾考虑:(a) 通用 skill 也要求先挂作用域标签——同上被否;(b) "业务
skill 与通用 skill 冲突时以业务为准"做成显式裁决规则——被否,取用
次序本身已表达优先关系(业务仓 docs/skills → 货架通用 → 仓内
issue-research → 裸定),替换式不叠加,裁决交给 Agent 的取用判断而不是
规则引擎;(c) 业务仓 skill 平台化发现装载(仿需求侧 repositorySkills
的只读快照)——本轮不做,先以"仓内 `docs/skills/` 约定 + Agent 按需
读"的轻量形态运行,治理需要出现再加。
