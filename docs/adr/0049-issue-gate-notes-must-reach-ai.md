# 闸作答补充说明必达 AI:重看豁免带话开回合

2026-09-21 拍板(#368)。流水线红灯举不可修告警闸,用户答「已在平台处理/豁免,重新监看」后,宿主只重置监看账重看同一提交、不开 AI 回合——既有注释写明「不开 AI 回合:监看是宿主的事,终态处理路径自会开回合」,预设作答只是确认。真实作答里指令往往在补充说明(选项装不下):#368 里用户两次写「回退 C++ 改用 JS」,补充说明只进转移账与事件账,永无回合送达;旧提交仍红,红灯通知重新派回合,AI 拿不到用户的话原样再举同一张卡,三轮循环。

决定:重看豁免作答带非空补充说明时,开一回合把话递给 AI(先按补充说明处置,监看器自然跟到新提交);为空维持原行为只重看。两种情况监看都照挂。同提交刹车帮不上忙不是缺陷——重看豁免清刹车账是有意的(#247:人声明平台已处理,重看仍红按新红灯重新计数),循环的根因只在话没送到。这条推翻「不开回合」的既有设计,同时立下词汇表不变量(见 CONTEXT「补充说明」):带补充说明的闸作答必须开回合送达,账本是留痕不是传话。

**曾考虑**:语义区分确认型/指令型,只对指令型开回合——否,宿主做语义预判是新的漏判点,纯确认白开一回合的 Token 代价远小于漏指令的循环代价;回合收口后再挂监看以消除竞态窗口——否,既有忙时转投(旧红灯 steer 进进行中回合)与「分支头已变丢弃旧结果」守卫已兜住竞态,不值得为它加收口钩子。AI 判「不可修」时漏掉「回退/换方案也算可修」的提示词补强随本决定一并落地,但不属本 ADR。
