# 润色稿跨页签驻留:确认弹窗等登记面板可见再弹

> **已被 ADR-0030 取代**:AI 润色功能整体退役,本文的驻留/渲染门机制随功能消亡,仅存决策史。

2026-09-15 拍板。登记页 AI 润色的挂起稿(已生成、未确认/未放弃)按用户名驻留 sessionStorage:顶层功能页签切换(工作台、我的任务等,看板整体卸载)不丢,刷新白送存活——润色请求进行中刷新仍会丢(页面卸载杀请求,救不了)。确认弹窗被「手工登记面板可见」渲染门 gate 住:人不在登记页时只驻留不弹(DTS 子页签也不算回来),切回瞬间弹回。无过期机制。润色进行中切走再切回属重挂:在飞请求登记在组件外,重挂实例恢复「润色中」灰化并接续迟到结果(照常落驻留与弹窗);被新请求顶替的旧结果不再落账(最新胜出)。

**理由**:确认弹窗 portal 到 body、越过 `hidden` 父级——人切到问题会话子页签时,润色完成会当面弹出打断;而顶层页签切换卸载看板后,组件内的润色稿直接丢失——请求照跑,结果落进已卸载组件的 setState 空操作,无人接收(服务端不落库,只存在于前端确认流)。「浏览器页签没关就在、关了就清」正是用户对驻留的语义预期,sessionStorage 恰好就是这条生命周期,与草稿、列表筛选的 localStorage 纪律同族。

**边界**:失败回执不驻留(明确非目标)——失败即逝,回来重按一次;挂起期间结构上点不到第二次润色——请求中按钮灰化(现有),挂起中弹窗模态挡住表单;登出换账号登录因键带用户名天然隔离;换面板/切页签收起弹窗不清稿,弃稿只认显式动作(放弃/Esc/遮罩)与替换。

曾考虑:模块级内存变量——更简,但刷新即丢,不符「页签没关就在」的原话语义;localStorage——重开浏览器都在,对一次性瞬态回执过度驻留;提示条点击再弹——多一层 UI,违背「切回即弹」的拍板。
