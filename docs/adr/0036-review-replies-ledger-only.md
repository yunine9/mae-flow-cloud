# 检视回复一律落账在意见处,报告不带「检视意见回应」段

2026-09-17 拍板(ADR-0035 红线的修正)。修改型意见的回复不再写进新版报告开头的「检视意见回应」段(ADR-0025/#261 引入的软性章节,删除):重写完成后,修改型意见同样逐条 respond_review 交代(说清改了什么,fixed 附依据),回复型照旧原地回复——检视回复只有落账一个家(检视面板意见卡下),报告保持交付物原貌。

**理由**:回应段与 respond_review 落账是同一语义的两套实现,且回应段把问答内容混进交付物——用户实际反馈:意见卡下看不到回复(修改型根本不走落账),重写版报告反倒带着应答材料,观感差。回复在意见处落账已有账本(AnnotationStore)与呈现位,回应段没有增量收益;它原本承担的「逐条给交代、不许漏号」约束改由 respond_review 承担(renderReviewNotes 修改版护栏:逐条交代、不许漏号、不该改的说清理由、报告不带应答段)。

**时序**:分诊回合只 respond 回复型意见(修改型不冒充已回复),declare_review_rework 整体回退重写照旧(ADR-0035);重写回合里报告改好后,对本批意见逐条 respond(分诊回合已回复过的不重发),再 submit_analysis 举确认卡——用户在确认卡上看到的是干净报告,逐条交代在意见卡下。

**统计联动**:版本账口径不变(修改型才出版本);「一次定位成功率」仍以版本账为准,不以检视批次数为准。
