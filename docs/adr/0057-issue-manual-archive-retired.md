# 手动归档入口整体退役:control 只剩取消与异常重跑,终态卫生尾巴共享化

2026-09-24 拍板(grill-with-docs 会话,#434)。ADR-0034 已退役**有单**会话的手动归档(交付出口=全部 MR 合入自动归档),但 `control(action="archive")` 入口保留给两类现场:无单存量挂起会话的收口,以及全场景的「取消」。#434 实证这个双轨活口的代价:自动归档路径(`autoArchiveDelivered`)漏调 `reclaimAfterCodeOrigin`,归档单的 code-origin.json 不落盘、repo/ 不回收,在达标率页顶着「待算」等每日清扫器兜底(最长 24h);横向排查发现结论闸闭环归档(conclude 卡答「确认是问题/非问题」)同样漏调,且自动归档还漏 `vault.remove`(凭据残留到重启对账)。终态尾巴在 4 天内两次被写漏(ADR-0044 上线只扫了手动路径、ADR-0048 新路径出生又没抄全),证明「靠约定记住完整收尾」守不住。

决定:

1. **手动归档入口整体删除**:`control` 动作词收成 `"cancel" | "revive"`,archive 分支(有单/非挂起两道报错门禁、结论 kind 三岔猜测、归档写路径)全删;路由白名单同步,拼错动作一律 400 fail-loud。`kind`/`summary` 请求字段随归档语义一并退役。取消语义不变:仍是运行中会话的即时停止出口与 failed 的出口之一。
2. **存量挂起只取消**:手动归档删除后,ADR-0048 退役挂起/转正前的存量挂起会话唯一出口是取消(不入结论统计)。登记统计口径注释与 UI 文案(挂起说明卡、协作流 blocked 提示、associate 410 指引)同步改指「终止会话」。
3. **终态卫生尾巴共享化**:新私有函数 `finishTerminalHygiene`(冻结终态快照→清理环境凭据→入队首次生成归属并在算完后回收现场),取消、结论闸闭环归档、交付自动归档三条终态路径统一调用;停容器同步/异步、通知、提单模板等由触发场景决定的差异留在各路径。凡写 archived/canceled 的第四条路径出现时,漏掉尾巴在代码评审里是一眼可见的单点偏差,而不是再靠人记得四个动作。
4. **归档对话框遗产清退**:`POST /issues/:id/merge-status` 路由与前端 `issueMergeStatus` 封装删除(归档对话框早已不在,前端零调用);服务侧 `mergeStatus()` 保留为合入事实单次现扫入口——生产的持续同步由合入监看循环承担,监看未启动的窗口要把事实落账时(测试、诊断)走这一扫。
5. **结论词表与生产者一一对应**:删除后 `delivered` 只由交付自动归档写入,`issue`/`non_issue` 只由结论闸写入,不再有「按 mrs/pushes 现场猜 kind」的第二写入者。

理由:结论产物(待算达标率、磁盘回收、凭据清理)要求的是「每条终态路径行为一致」,而触发形态(用户点按钮要等容器停净、闸作答与合入事件要快回)天然分叉——把一致的部分收进一个函数、把分叉的部分留在原地,是对「行为应该一样吗」的准确回答:该一样的由结构保证,该不一样的各归其位。曾考虑只补两行调用(原 #434 提案)——否:那是第三次靠人记得尾巴,且 vault.remove 的同类遗漏还在;也曾考虑把停容器/通知一并收进共享函数——否:同步等停与快回是真实的需求差异,硬统一要开参数洞,复杂度只是搬家。

后果:存量挂起会话无法再以「确认是问题」结论收口,登记统计(只数结论已出)会随存量经取消退场而少计——存量规模有限且用户已拍板不考虑;`GET` 读路由与归档会话只读路径不受影响,归档会话的网页查看照旧。自动归档与结论闸归档即时起伴生计算与现场回收,归档时刻多一段后台 git 开销(ADR-0044 既有设计,手动路径一直如此);取消路径的入队行为不变。旧前端若仍发 `action: "archive"`,得到 400 与指向性报错,不是静默落空。
