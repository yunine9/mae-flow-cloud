# 问题会话异常重跑:failed 第二出口,原地复活带全现场

2026-09-23 拍板(grill 设计会话)。问题会话底层异常(模型报错/崩溃/卡死等,一律黑盒)落到 failed 准终态后,唯一出口是手动取消,取消后重新发起=新问题单目录——分析报告、检视意见、人工决定原文、事件账、阶段与轮次账、代码现场全部断代;操作者排除异常后想带着原上下文继续,无路可走。而现有恢复机制(重启自续跑、idle「继续」、超限/限流/401 分诊、resumeSession 原样接回)全部只在会话内工作。现场盘点表明:宿主层现场(issue.json 账本/events.jsonl/waiting.json/分析报告/repo/)绑问题单目录而非内核会话,failed 又豁免现场回收——洞虽在,现场大多还在。

决定:

1. **failed 增设第二出口「异常重跑」**:问题工作台操作区(与取消同位)提供重跑按钮,责任人可按;不取消、不动问题单目录,状态拉回进行中并开恢复回合。
2. **异常是黑盒**:平台不诊断、不自动重试;操作者显式确认异常已排除才可触发(异常不可预测,诊断与处置是操作者的事)。
3. **恢复回合的上下文**:优先 resumeSession 原样接回 Pi 会话上下文(同重启自续跑链,接回含工具结果与压缩边界);Pi 原生文件不可用时降级为账本投影续聊词(issueResumePrompt 路线:重灌登记元信息、最近阶段、报告指针、检视意见恢复源、已推送/已建 MR 账)。
4. **交接内容=账本投影,不信模型摘要**:登记元信息、阶段与轮次、报告指针、检视意见原文、末几条人工决定原话走确定性投影;模型生成的过程摘要仅在降级路生成一次,不作为长期账本(沿 materializeAnalysisDecisions 先例:不拿上一位 Agent 的摘要替代人的原话)。
5. **账务口径同续聊先例**:轮次账不动(不 round+1),落一条异常重跑语义事件进事件账/审计账;阶段保持 failed 前原样;在途问题卡/闸/监看按重启恢复先例处理(作废待办、回灌末条人工决定)。
6. **操作者可附一句话说明**:随恢复回合必达送达 AI(补充说明不变量:带说明必开回合送达,只记账不算送达),空则发默认词「操作者确认异常已排除,继续推进」。

接受的代价:

1. failed 的「可恢复态」语义正式化:状态机新增 failed→进行中转移;在途账(挂起的卡、流水线监看、修复轮刹车账)要逐项对 recover() 清单清理/重挂,不能只翻状态字段。
2. 异常重跑与「重新发起」并存两条路:重跑原地续(现场全在),重新发起新开目录(现场断代)——工作台文案要讲清差别,防止误用重新发起丢现场。
3. 轮次账不推高,统计口径把重跑视作「同一场没断」——一次解决率等指标不被异常污染,代价是异常频次本身只能从审计账看,不进指标。
4. 复活时删除 failed 期冻结的终态快照(ADR-0042 的读侧只在终态读快照,复活后会话已非终态,留着会让"只生成一次"的读侧把 failed 版本当终局),最终收口时按现行纪律重新冻结。

**曾考虑**:

- 继承式重发起(取消后重新发起勾选继承旧现场):否——转正继承先例已退役(ADR-0048),两本账并行的一致性成本高;且取消即触发现场回收,继承时间窗不可靠;
- 纯模型摘要交接(总结旧会话喂新会话):否——摘要失真,违反宿主「投影原文」哲学;只收编为降级路的补充;
- 检查点回拨(回到出事前某轮重来):否——工作区代码无快照机制、远端副作用(已推送分支/MR/评论/通知)不可逆,与「账本只增、追加修正不撤销远端」哲学正面冲突;「回到 analyze 重来」的合法需求已由整体回退覆盖。
