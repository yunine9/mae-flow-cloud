# 会话级介入档位:DTS 列表发起前按单定档,创建即定格(全局档保留为缺省)

2026-09-24 拍板(grill-with-docs 会话)。介入档位(ADR-0019)此前只有账号全局一档:个人设置「人工介入程度 · 问题处理」三档,按会话责任人现读现判。有人反馈想要会话粒度——不同的问题单想用不同的档(例行单全自动,棘手单优先对齐),而全局旋钮一刀切。另有一处旧拍板就此部分推翻:需求交付四档卡上「一个旋钮说清,不做任务粒度设置」的决策不延伸到问题侧——问题侧现在有会话粒度,但只在发起前。

决定:

1. **只在发起前可设**:DTS 列表新增「介入档位」列,未发起行是四选项下拉(跟随全局〔缺省〕/全自动/优先报告/优先对齐);选中的档随创建请求(`intervention_tier`)定格进会话状态,发起后不可改——没有写路由。偏好存发起人本地(localStorage 按人按单,同发起备注款),发起成功即清条目(已消费);协助视角未发起行不设(偏好只影响自己的发起)。
2. **覆盖语义**:会话状态有 `intervention_tier` 时终身用它,不吃全局改档;缺席=跟随全局,继续现读现判感知个人设置的变化。`tierOf` 一处改读取顺序(会话字段 > 账号回调 > 缺省二档),开场词/续聊词/闸代答/环境闸等全部派生路径自动跟随。特例随会话走:责任人转手后新责任人继承。
3. **进行中行只读**:特例过的显示档名,没特例的显示「跟随全局」(自己的会话悬停可见当前实际生效档);已闭环行显示「—」。

理由:发起后改档没有实际价值——三档的行为差异集中在分析阶段与报告确认拍点(优先报告「分析过程不问,报告是唯一停靠点」、优先对齐「证据不足主动问」、全自动「报告提交后平台自动确认」);报告确认之后的流程三档同构(都直推、MR 都人工、红灯都等人),唯一的窗口是报告确认那一拍,而那一拍人自己点一下确认就等效。跑偏了要纠正,报告检视提意见或续聊直接说,都比改档位直接。省掉写路由,也少一个越权面(介入档位本质是责任人对自己会话的授权,不开放他人代改)。

后果:创建路由对 `intervention_tier` 做三档合法值校验,非法 400;服务直调同尺兜底。存量会话无此字段,读作跟随全局,零迁移。全局旋钮语义不变(仍是所有未特例会话的现值),设置页文案补「可按单特例」一句。
