# DTS 逐单分支匹配,退役列表级产品版本选择

2026-09-17 拍板。DTS 列表不再挂全局「产品版本」选择框:每个单子的分支由其版本号推导——单据版本字符串**包含**配置中心配置的某个产品版本即命中,多命中取最长。配置中心「版本与分支」页签仍是映射的唯一维护点;匹配在后端单点实现,DTS 列表 API 逐单带出分支,前端分支列纯展示。未命中显示「未配置分支,前往配置」(深链 `/configuration?tab=versions`),该行禁发起:前端禁勾选(与「已发起」同款先例),后端 create 对 dts 来源硬拒绝,"未匹配沿用原基线"的静默兜底一并废除。基线分支在远端仓里不存在时,pull_repo 硬失败回报事实,不再退回默认分支继续——两处静默兜底都让位给"没有正确分支就不动代码"。

**理由**:选择框回答"这批单在哪个分支",但每个单据的版本号本就各自携带分支事实,全局选择在混合版本批次里既冗余又可能选错;包含匹配贴合 DTS 版本带 B 版构建号(版本组之外还有 B 段)的现实——精确匹配要求配置中心逐 B 版枚举,维护不现实。多命中取最长:更长配置段是更具体的命中。匹配逻辑收在后端单点,列显示与发起解析永不漂移。

**后果**:显示=现算、执行=快照(发起后改配置不影响进行中会话,与既有环境快照同一纪律);发起时不做远端分支预检(不为它新增 ls-remote 机制),分支存在性只在拉仓时刻裁决;手工登记与需求侧发起的产品版本选择框不在本次范围——它们没有单据版本号可推导,全局选择仍是唯一入口。配置文件本身损坏按"零配置"处理:列表分支列全体呈现「未配置分支」,发起一律拒绝——坏配置不炸拉单页,但也没有单子能在无从核对分支的情况下发车。分支补齐在单张详情接口与列表同源,远程查单入列的单子不因绕过列表而误报未配置。
