# 问题域参考数据接口免登录允许清单:拉单/详情/绑定/模块目录/人员名单匿名可达

2026-10-30 拍板(#566):鉴权开着的部署里,六条精确到 method+path 的参考数据接口允许匿名(不带会话 cookie)访问——`GET /issues/dts`(匿名必须显式 `?owner=` 指名,缺省即 400 打回)、`GET /issues/dts/:ticket`、`GET /issues/dts-bindings`、`PUT /issues/dts-bindings/:ticket`、`GET /business-modules`(仅列表;写与逐模块操作仍在闸后)、`GET /auth/people`。目的:支撑无头本地客户端(zcode-mae)零凭据最小集成——这些接口的数据本身与人无关,是团队共享事实,此前要求先持用户身份才能读,只是登录闸统管 `/issues/*` 全域带来的副作用,不是数据契约的需要。

**理由**:`/issues/*` 全域挂在 `authEnabled && !viewer → 401` 一道闸后(routes.ts 顶部),对拉单、绑定映射、模块目录这类共享参考数据是过度约束。客户端为此要么持有用户会话 cookie(把个人身份塞给无头进程),要么整套 mock 自建。数据敏感性逐条核过:DTS 单据在 DTS 系统本就全员可见(平台是镜像),绑定映射与模块目录是团队共享配置,人员名单只有工号与姓名两个公开字段。放开这一小撮,客户端保持零凭据配置。

**决策(拍板)**:
- 允许清单由各域路由文件自己维护:问题域在 `handleIssueRoutes` 闸前判精确 method+path 集(`anonymousAllowed`),业务模块目录在 server 层 protectedRoute 表按方法拆开,人员在 auth 路由块摘 401。不做中央匿名路径表——豁免跟着路由走,改路由不会漏改中央表。
- 默认拒绝是结构性的:清单之外的现有路由与一切新增路由照旧落闸,不靠人为纪律。
- 匿名拉单 owner 必填:`?owner=` 缺席且无登录态即 400「缺少 owner」,不静默查空。仅限鉴权开着的部署;无鉴权本地单人形态(authEnabled:false)维持原缺省,不受匿名契约影响。
- 绑定改选的匿名写:操作人以请求体 `account` 自报(内网信任调用方),缺席 400;登录态在场恒取登录身份,客户端改写不收——与 `POST /issues` 登记人同哲学。域校验照旧(单号格式、模块存在且 active)。
- 匿名调用者无角色,按开发者待遇;管理员 403 边界对匿名自然不触发。

**信任模型(拍板,已知悉接受)**:平台是持 DTS 网关凭据的代理,放行即接受「能摸到平台端口的内网设备,无需 DTS 账号也可经平台拉单」——匿名读把这层读面广播给整张内网。部署前提是内网可达、DTS 本就全员可查的环境。匿名调用无归属、无撤销(只能改代码重部);`PUT` 的 `updated_by` 是自报值,不构成审计事实,只供对账参考。

**先例澄清**:小鲁班插件回调是「独立固定 token 的单一写入口」,`body.account` 只在无鉴权部署形态生效——两者都不是「鉴权开着却匿名放行」的先例。本篇是第一处这样的口子,故立 ADR 存照;它不构成对其它接口放开的先例,每次新增都要单独拍板。

**不在清单内**:`/issues/dts-file`(描述内嵌图代理;客户端要渲染内嵌图时另行提案)、会话读侧(列表/详情/材料/事件)、一切会话写操作、交付分析、需求域、任务域。服务端不加 CORS 头——面向桌面直连客户端,不受浏览器同源策略约束;浏览器内核形态的客户端撞跨域时另议。

**切换说明**:纯放行,无破坏性变更——带 cookie 的既有调用行为不变;客户端(如 zcode-mae)401/403 降级提示随之退役。

曾考虑:(a) 给 zcode-mae 签发客户端 token(小鲁班模式推广到读接口)——否,零凭据是集成目标,信任模型已接受,token 的归属与撤销收益在此场景换不来配置成本的合理性;若部署环境比 DTS 暴露得更广,应重开此案。(b) `PUT` 绑定保守留闸、客户端降级只读——否,发起前数据准备需要闭环改选,自报工号在已接受的信任模型内。(c) server 层统一匿名路径表——否,豁免与路由分居两文件迟早漂移。(d) 缺 owner 一律 400 不分部署形态——否,误伤无鉴权本地单人形态与测试世界(viewer 永远缺席,原缺省是它的正常路径)。
