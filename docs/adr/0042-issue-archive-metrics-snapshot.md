# 问题单统计:账记事实,归档时一次冻结快照

2026-09-19 拍板(父讨论 issue #317 的后继)。问题单的度量体系分两层:**事实账**(一直就有,issue.json 逐笔记发生事实——推送、验证未通过、报告版本、外部头观测(分支头被平台外推送取代的每一次发现记录)、转移账)与**指标**(事实的投影,onceRates 现算)。本决定补第三件东西:会话到达终态时,把原子事实程序化计算一次,冻结成会话目录下的 `metrics.json`——只读、与该会话天然关联、此后不再变。

**理由**:issue.json 不能无限变长,统计也不该每次全量重算;但预存计数器会与事实账漂移、口径换版要迁移、新指标无法回溯。冻结快照是"事实账的可重算视图"而非第二真相源:事实仍以 issue.json 各账为准,快照带生成版本戳,口径升级或快照缺失时可从事实账重新生成;从现场算不出的列(如代码现场已回收后的逐推送 diff)如实标注"不可得",不虚构。

**快照怎么算**(全部在归档那一刻、代码现场回收之前完成):

- **事实投影(零新记账)**:仓数、各仓推送次数与提交号清单、检视三口径(平台检视意见条数/检视批次/MR 评论条数)、分析报告版本数、验证未通过次数、红灯各轮处置结局(修复/随合入取消/随头变丢弃)、外部头观测记录、各阶段耗时、答卡次数与答案、回退次数与原因、MR 事实(数量/合入/关闭)、端到端时长。
- **归属比对**:推送工具已程序化记录平台每次推送的提交号(推送账);归档时 fetch 一把 MR 的完整提交清单,与推送账比对——合入内容中哪些是平台(Agent)提交、哪些是平台外提交,终局一次算清,连中间被覆盖的外部提交也拿得到(它们仍在 MR 清单里)。实时观测记录保留为补充(它带时刻信息),不承担完备性。
- **逐推送 diff 统计**:对推送账相邻两次推送的提交区间统计文件数、增/删行总数、仅源码的增/删行(源码=扩展名白名单常量,首版内置常见后缀)。放在归档时算而非推送时记——单点实现,推送工具零改动;降级路径:现场已回收或对象不可得时该列标"不可得"。
- **降级总则**:分支被平台删除、fetch 不可达、现场丢失——一律退回观测记录+推送账,缺项标注,不阻塞归档。

**读侧**:统计接口对终态会话读快照(快、稳),在途会话现算;快照缺失时回退现算。快照对所有终态(交付/取消/失败)一律生成,是否进分母归读侧口径(一次率两轴分母仍只认完成交付)。

**随迁面**:CONTEXT 补「原子事实」「平台检视意见」「MR 评论」词条;一次率两轴口径不变,快照是其原料的超集;新增指标(外部介入度、外部合入收口占比、端到端时长、每单推送数等)从快照/事实账投影,呈现后议。

**曾考虑**:推送工具逐次记 diff 统计——否,归档前现场都在,单点计算更简单,推送路径保持零负担;metrics.json 只存计数不存明细——否,丢明细就无法回溯新指标,快照存"原子事实+投影"两层。
