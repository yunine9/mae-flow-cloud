# 环境验证卡删「验证通过」选项——合入即通过是唯一通过出口

2026-09-19 拍板(修订 ADR-0034 的验证出口口径;「验证合入阶段」提案收窄为本决定,不动阶段机)。**环境验证卡(env_verify)删掉「验证通过」选项,只留「验证发现问题」。** 通过无需作答:全部 MR 合入即视为验证通过并自动归档收口——合入即通过从「未答时的默认」升格为唯一通过出口。

**理由**:ADR-0034 已规定「自动归档在统计与流程语义上=验证通过,一直没答卡的视为认可」——「验证通过」按钮在此语义下是冗余动作,点它不改变任何事实。删掉它顺带消掉一串边角:答 pass 后的「已验证待合入」中间态(只有自由文本停机说明、没有结构化字段,守闸器还要专门排除它)整个退役;答 pass 后阶段已收口且无闸,催办判据会把停机误判为「欠验证卡」再催 AI 重新举卡的潜伏不一致一并消失。等待的显示词同时按在场卡派生:环境验证卡在场显示「待验证」(查看模式「待责任人验证」),不再与「等你答复」混同——阶段机不动,「提交 MR·跑绿」仍是末阶段,验证窗口的等待语义由在场卡承载。

**统计口径收紧**:一次修复成功率公式不变(转移账里出现「用户环境验证发现问题」前缀即非一次修复),但实质变严:此前「答 pass 后续聊返工」不进失败计数——验过了又要求改,第一轮其实没修好,这是统计漏洞;此后绿后的一切返工必经「验证发现问题」作答,一律计入非一次修复。

**MR 全被 close(未合入)不建终态**:这种现场流程本身已经不对,不为其设计专门收口——责任人点「验证发现问题」写明原因走整体回退(返工轮 create_mr 按仓替换台账记录,被关闭 MR 的死账不会堵住「全部合入」判定),或取消会话。

**随迁面**:卡面问题模板与 AI 回执/通知词(mrgate.all_green、mrgate.empty_ok、green.deliver、催办词)改为「等待用户验证(可不答,合入即通过)」;码表 GATE_OPTIONS.env_verify 删 pass 码,GateVerdict 删 pass 成员,service 的 pass 分派与 VERIFY_PASS_NOTE 退役;输入区、卡座状态签、卡片状态词、团队页现场范围四地按 gate.kind 派生「待验证」,团队页「等你答复」档排除环境验证卡在场者;红灯停泊通知在卡在场时不再覆盖停机说明(等待语义以卡为准);部署在途的旧卡若被补点「验证通过」,按认不得的答复原样 409,刷新页面即见新卡面。

**曾考虑**:新增「验证合入」固定阶段(弹卡时切阶段、外侧提示随阶段变)——否,阶段值绑着合入轮询、催办、守闸器与回退清理一串判据,收益只是显示词,由在场卡派生即可零风险达成;验证卡整体退役(ADR-0034 已否)——保留「发现问题」通道,环境里是否真的好只有用户知道。
