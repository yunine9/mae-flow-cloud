# 问题分析 skill 圈选闸拆除:渐进式发现是唯一取用方式

2026-09-03 拍板:拆除 ADR-0011(2026-09-02)的 skill 圈选闸。业务仓 skill 的取用回归且只有一种方式——**渐进式发现**:AI 先建索引(逐仓列 `.cac/skills` 的 name+description),拿索引与当前问题对相关性,相关才读正文。全程 AI 自主,不分介入档(月光开/关一致),平台不举卡、不圈选;analyze 入口的扫描降级为留痕(发现清单进转移账,现场可查当时有哪些可用),`skill_selection` 台账不再产生(存量会话的旧台账与挂起卡照旧消费,封存不删码——与 ADR-0013 同一纪律)。

理由:圈选闸的唯一增量价值,是"人能看出 skill 相关、AI 从 description 映射不出来"时强行补位——而这恰恰是描述质量问题的症状,该由 skill 维护者在源头修(把触发场景写进描述),不该由运行时的归属人拿选择卡兜底。渐进式发现的成本结构也更好:AI 建索引是几次廉价的 frontmatter 读取,相关性映射是它的本职;人工圈选则把每次分析都变成一道打断,而全程把关档的用户恰是最容易被卡片疲劳的人群。空选虽然合法,但"永远空选的卡"就是纯噪音。一句话:**描述没命中 = 维护者的 bug,不是用户的作业。**

与 ADR-0011 的关系:0011 的动机(控制权与知情)成立,但手段过重——知情由扫描留痕满足(转移账可见当时清单),控制由"必读而非白名单"的自我削弱而基本落空(选了 AI 也只多读几份文件,不选它照样按取用次序找)。0011 不翻案 ADR-0005 的部分(不装载、不快照、Agent 普通 Read)继续成立。与需求侧的对照:需求侧的仓内能力勾选发生在下单页(发起前的表单时刻,人在填单状态),问题流把勾选挪到 analyze 入口成了运行中打断——两侧本就不同构,问题流回归"无卡"侧。

曾考虑:(a) 圈选卡降级为非阻塞提示——知情价值已被扫描留痕覆盖,提示仍是噪音,否;(b) 只在"扫描结果与单据关键词相关"时举卡——相关性判断本身就是 AI 的活,做成就绕回了"AI 自己决定",闸失去存在理由,否;(c) 保留月光关档举卡——把关档的语义是"关键决策人拍板",skill 必读集合够不上关键决策(选错最多浪费几份正文阅读),否。
