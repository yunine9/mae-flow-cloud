# 问题流自动接单:个人自助开关(初版为管理员名单,次日修订),定时替责任人自登记名下 DTS 单,校验与人工发起同尺

2026-10-09 拍板(wayfinder grilling 三轮,领导诉求"责任人名下有问题单就自动开始处理"):平台新增**自动接单**——定时把自动接单名单内开发责任人名下符合条件的新 DTS 单自动发起为问题会话。自动只接管**发起**这一个动作,处理深度仍由责任人的介入档位决定(缺省二档「优先报告」,自动接的单跑到分析报告确认卡自然停)——不新造无人值守形态,不改五阶段流程语义,source 仍为 dts。

**修订(2026-10-10,用户拍板,静态原型定稿后实现)**:开关从管理员名单迁入**个人设置**——个人自助开关成为唯一闸,缺省关闭,谁登录改谁的(`PUT /auth/me/issue-auto-claim`);名单与按人代开退役。迁移动机:发起以责任人名义自登记,Git 提交用其令牌、MR 挂其名,同意权应随身份走;介入档位已在个人设置,自动接单与之同域。管理员保留两根**全局**杠杆:扫描间隔(0=全团队暂停,个人开关原样保留、恢复即续)与配置中心「参与自动接单」版本组勾选。取舍:领导不能再点名强制某人开启,推广靠动员;若将来要"资格"层,存储字段(auth.json 每用户布尔)不变,可在个人开关之上无痛叠名单。界面纪律:说明只留一句,「符合条件」规则与下次发起时间收进问号悬停(新增 `GET /issues/auto-claim` 读调度器下次扫描时刻;间隔为 0 显示「已暂停」),页面无常驻附加信息——用户按下次发起时间自行观察,没按时发起即有问题,排查走审计账与管理页旋钮。下文名单时代的拍板按 2026-10-09 时点原文保留,凡与本期修订冲突处以本段为准。

**开关模型(拍板)**:自动接单名单是唯一开关,没有用户个人开关。管理员在人员页(People)按用户勾选,存 auth.json 每用户布尔字段,现读现判、跨实例一致:在名单即开、移出即停、重加即再开,单一真相源,不存在"添加了却不生效"的冲突场景。名单只闸"接新单"——移出名单不取消已发起的进行中会话(那已是普通会话,归既有机制管)。管理员账号不可入选(管理员不写问题会话,create 硬闸兜底)。名单本身就是灰度旋钮:先加一人试点,逐步扩大。

**扫描与校验(拍板,同尺铁律)**:自动接单是"替人点了一下发起按钮",与页面上人工发起走**完全相同的校验链**,一条不少、不发明第二条规则。服务内定时器(知识沉淀 startScheduler 的「setInterval 一拍 + 单飞防重入」样板,由正式入口接线驱动),默认 30 分钟一拍、间隔做成管理页旋钮(0=关,即功能总开关),不限时间窗——问题会话不要求人在线,半夜发起早上看正合适。每拍逐名单用户调 DTS `listByOwner`(currentHandler=工号),逐单过滤,任一不过即跳过本单:

1. 单据状态须为「开发人员实施修改」——交付流转走后(待验证/已解决)不会被重复接;
2. 该责任人名下无此单的非终态会话——与「已发起」判定同尺,create 内同账号+同单号去重兜底;
3. 单据版本命中配置中心标记「参与自动接单」的产品版本(版本组粒度,勾一组=组内全部 B 版)且分支映射存在——ADR-0038 分支匹配同尺;
4. 单据特性名强匹配业务模块——模块带出同尺。

宁可漏发不可错发:任何拿不准都跳过。DTS 网关异常整拍跳过、下拍再试;不加单拍限流,并发额度(queued 排队)是唯一流控,名下积压多拍自然消化。

**发起身份(拍板)**:自登记形态(ADR-0031)——create 的 account=assignee=责任人工号,reporter 归一;Git 凭据门查责任人(requireGitAccount 现成),无凭据 create 抛错、跳过记审计。会话记「发起方式=自动」展示标记,通知文案带"系统自动接单"字样(复用 create 的指派通知链路);交付分析统计(一次定位率等)暂不按来源拆分,上线观察后再议。

**发不了的单(拍板)**:静默跳过,只落审计账(进程级 logs/,ADR-0053 样式,记单号/责任人/跳过原因),不通知任何人——"发不了"的通知是噪音,DTS 列表的人工发起入口照常在,谁想发谁发。版本未标记的老版本同此:按规则不归自动管,忽略且不通知。与"该处理但发不了"不作区分,统一静默。

**曾考虑**:(a) 双层开关(管理员名单×用户个人开关,AND 语义)——推演"移除再添加不复活"等冲突场景后,用户拍板最简模型:名单唯一开关,用户无退出权,冲突问题不存在;(b) 自动接的单固定一档全自动——否,自动发起≠无人值守,一档会"高置信非问题自动关单",单主还没看过单子就被关掉,风险不可接受;(c) 单拍限流旋钮——否,并发额度已在流控,积压顺延消化,多余一道旋钮多一分理解成本;(d) 发不了的单通知责任人——否,守住口子、宁可漏发不可错发,通知即噪音;(e) 外部 crontab 打内部触发 API——否,/issues 写操作全线登录 cookie 鉴权,为它新开 token 端点不值,服务内定时器零新增攻击面;(f) 名单放 settings.json 独立编辑器——否,按用户布尔挂人员页与账号同处治理,管理员一眼可见。

**验收(实现期)**:定向测试——调度器单拍扫描的过滤矩阵(状态/版本组标记/分支映射/模块匹配/非终态去重逐项)、名单增删下一拍生效(现读现判)、自登记身份与责任人凭据门、审计跳过行(带原因);根 typecheck。人工发起路径回归零改动:create 校验链未被为自动路径分叉。
