# 问题结论词表收敛:fixed 并入 delivered,converted 并入 issue

2026-09-17 拍板(收掉 ADR-0022 引入的 delivered/fixed 细分)。归档结论词表从五档收敛为三档:`non_issue`(非问题)/ `delivered`(修复完成即交付)/ `issue`(问题成立,含转正收口)。

**理由**:两个被收掉的档位都答不出"知道之后做什么"。
- **fixed(已修复未合入)**与 delivered 的差异只在 MR 合入状态,而合入状态本来就逐 MR 记在 mrs 账里(会话详情/合入通知都展示)——结论格再复述一遍没有增量信息;ADR-0034 之后有单会话的交付出口只剩"全部合入自动归档",到手动归档还能归档的有单现场近乎不存在,为它维持一档结论更没意义。归档瞬间的合入竞态复核(syncMergeFacts)只为这道细分服务,一并退役。
- **converted(已转正)**描述的流程事实(旧会话因关联单号转正让位给新会话)由 `converted_to` 血缘字段承载(元信息页「转正自/转正去」照旧),结论格再立一个档位,用户看不出它和"问题成立"在处置上有什么不同——转正的前提本就是问题成立。

**口径**:delivered=修复完成归档,合入与否看 mrs 账本身;一次率分母(完成交付)随之把未合入的手动归档也计入(修复完成即交付)。存量旧账在读盘时归一(`loadState`:fixed→delivered、converted→issue),磁盘原值不动,统计与展示不认旧词;关联转正的旧会话归档时直接记 issue。

**退役词汇**:「已修复(fixed)」「已修复未合入」「已转正(converted)」不再作为结论档位出现;挂起转正的**流程**不变(两段式关联、新会话继承、单号唯一),只是旧会话收口时的结论词归入 issue。
