# 首次生成占比改工作量口径;指标家族改名定位率/验证率/解决率

2026-09-20 拍板(同日修订 ADR-0044 的度量定义;#342,原型驱动的走查后拍板)。问题单交付统计上线当日的两个修正:

**一、首次生成占比改工作量口径(取代 ADR-0044 的留存行口径)**

占比 = 首轮提交变更行 ÷ 全部提交变更行;每个非合并提交的变更行 = 新增行 + 删除行(源码扩展名白名单内),**删除与新增同权,均为正向工作量**。理由:删除烂代码是实打实的交付工作——留存行口径下纯删除型修复无法评价(显示「—」被排除),删除行不记账等于宣布"删代码不算活";工作量口径让纯删除交付得到 100% 的应得评分。提交三分类(首轮/返工/平台外)与反馈事件划界机制不变,计数层从"最终差异行级 blame"换成"逐提交 numstat 按桶求和"——实现净简化,不再需要行级溯源。

代价(知情接受):同一行被改写 N 遍在分母里计 N 次,占比从"最终代码的出身构成"变为"代码运动的一次率"——指标名与达标语句相应改为工作量语义。需求侧「首次实现占比」维持留存行口径**不迁移**(历史数据都在旧口径上,且两域指标名不同,分叉可接受;后续若统一单独立题)。

**二、指标家族改名(公式即文档)**

- 一次定位率(原「一次定位成功率」)= 生成分析报告次数 = 1;
- 一次验证率(原「一次修复成功率」)= 验证不通过次数 = 0(未答卡=通过,ADR-0043)——旧名"修复"名不副实,量的是验证轴;
- 一次解决率(新增)= 报告一版过 且 验证不通过 = 0,两轴的与;
- 首次生成占比(原「一次生成占比」)与 90%AI生成达标率(原「一次生成达标率」)如上;达标线仍是参数。

会话卡徽标随迁「一次验证✓/✗」;团队DTS 的交付质量比率瓦片与特性比率列整体撤到交付分析「问题处理」页签(指挥页管推进、复盘页管质量的关注点分离),概览头留「交付统计 →」入口,过程视野与格筛选联动不动。

**三、实现与边界**

- 伴生快照升 schema v2:每提交带 adds/dels;v1 快照按缺失处理(上线当日切换,存量≈0,零迁移)。
- 返工边界应用改**按时刻**:推送时刻晚于边界事件时刻的推送,在**所有仓**一律计返工——修正 ADR-0044 按提交号匹配在多仓会话"另一个仓全算首轮"的角落。
- 执行架构(后台串行通道/异步 Git/回收让路/清扫器兜底/起算日期常量)零改动。

**曾考虑**:需求侧同步切工作量口径——否,历史数据与新现场回收使老任务不可重算;过程率加仓维度——否,会话级裁决无仓归属,多仓重复计数注水;「AI 代码内部一次率」伴随列——否,三分类数据已就位,呈现后议。

## 修订(2026-09-22):「按缺失处理」只盖了一个方向,补前端钝化(#360)

上线次日生产现身(#360,进入已归档会话详情偶现整页报错):「v1 快照按缺失处理」靠的是后端读侧拒收非 v2 快照,这只盖住**新后端 + 旧快照**一个方向。代码里还有两个没盖的方向,前端拿 v1 快照里不存在的字段(adds/dels)或旧前端拿 v2 快照里不存在的字段(lines)直接 `toLocaleString`,一崩就把整页换成报错页:

1. **部署窗口**:新静态资源已发出、旧后端进程还活着时,版本门不在,旧快照原样出网;
2. **长命标签页**:部署前就开着的页面,内存里是旧前端包(入口页每次回源也换不掉已在跑的代码),按 v1 字段读 v2 快照。

补齐只动前端,后端不动——v1 的留存行口径与 v2 的工作量口径是两个度量,数字不可换算,后端归一化等于编造,违反「宁缺勿假」。面板自验快照版本(非 2 即走「暂无统计」既有文案),行数格式化对非数字兜底显示「—」,未来任何形状漂移降级为缺字而非白屏。原拍板不变(零迁移、旧快照按缺失处理);已在内存里跑着旧包的标签页刷新前无法追溯治愈,再撞一次白页由整页报错+自动上报兜住,知情接受。
