# 登记描述 AI 润色退役:格式职责交还预填模板

2026-09-16 拍板。登记页 AI 润色(#184)整体退役:服务端一次性润色通路(`POST /issues/polish-description`、临时 models.json + ModelRuntime 组装、识图熔断门、polish/polish-template 两份提示词资产、PolishModelError 错误族)与前端确认流(润色按钮、确认弹窗、ADR-0029 挂起稿驻留与在飞接续)一并删除。描述格式化的职责由登记页预填的标准提单模板承接(见后续票):用户照着模板填,格式合规从「可选润色」变成「阻力最小路径」。

**理由**:流程不等于质量,优先评估删除机制。润色的两条增量价值都立不住——

- **格式化**:润色是可选项,测试人员不点就没有格式;模板预填让照着填成为阻力最小的路径,合规率更高,且免去确认弹窗、驻留、在飞接续一整串为「AI 产物回填」服务的前端机制(ADR-0029 随功能消亡)。
- **识图预读**:润色把截图经识图模型换文字观察注入稿件,但登记后的问题会话本有 `inspect_image` 工具,Agent 分析时自己会读图——润色等于提前替 Agent 干了一遍它自己能干的活,白白多一次模型调用与一个熔断状态。

**红线(删除的边界)**:`describeImageBytes` 是润色专属的字节直入包装,随之删除;但 visionCapability 的识图能力(探测、`inspect_image` 会话工具及其压裁/缓存/防注入纪律)不动。一键复制、截图粘贴/拖拽直传是独立功能,不随迁。

曾考虑:(a) 只砍识图保留文字润色——否,纯文字润色与模板预填职责完全重叠,保着就要继续养模型通路;(b) 润色改「可选模板插入」按钮——否,多一个入口多一份 UI,预填即零动作;模板仍可整段删掉自由书写,不损失表达自由。
