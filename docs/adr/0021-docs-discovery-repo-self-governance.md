置信度分层由提示词承载:有契约文件(即有标准句)的仓,docs/ 内容高置信;没有契约文件的仓,AI 可参考 docs/ 但置信度中等,以代码为准——无人维护 AGENTS.md 的仓,其 docs/ 质量同样无人背书,这个推断在提示词里明说。

保留不变:①团队资产库组照旧注入(进 analyze 定格,条目带 title/summary/when_to_use 检索意图与版本防漂移,条目个位数,信息密度远超 ls——砍它省不了钱,丢的是"何时读");②"引用业务事实写路径进证据链"约束保留(标准句+分析工作流取证指引双写);③analyze 阶段门控随地图一起消失,标准句经契约文件全程在场。

曾考虑"平台保底行"(无契约文件的仓由平台注入一行存在性提示),被否:用户裁定无人维护 AGENTS.md 的仓,docs/ 置信度就该降级而非平台兜底——平台兜底会掩护无人治理的 docs 继续存在,治理责任必须归位到仓主人。

代价是显性的:漏看从"不可能"(程序注入)变"概率性"(注意力依赖)——标准句埋在 16K 契约正文里,存在性靠模型注意力维持。接受此代价的依据:信息量上原地图就是一次自动 ls(AI 随时可自取),省下的每轮常驻 token 与注意力稀释,值得换;且失败自限——docs 没被发现会倒逼维护者治理,而不是平台兜着。
