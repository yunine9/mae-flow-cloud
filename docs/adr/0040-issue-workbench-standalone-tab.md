# 问题工作台独立页签:应用内入口一律新开浏览器页签,页内 overlay 退役

2026-09-18 拍板。问题工作台从「叠在问题处理页上的全屏 overlay」改为独立浏览器页签形态:应用内一切进入动作(问题列表卡、DTS 列表「进行中」徽标、团队问题两张卡)一律新开页签打开 `/issues/:id`,不再在当前页内跳转;小鲁班通知深链本就是 URL,不变。动机:经常需要同时处理多个问题,页内 overlay 一次只能开一个,切换即丢现场。`/issues/:id` 深链在此前已能完整还原工作台(SPA 兜底 + `readIssueRoute`),故这是入口行为的收拢,不是路由重建。

**理由**:多开是真实使用姿态——责任人名下常有多张在跑的单,列表卡点进 overlay 后回列表再点另一张,前一张的页签状态(左栏页签、滚动位置)全部丢失;浏览器页签是现成的多开会话容器,每个页签自带独立的历史与刷新语义。技术侧无阻碍:现场直播是 SSE(`/issues/:id/events`),每页签各挂一条,服务端无状态冲突;写动作仍经 `answer()` 单点分派,同会话双开的重复作答由服务端裁决兜底。代价:多页签各占一条 SSE 连接与 MR 检视 5s 轮询,量级可忍。

**口径**:
- **入口形态**:卡片入口由 `<button onClick>` 换成 `<a href="/issues/:id" target="_blank">`,白得中键/Ctrl+点的后台页签能力;通知深链不动。
- **登记成功后**:手工登记不再自动跳工作台(异步回调里 `window.open` 会被弹窗拦截器杀掉),成功提示里放「打开工作台」链接(登记完成即撒手,登记人本就零操作);批量发起成功后当前页跳到问题会话列表(切会话子页签),逐单入口交给列表与「进行中」徽标,不开 N 个页签。
- **overlay 退役**:IssueBoard 的 `openId` 渲染门、「正在打开问题工作台…」过渡、Esc 关 overlay 整套机制删除;工作台唯一形态是 `/issues/:id` 页面(App 在深链 URL 下把工作台渲染为页面内容)。深链读取逻辑(`readIssueRoute`/`issueRouteId`)保留——它服务 URL 直开。
- **退出语义**:工作台内 Esc/返回钮 = 本页签内 SPA 切到问题处理列表;浏览器后退按历史自然走;不依赖 `window.close()`(脚本只能关自己开出的页签,粘贴 URL 进来的关不掉)。
- **挂起转正**:当前页签内直切新会话(`pushState` 到新 `/issues/:id`)——已在工作台内,是会话内换题,不该越开越多;旧会话从列表再开新页签回看。
- **页签标题**:工作台把 `document.title` 设为单号/标题(无单用会话标题),回列表复位默认——所有页签同名则多开不可辨识,这是本改造的必要组成。
- **范围**:只改问题侧。任务工作台(`/work/:id`)是同构 overlay,是否同样页签化另议,由使用事实说话。
