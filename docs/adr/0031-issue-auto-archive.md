# 有单归档自动化:删手动归档,合入即收口

2026-09-17 拍板(#290)。有单问题会话删除手动归档:归档按钮退役,旧归档入口服务端明确拒绝;合入监听发现全部 MR merged 即自动归档,结论记 delivered。自动归档在统计与流程语义上=验证通过——环境验证卡已答 pass 的自然衔接,一直没答卡的视为认可(合入事实是外部系统边界,交付完成不以人点一次按钮为前提)。手动取消保留,取消=失败。无单会话的归档按钮在结论产出前禁用(既有 conclude 卡驱动链路不变)。

**理由**(kernel-simplification:先删机制):手动归档防不了任何具体错误,只让人在合入后多等一次点击;它还制造了第三种含糊终态——MR 没合入也能归掉,任务最终状态不可判,统计口径被迫为它打补丁。环境验证卡保留:环境里是否真的好只有用户知道,那是问用户事实的闸,不是流程尾巴;它的 fail→回退仍是环境质量问题的正式通道。

**随迁面**:守闸器「已验证待归档」排除判据改按自动归档后的状态;MR 全绿等待横幅与验证 pass 后的「待归档」人工停靠文案收敛(idle 等人点归档的停靠退役);归档通知改在自动归档时投递;CONTEXT「一仓一MR」「合入事实」「查看模式」等词条随迁。

**曾考虑**:验证卡一并退役(合入即归即视为验证)——否,那会删掉 fail→回退的正式通道,环境里发现问题只剩取消一个出口,修复轴信号丢失。
