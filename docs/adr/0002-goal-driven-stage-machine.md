# 问题流阶段机:目标驱动自报推进,平台只守两道核验(用户卡 + MR 验绿)

2026-08-28 拍板:固定流程的阶段机从"平台核实每个出口"改为"目标驱动 + AI 自报推进"。每个阶段给出目标(干什么/出口算完/可用工具),五个阶段(拉单/拉仓/修改/UT/提交MR)由 AI 判断达成后调 complete_stage 收口;三张用户决策卡(分析报告确认/无单结论/换库验证)保留,且举卡工具就是那三个阶段的唯一出口——卡即出口,没有 complete_stage 可绕。平台保留的核验只有它做得比 AI 好的两道:①用户决策(卡);②提交 MR 阶段的 MR 验绿门——AI 申报的 MR 清单必须与会话台账(create_mr 自动记账)一致,且每个 MR 最新推送 SHA 的流水线全绿,阶段转移才发生:全绿当场放行、有红当场打回进修复循环、在跑受理由监看器等绿。report_ut 降级为事实上报(只记账,不再是出口、不再是建 MR 门禁)。阶段工具白名单保留不变。

理由:此前的机械出口(拉单成功即推进、首仓落地即推进、UT 上报即推进)在"AI 自己能判断的事"上替 AI 拍板——多一道仪式,不含新信息,还多一个忘调的环节。需求交付流的对照实现是宿主全程拥有交付(prepush→push→权威流水线→裁决→await_merge,AI 从不申报);问题流选择中间态:AI 申报交付范围并对台账负全责(清单=台账,少报多报都打回,防止静默丢弃已建出去的 MR),绿的裁决权仍归宿主监看器。曾被否的两个替代:更严的"在跑也拒绝、绿了唤醒 AI 重报"——多一跳往返,无信息增益;更松的"不要求清单,平台台账全绿即放行"——AI 失去"这些仓就是本次交付物"的显式表态。
