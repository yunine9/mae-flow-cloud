# 业务知识地图:仓内 docs/ 轻量索引 + 资产库业务知识接入问题分析

2026-09-02 拍板(grill-with-docs 两轮 13 项):问题分析消费的领域
事实库,统称**业务知识**,两个来源,一张地图:

1. **仓内业务知识**:业务仓根目录 `docs/` 的目录树(可能很大,也可
   能未总结)。**渲染时现扫**——开场词/续聊词渲染 analyze 简报时扫
   文件系统,不落台账、无状态:地图不是决策,没有"已拍板"语义,不
   需要"重走不重举"判据;中途补仓(pull_repo 补)后新 docs 自然可见。
2. **团队资产库业务知识**:业务模块知识发布库(需求侧"业务模块知
   识"同一资产库)**接入问题会话**——进入 analyze 时按**当时**绑定
   的业务模块选取已发布资产,快照+只读投影 `.mae-flow-work/
   business-modules/`,清单落台账(`business_knowledge`)。定格不随
   发布库中途更新漂移,与需求侧"按任务固定版本"同一纪律;重启/续聊
   按台账渲染。模块可能在 prep_repo 才绑定(bind_module/预绑),所以
   定格锚在 analyze 入口而不是会话创建;绑定缺席=资产源静默缺席,
   补绑不追溯本轮。

两源皆空=地图整段缺席(静默);地图注入点:analyze 简报(开场词/
续聊词)+ complete_stage 进 analyze 的交接回执。正文一律**按需
Read**,不整包注入上下文——与需求侧"轻量索引+按需读取"同一口径。

## 使用位置(拍板的问题:"在哪些地方使用")

复述现象(理解业务语境,防理解错全白干)、取证循环(字段含义/流程
走向/配置语义等业务事实,支撑证据链)、报告引用(业务事实的出处写
文件路径,取证规范"每条证据带出处"的自然延伸)。**fix 阶段不设新
机制**——分析已把业务事实消化进报告,真缺 Agent 自己 Read(文件在
工作区)。

## 关键裁定

- **领域事实库,不进方法论取用次序**(ADR-0005 的替换式次序解决
  "用什么方法论定位",业务知识解决"这个业务是什么");与「业务问题
  skill」互补不互斥:skill 供排障方法论,业务知识供领域事实。
- **发现口径**:docs/ 整棵一层目录树(条目=文件与一级子目录,子目
  录折叠为 `xxx/`),不发明命名约定;多仓按仓分组;**条数上限 40**,
  超限按目录折叠并注明"按目录自查"——地图的使命是导航不是全文,爆
  上下文比缺索引更有害。
- **不分介入档**(与 skill 圈选闸 ADR-0011 的关键差异):地图不举
  卡、不停机、不等人,月光开档照常注入/定格——ADR-0011 分档的理由
  是"过程要不要停等人",地图没有"停"这个动作。
- **资产定格不分档但落台账**:定格是选材料不是举闸,但发布库资产有
  版本,中途发布不能让同一场分析看到两版事实;台账即"已定格"判据,
  重走 analyze 不重复定格。
- **只接业务知识**:文档类工程知识维持不进(通用工程方法论已经以货
  架 skill 形态经 ADR-0005 进问题会话;再接文档类工程知识是另一个
  需求)。匹配口径=会话绑定的业务模块(issueKnowledgeContext 的
  businessModuleIds)+ 登记仓过滤,复用需求侧选择器
  (selectBusinessModules:moduleIds+repositories,4 模块/60 资产/
  8MiB 限制沿用)。
- **fail-open**:模块库故障/投影失败只留一行转移账,不挡分析——知识
  旁路不能卡会话(与需求侧 materialize 容错同纪律)。
- **账本保护**:`.mae-flow-work/business-modules` 加入 GateService
  只读账本(与 host-skills 同罪:只读投影,Agent 没有写它的理由)。
- **足迹不加**(如实挂账):需求侧知识效能暂时看不到问题会话的消费。
  问题侧足迹是独立决策(要接得接 knowledgeInsights 聚合口径),不在
  本轮顺手长机制。
- **圈选卡 context 不动**:地图已在简报,卡面不再堆字。

## 与 ADR-0011 的边界

0011 的 skill 圈选是"人收敛必读的方法论"(举卡、分档、落台账判据);
本决定的业务知识是"平台给的领域事实地图"(不举卡、不分档;资产部分
落台账只为版本定格)。两者共用 analyze 入口扫描点,共享"只供知识不
定流程"的知识边界,但供给方向相反:圈选自下而上(人→AI),地图自上
而下(平台→AI)。

## 曾考虑

(a) docs/ 进方法论取用次序——稀释 ADR-0005 的替换式结构,被否;
(b) 只认约定文件(docs/业务总结.md)——约束存量仓,大多数仓被排除,
被否,整棵 docs/ 树即地图;
(c) 纯 prompt 指引(零机械扫描)——增量价值低,保证看见+省探索+体量
可控才是索引的真实价值,被否;
(d) docs 也进 skill 圈选卡人工勾——性质不对(知识地图 vs 行为契约),
文件多圈不过来,把卡撑爆,被否;
(e) docs 索引挂月光关——让月光开档的 Agent 更盲,没有"停"的动作却
分档,被否;
(f) 资产定格锚在会话创建——模块可能 prep_repo 才绑定,被否;
(g) 资产每回合现查发布库(不落台账)——中途发布让同一场分析看到两版
事实,违背"按任务固定版本",被否;
(h) 文档类工程知识一并接入——通用工程方法论已有货架 skill 供给线,
范围膨胀,被否(另立项);
(i) 本轮加消费足迹——ADR-0011 刚拍过问题侧不加,独立决策,被否。

## 落点(实现时触及)

新模块 issueFlow/businessKnowledge.ts(docs 扫描+地图渲染)、
state.ts `business_knowledge` 台账、service 定格与账本、
prompt 开场/续聊词注入(workspace 选项)、tools complete_stage 回执、
issue-analysis 技能取证清单补一条、CONTEXT.md「业务知识」词条。
