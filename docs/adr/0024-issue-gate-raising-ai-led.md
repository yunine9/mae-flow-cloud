# 举卡发起权归 AI:平台闸停代举、改工具校验制(Agent 主理收口)

2026-09-13 拍板(grill-with-docs 会话):问题流仅剩的两处平台后台代举——MR 全绿监看器的 env_verify 闸(awaitEnvVerify)与红灯监看器的 pipeline_unfixable/pipeline_evidence 闸(raisePipelineGate)——停掉。监看器降为纯发送:把事实(全绿/红灯、失败原文、产物镜像)经现有三态通道(运行中 steer/等人落便签/空闲开回合)送进会话,由 AI 在回合内经举卡工具落卡。平台保留三样:举卡工具的**前置事实校验**(可拒绝举卡,如「MR 未全绿,env_verify 不放行」;判据只查平台可复核的事实,不查 AI 口供)、**发送必达**、**计数与裁决协议**(修复轮/催办预算、决策码表、resolveGate 分派)。退的是举卡,不是验绿——全绿/红灯的事实认定仍在平台监看。

**范围**:只迁上述 3 个卡种。push_confirm/analysis_confirm/skill_select/conclude/env_needed 五张本就在 AI 回合内触发,已是终态;Skill 化包装(触发时机描述+卡面模板进 issue-skill,仅在问题流程加载)后续单独一批。

**回合语义(拍板:落卡即返回)**:举卡工具落卡即返回,回合照常收口,settle 凭闸定格 waiting_user——与部署工具三档下举 env_verify 的既有路径同款。不采用挂起等答(AskUserQuestion 同款):那会让单个回合横跨闸裁决(env_verify fail 是阶段回退),旧回合在回退后的阶段机里醒来;且回合挂起期间压缩被禁,上下文越等越重。配套单卡互斥:闸在场时 askTool 拒答、任一卡在场时 raise_card 拒举——两张卡并存自此在协议上不可能。

**漏举的闭环(策略内防线)**:回合完整性校验沿用提前收嘴机器的既有判据(未到出口即催办),预算耗尽转人工;新增**守闸器**(watchdog,纯报警不举卡):机械判据发现「应举的卡长时间缺席」(如全绿后无验证卡超 N 小时)即喊人。守闸器对人,催办对 AI。

**存量卡死(issue-53 类:答闸开回合撞上挂起 prompt)**:不修,存量单子由用户取消重发(control 对 cancel 不设忙时守卫,终态清现场;进程重启后现场重建亦可自愈)。迁移批(举卡工具+单卡互斥+监看器改发送)必须**一个原子提交**上线——代举还在、互斥未装的窗口期撞车 bug 仍活。

理由:issue-53 实锤的撞车类 bug,成因正是平台后台线程绕过活会话代举——闸与 AI 问题卡并存,作答分派闸优先,AI 卡成死卡,答闸又被挂起的 prompt 撞成双卡死。发起权交给 AI 后,举卡只能发生在活回合内,该 bug 类结构性消失。这也是 Agent 主理原则(ADR-0023 升格为项目原则)覆盖的最后一块代执领地:平台从举卡者退成校验+发送+计数+验收。红灯分诊判断(证据够不够、可不可修)从硬编码启发式移给 AI 现场判断,启发式随管线形态漂移的持续修补(票 03/81/82)不再需要。代价认账:每次举卡多一个模型回合(延迟+费用+模型故障面),约 12 个测试文件重写;共享分诊启发式(pipelineEvidence/pipelineContract)需求侧仍在用,保留不删。

曾考虑:(a) 平台保留兜底举闸(催办耗尽平台自己举)——否,拍板平台退场,以守闸器报警替代兜底;(b) 举卡挂起等答——否,见回合语义;(c) 闸等卡:AI 卡未决时监看器挂账不举、卡答完再举——否,多一套 pending 闸状态与三条补举路径,验证里程碑被无关提问押后;(d) 先落 supersede+咽喉守卫小补丁再迁移——否,存量拍板不修,迁移后该守卫失去保护对象。
