# 无单流程与 DTS 彻底解耦:确认是问题即闭环出提单模板

2026-09-21 拍板(交付分析三页签设计讨论引出)。无单流程的「挂起等转正」机制退役,确认是问题成为无单会话的终态;研究成果以提单模板文本穿过 DTS 系统到达下一个有单会话。

**一、解耦模型**

现状(退役):无单三节点 conclude=issue → 会话挂起(suspended),等责任人经 associate 关联 DTS 单号「转正」——新会话继承工作区(repo/、ref/、分析报告整树复制)直接进问题修改,旧会话归档(结论 issue,血缘 converted_from/to)。

改为:conclude=issue → 生成提单模板 + 直接闭环归档(结论「确认是问题」)。提单在平台外完成:测试把模板复制进 DTS 提单系统,新单号出现后任何人从 DTS 列表发起有单会话,完整重走五阶段(dts_info 起)。suspended 状态与 associate 端点即日退役(选项 B「保留只服务存量自然排空」被否——挂起在等一个不再产生的动作);存量挂起会话走已有的手动归档出口收口(结论按确认是问题记,自动进登记问题统计的分母)。

代价(知情接受):prep_repo + analyze 在新有单会话里重做一遍。理由:研究成果不丢——提单模板把登记元信息与分析结论带进 DTS 单据,新会话 dts_info 拉单即读到上一轮的 distilled 结论;工作区现场(repo 检出、拉过的日志)本就该按新单重拉;DTS 系统同时获得一张内容规范的真单据,平台外可见。换来的是 suspended 停泊态、associate 两段式、工作区整树复制、血缘字段、同单号防撞全部退役,无单/有单成为两个不相交的统计人群。

**二、提单模板**

按 DTS 提单系统版式排栏(与登记描述模板同款栏式:基本信息/发生时间/版本/复现概率/问题描述/触发步骤/实际现象/预期结果),登记元信息填入各栏,分析报告全文随附;末尾「参考:问题根因/修改方案」两节——标题即声明,正文附说明:初步研究未经修复验证,接单的 AI 与评审不得直接采信,以有单会话的重新分析为准。说明随单据进入 DTS,正是给新会话 dts_info 阶段的 AI 读的。模板在 conclude=issue 时自动生成(不搞按需按钮——结论出模板就该在场),存进会话目录(过程记录,永不回收),会话页与归档详情出复制卡;登记人在「我的问题」只读可见可复制——提单的人是测试(登记人),不是推进会话的责任人。

**三、登记问题统计(交付分析第三页签)**

交付分析页签变为三个:需求交付 / DTS(原「问题处理」更名,内容不变) / 登记问题(无单会话)。登记问题页签:瓦片四枚——登记总数、非问题闭环率、确认是问题率(分母=研究完成:非问题+确认是问题+取消)、一次定位率(分母=非问题+确认是问题,取消不构成一次研究);观察维度三个——按模块/按登记人/按会话,与 DTS 页签(按特性/按会话/按代码仓)同构,会话行点击下钻报告版本账与提单模板卡。本页只数结论已出的会话:研究进行中的与存量挂起一律不进,不给挂起设任何统计口径;存量挂起手动归档后按结论自然入账。零新增记账:登记与结论本就在 issue.json 转移账,报告版本在分析版本账,终态冻结 metrics.json——全历史可算,无起算日(与 ADR-0042 纯投影同架构)。

存量修正:历史转正产生的已交付会话没有 analyze 阶段、报告版本数 0,在旧规则下白捡一次定位通过;读侧在一次定位轴剔除这类会话(分子分母都剔,其余轴不动),历史比率同口径重算。解耦落地后不再产生新样本。

**曾考虑**:associate 保留到存量排空——否,见上;模板按需生成——否;平台内回填新单号保持两域关联——否,解耦要彻底,提单后的追踪在 DTS 系统自身;维持转正继承工作区以省一轮重复研究——即现行机制,废,重复研究的算力代价小于停泊态+血缘+复制的机制复杂度。
