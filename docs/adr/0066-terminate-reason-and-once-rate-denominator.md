# 主动终止按原因记入统计:负面原因进一次解决率分母记失败,「问题已处理」与无原因取消维持排除

2026-10-21 拍板(#540;实现 #541/#542,本篇文档 #544):用户主动终止(取消)问题会话时必选一个终止原因——下拉五项:问题已处理(默认)/分析不准确/速度太慢/指令不遵从/其他原因(附选填一句话说明);除「问题已处理」外的原因,其有单(带 DTS 单号发起的)会话自本次起计入一次解决率(问题端到端一次做对的占比)分母并记一次失败。「问题已处理」的取消与历史上没有原因记录的取消待遇相同:不进任何统计。原因与说明落会话状态并随终态冻结进指标快照;历史数据没有原因字段,即「无原因取消」。

**理由**:此前取消的会话既不进分子也不进分母,在统计里完全隐形。但不满的人更容易中途放弃:会话越失败,越是从统计里消失,一次解决率因此被动虚高——失败越集中的时期,虚高得越多。同时用户没有任何渠道表达「为什么终止」,平台拿不到改进线索。一次解决率要回答的是「问题端到端一次做对的比例」,中途放弃的失败会话本是它分母的应有部分;把退场原因结构化收上来,才既纠正分母,又留下改进线索。

**决策(拍板)**:
- 终止原因枚举八个稳定英文值(resolved/accidental/wrong_module/inaccurate/slow/disobedient/unclear_plan/other;2026-10-21 增补 unclear_plan=方案未明确、wrong_module=业务模块绑错、accidental=误发起),界面渲染中文,不计入统计的排除类排在下拉前段,下拉默认「问题已处理」,选「其他原因」可附选填说明。
- 负面原因(inaccurate/slow/disobedient/unclear_plan/other)终止的有单会话进一次解决率分母记失败;resolved(问题已处理)、accidental(误发起)、wrong_module(业务模块绑错)为排除类——发起失误与模块绑错重开登记即可,不是平台没把问题做对。负面码表显式列举,将来新增原因各自表态,不做「非 resolved 即负面」的隐式推导。
- 「问题已处理」取消与无原因取消(历史数据)排除:不进分子分母,不进按会话明细。
- 一次定位率、一次验证率口径不动:分母仍只含完成交付(修复完成归档)的会话——终止时刻没有完整的分析版本账与验证记录,定位、验证两轴无法判定,不虚构判定。
- 按特性、按代码仓聚合不动;无单会话维持在任何率之外(无单取消的统计待遇另见 ADR-0064,不受本篇影响)。

**连带取舍(拍板,接受的成本)**:「问题已处理」是默认项且零成本,存在逃生门效应——部分不满者会顺手套回默认退出,原因是真实的但被归入排除类;「其他原因」计失败会误伤非系统原因(如用户自身安排导致的放弃)。缓解不靠加机制,靠透明:页面环图带「用户终止」第三片与口径标注,统计口径文字与本文写明边界,后续观察原因分布再议类目调整。

**定位**:内部改进信号。它回答「流程哪里让用户半途而废」,不挂钩考核——不作为对个人或团队的评价依据。这一定位是上述逃生门与误伤两项成本能被接受的前提。

**与 ADR-0064 的关系**:收窄适用范围,不是废除。ADR-0064 拍板「取消是退场、不算研究结论、不计入登记问题统计」,该拍板对交付分析「登记问题」页签(无单会话统计)维持原样,ADR-0064 原文不改;本 ADR 只把「取消一律不进统计」的适用范围收窄到登记问题统计这一个面——有单会话的主动终止自本次起按上述规则进一次解决率统计。

**切换说明**:口径自本版(2026-10-21 上线)起生效,历史指标序列在此断点:切换前的数字按旧分母(只含完成交付)算,切换后的分母含负面终止,序列上出现的跳变是口径切换,不是质量突变。历史取消不补录原因——当时没有采集,无从补起也无须补:无原因即按排除类处理,比率投影现算,不做快照迁移、不设起算日。页面口径标注「自 2026-10-21 口径切换起」与本篇同日交代。

曾考虑:(a) 「问题已处理」也进分母记成功——否,正常的提前退出被记成「一次解决」同样失真,还会制造把默认项当成功按钮用的激励,比逃生门更坏。(b) 下拉不设默认、强制主动选择——否,牺牲「回车两秒退出」的低摩擦目标;被逼着选的人会随手点第一项,数据并不更真。(c) 给负面终止会话补判定位/验证两轴——否,终止时刻两轴的判定事实不完整,判不了就是判不了,虚构判定违背「坏账宁缺勿假」的统计纪律。(d) 历史无原因取消按「无原因=负面」回溯进分母——否,旧数据里既有不满放弃也有正常提前退出,一律记失败是无证据的指控,方向也不保守。
