# 问题流 MR 检视意见确认制:外部意见由责任人放行,AI 不自动处理

2026-09-16 拍板。问题流接入 MR 检视闭环(票 01-03)后,检视意见自动注入唤醒 AI(改码或回复),外部垃圾意见会不经人手直接驱动代码修改——且意见注入零刹车(流水线红灯有同提交刹车+修复轮预算,意见侧连轮次计数都没有,未了结意见每次修订都重新注入,无上限)。改为结构确认制:意见到达只落账+提醒,责任人逐条「AI 处理 / 忽略 / 亲自回复」或「全部处理」放行,AI 侧自动注入路径整体删除——"必须责任人点击才开始处理"不靠卡、不靠档位豁免,靠不存在自动触发路径这一事实保证。

**理由**:

- **威胁模型是内容不是成本**:要防的是垃圾意见驱动改码让代码越改越烂。预算刹车只封顶不防第一刀,耗尽前代码已被垃圾改过;"这条意见值不值得让 AI 碰代码"是只有人能做的判断,与流水线人工事实闸同类。
- **确认制的等待成本压到了最低**:责任人正常动作是一次往返——先看一遍,该忽略的忽略、该亲自回复的回复,剩下点「全部处理」一把放行;放行动作只记账,AI 在会话空闲时单回合按现有注入词处理,合法意见不因确认制多耗轮次。
- **不举闸卡**:闸单槽互斥(环境验证卡在场时意见卡举不出来要排队)、平台侧举闸要自补 waiting_user 定格、介入档位代答守卫会穿透(全自动档"人工零介入"会替人放行)。三者都是纯新增机制;小鲁班通知+工作台横幅+常驻操作区用现成件拿到同等可见性,且无闸方案里"三档保留人工"由结构自动成立,无代答面可穿透。
- **回复投递收敛公共件**:需求侧(taskService 的 review_reply 信箱)与问题侧(mr-review-outbox)两套投递语义相同、实现各自漂移——Idempotency-Key、expected_sha 绑定、重试上限、"只回复不代 resolve"各写各的,需求侧机器人刷屏事故(2026-08-30)正是这类漂移的温床。抽共享投递模块,两侧都切,落盘与触发各自保留。

**口径**:

- 动作语义(落地词表):外部意见一律先成为**待判断批注**——责任人可补充修改要求(只保存不派修)、自行答复、本地闭环、删除,或选中若干条**批量交办**给 AI(AI 自行决策改码或回复;忙时沿用插话/等收口)。交办按提交时快照取选中批次,不含后来新增的草稿。闭环判据不变:检视人在 CodeHub 点解决才 closed;自行答复经出站信箱直达远端讨论,不主张代码已改、不绑推送收据(AI 回复仍绑),复用与需求侧共用的投递原语。
- 追问与普通意见无区别:同一讨论出现新正文=新的待判断批注,重新汇总提醒;已删除、已答复、已闭环的不因追问或重新拉取复活——复用内容键去重,检视人真有新话就说,新正文即是新意见。
- 追踪窗口:意见发现停点=全部 MR 合入(合入监听已有,ADR-0022);合入后停止追踪、账保留展示,在途回复照常投完。合入前验绿收口后的意见照常处置,AI 交办走"收口后续聊返工"现成路(重开 mr_green,不算整体回退)。
- 呈现与操作面:批注面板承载待判断批注(问题流与分析报告检视同一面板家族,按每页八条展示);工作区变更签的聚合视图按仓分段呈现(服务端分段标记切片)。需求工作台不再重复显示独立的 CodeHub 长报告清单。写动作归责任人,查看模式只读(ADR-0031 同款)。
- 提醒:每五分钟汇总尚未通知的新意见走小鲁班,首次发现可立即通知;成功后持久化记账,失败下轮重试,旧意见未处理不重复提醒。
- 退役清单:检视意见自动注入整条链(待注入标志/内存集/恢复补挂/注入函数)与 repair_rounds=0 的检视分支(确认制下失去意义;流水线红灯的预算语义不动);回复投递收敛为两侧共用的共享原语(端点形状+幂等键+请求体契约),SHA 绑定与重试政策留两侧各自拍板(需求侧持票等收据,问题侧漂移即作废)。
- 需求侧与问题侧同制:两侧新意见都只入批注等交办,"不再因为讨论门禁未通过而自动开启检视修复";冲突与客观 CI 失败仍按原修复入口,实际 MR 门禁以平台结果为准。

**落地**(2026-09-16):确认制骨架(批注同步、交办、答复、五分钟汇总、自动派修退役,需求/问题两侧)由并行提交 cbe741e 落地;本票补齐共享投递原语(两侧切换)、责任人答复直达平台、合入停点与变更分段呈现,及本文档与 CONTEXT 词条口径。

曾考虑:(a) 举闸卡(决策卡家族新卡种)——单槽排队、状态定格、代答豁免三样新机制换一个横幅能给的可见性,否;(b) 注入轮次预算(把需求侧刹车搬过来)——只封顶不防垃圾驱动改码,作为唯一机制不够,否;(c) 按介入档位分档(全自动档自动处理)——与"必须责任人确认"的拍板冲突,档位语义复杂化,否;(d) 逐条勾选放行——读意见的成本省不掉只多点击,逐条三动作已覆盖粒度需求,否;(e) 在工作区变更签另建检视意见区——批注面板已是意见的呈现与处置家,两处呈现同一批意见违背一处事实一处呈现,否(变更签只补按仓分段)。
