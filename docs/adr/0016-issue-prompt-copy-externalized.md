# 问题流提示词文案外置:assets/issue-prompts 分层挂载(文案外置、结构留代码)

2026-09-03 拍板:问题流里**直接嵌进 AI 提示词的自然语言文案**,从 TS 字符串
外置为 `assets/issue-prompts/` 下的静态 md,服务加载时一次性挂载
(`src/issueFlow/promptCopy.ts`),按锚点取段、`{{var}}` 极简字符串替换。
锚点缺失/变量缺失/锚点重复一律 fail-loud(与 skills 挂载同一纪律)。

## 分层(本 ADR 的核心不是"全部外置",而是"什么该外置")

拍板过程否决了"所有自然语言一律 md"的全称命题,定为三档:

1. **文案——外置**(本目录):固定开场契约条文、转正继承注、
   开场收尾、续聊词固定段、催办词、闸门裁决后的交接词、流水线结果
   通知、环境通知、工具回执与门禁拒绝的人话。特征:完整句/段、高频
   调整、与行为只通过决策码/事件类型弱耦合。
2. **结构——留代码**:阶段简报的目标/出口/可用工具是 `stageRegistry.ts`
   阶段表的列,与工具门禁白名单同源(引导层说能用的=权威层放行的,
   构造上不可漂移)。历史实锤:简报文案写 submit_analysis、门禁却在
   别处放行——文案与结构分家正是那次漂移的根因,`exit` 文案引用工具
   名,外置等于旧病复发。同理留下的:事实块的字段标签/标题(「## 问题
   事实」、`- 标题:`)、平台通知前缀的拼装格式、闸卡推荐码。
3. **已外置/不在范围**:`assets/issue-skills/`(方法论,ADR 前已迁移);
   工具 schema 的 description(与参数共演进);举给用户的问题卡文案
   (UI 文案,不是 AI 提示词);修复派发回合的逐段拼装
   (graded/mismatch/previousFailure 等,与派发逻辑逐段耦合,锚点化
   收益低)——最后这项记为已知未迁移,若后续要动,先给派发器立段级
   锚点再迁。

## 文件按消费方分类(命名即治理)

`opening.md`(会话入口词)/ `notices.md`(平台主动通知)/
`receipts.md`(工具回执与门禁拒绝)。目录内 README 是治理规则的
single source:锚点命名 `<域>.<名>[.<变体>]`、锚点=代码协议(改名须
同 commit 改取用处)、变量只支持 `{{snake_case}}` 纯替换(无表达式/
条件/循环,需要新变量=代码与 md 同 commit)。

## 替代方案与否决理由

- **全量外置(含阶段简报)**:把注册表拆成"代码表+md 文案"两个半张
  表,重开漂移口子;ADR-0013"重启换库一天完成"的红利依赖引导层与
  门禁层同列,不容稀释。
- **模板引擎(条件/循环/继承)**:当前事件文案最多两三个变量,20 行
  自研替换值不起一个引擎;表达力上去了,改文案的人就得懂程序。
- **运行时热重载**:开场词是开局注入的,中途换文件对进行中会话无效,
  "半生效"状态比重启更难排查;启动一次性读,要新文案就重启。
- **每条文案一个文件**:40+ 锚点碎成 40+ 文件,目录即噪声;按消费方
  分三个文件、文件内锚点分节,目录可导航、diff 可读。

## 迁移与回归

首批迁移 ~45 锚点,文案**逐字搬运**(两处顺手修正:`push.no_ticket`
的叠字"请请"、`fixed.header` 里过时的"报告四要素"改"五章节")。既有
问题流测试(83 项,含大量钉文案断言)不改一行全绿——逐字迁移由测试
背书。渲染器契约测试在 `tests/issuePromptCopy.test.ts`。

需求流(taskService)的同款治理不在本次范围,待问题流形态跑稳后另立
清单(需求流嵌的文案多一个量级,不可一次做完)。
