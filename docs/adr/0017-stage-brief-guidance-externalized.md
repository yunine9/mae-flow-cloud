# 阶段简报引导语外置 briefs.md:契约句留代码拼接(ADR-0016 分层的补全)

2026-09-06 拍板:阶段简报三行(当前阶段 goal / 怎么算完 exit / 可用工具
tools)中的 **goal 自由引导部分**,从 `stageRegistry.ts` 阶段表外置为
`assets/issue-prompts/briefs.md`(锚点 `stage.<名>`);**exit 与 tools
两列留代码**。动机:goal 列混了两种性质的内容——自由引导语(高频调整:
运营想改"进入分析先调 grilling 对齐"这类节奏提示,不该改代码)与契约句
(出口条件/工具名,必须与门禁白名单同源)。ADR-0016 否决"简报全量外置"
的理由是怕拆成两个半张表重开漂移口子;本篇把**会漂移的契约句留代码、只
外置不漂移的自由引导**,渲染时由代码把契约句拼在引导语之后——防护不破,
分层变纯。

## 机制

- `stageRegistry.ts`:goal 列删除;`stageBriefLines(scenario, stage,
  guidance)` 增加引导语入参,输出三行形状不变(`当前阶段「X」: guidance`/
  `怎么算完: exit`/`可用工具: tools`)。
- `promptCopy.ts` FILES 增挂 `briefs.md`;调用方(complete_stage 回执、
  pull_repo 回执、平台交接词、催办词、开场契约)取锚点 `stage.<名>`
  传入。锚点缺失 fail-loud(与全部文案同一纪律)。
- **子 Agent 派发同日开闸**(c3936c3):analyze 引导语据此点名 grilling
  的举卡用法——引导语的第一次高频调整就发生在 md 上,验证本篇动机。

## 内容纪律(写入 briefs.md 的标准)

- 只写**方法论与节奏提示**,不复述出口条件/工具清单/产出物硬要求——
  这些在 `怎么算完`/`可用工具` 两行(代码拼接),复述=第二真相源
  (ADR-0015 对 dts-diagnose 的瘦身同理)。
- 可以点名**技能名**(vendor 或平台技能),那是取用指引不是门禁。
- 场景差异(有单/无单)写在句内条件(如"确认无需代码改动可跳过"),
  不为变体单开锚点。

## 与既定决定的边界

- **ADR-0016 不翻案,补全分层**:文案/结构两档照旧;本篇只是把 goal 列
  从"结构"重新归类为"文案",依据是它可拆——契约句拆出来留代码后,
  剩余部分满足 0016 的外置判据(完整句段、高频调整、弱耦合)。
- **出口/工具列不外置**:0016 的历史实锤(简报说 submit_analysis、
  门禁放行别处)恰恰发生在这两列;同源是防漂移的本体。
