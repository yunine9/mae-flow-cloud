# 问题流分析结论闸的月光代答:推荐码首次被消费为自动作答依据

2026-08-31 拍板:问题流接入个人设置「人工介入程度」的月光轴(moonlight,过程人工节点由系统代答),现读现判。月光开着时,固定流程的分析结论闸由系统代答——有单 analysis_confirm 全量自动确认;无单 conclude 仅提案 non_issue 且自报置信度高才自动闭环归档,其余(是问题/置信度不足)必举卡。代答走 answer() 同一裁决通道,现场账标注「月光免审批自动确认」,notifyOutcome 通知归属人,事后可经现有回退机制推翻。env_needed/env_verify 问的是用户的事实(环境配置/验证结果),与需求流"开放题退回人"同则,永不代答;MR 验绿门不动。

理由:ADR-0004 说"推荐是将来无审批全自动模式的执行依据"——analysis_confirm 的推荐码在码表里定死 confirm,这是它第一次被机器消费。有单报告确认后还有 UT、MR 验绿、环境验证三道闸兜底,自动确认的风险下游接得住;无单闭环没有下游,闭合即终局,所以保留分级(非问题+高置信才自动)。置信度来自 submit_analysis 的结构化自报字段,缺省视为不足——宁人工勿猜,与代答"认不出不猜"同则。

过程行为同步分层:提问密度与中间简报由开场词/续聊词按月光现值渲染「介入节奏」(月光档少问、不中间简报、报告写到无需补充即可执行的自足);GateService 既有的月光"禁问"分支不接问题流——它会连"真缺信息问一句"一起禁掉。本轮只覆盖固定流程;自由模式不变,push_confirmation 轴(交付过目)属 MR 交付范畴不在其列。

曾考虑:(a) 有单也按"轻量路径+高置信"分级——被否,有单下游有三道闸兜底,分级收益不抵协议复杂度(需再加 path_type 自报);(b) 平台从报告「置信度」章节解析文本判级——被否,报告措辞一变就失灵,结构化自报才是可审计的判据;(c) create 时烙印介入档——被否,与需求流"每张卡到达时现读"口径冲突,用户改设置应即刻生效。

## 扩展(2026-08-31 拍板):代答口径从平台闸扩至 Agent 问答卡

月光的代答范围从平台闸延伸到 Agent 自举的 AskUserQuestion 卡:一张卡上所有题都是选项题且每题都带 recommended(ADR-0004 的「AI 推荐」,校验层已强制选项题必带、逐字命中)时,每题按推荐项的决策码整卡代答。推荐项由此从「标注」升格为「可代答的审计依据」——被自动作答的答案就是卡上标了推荐的那项,「AI 推荐」徽标与代答行为同源,没有暗箱。

整卡纪律:含开放题(无 options)或 recommended 缺失/不命中(理论上被机械校验拦住,此条是历史卡的防身)整卡等人,不做半卡代答——机器只复述 AI 明示的推荐,不替人拼凑方案;开放题与 env 闸同则,要用户自己给的事实与文本,永不代。检视回合(review_active)的 Agent 卡整段跳过——ADR-0007 口径的延伸:检视回合的卡是"意见是否被吸收"的复核点,代答等于架空检视闭环。平台闸优先不变:盘上有平台闸走闸代答,轮不到 Agent 卡,两者互斥不重复作答。

作答与闸代答同款:走 answer() 同一通道(状态版本先到生效、决策码还原选项原文入账、续跑、事后可经现有回退推翻),defer 到回合收口之后,失败旁路 fail-open 卡留待人;留痕落 notes(「月光免审批自动作答(推荐项:…)」——decision 位被码还原的选项原文占用,与真人页面作答同形,notes 是过程问答与现场导出都投影的留痕位);notifyOutcome 通知照发。现读现判:只在卡落地的 settle 时刻判定一次,已挂起的卡不追溯代答,月光中途打开对存量卡无效。自由模式同享:自由模式没有平台闸,Agent 卡代答是月光在自由模式唯一的硬牙齿,两个模式走同一条代答路径,不分支。

曾考虑:(a) 半卡代答(选项题按推荐答、开放题留人)——被否,拼凑出的答案会以"整卡已答"的假象续跑,AI 自己都没把握的问题不该有机器版的半个方案;(b) 留痕写进 decision——被否,decision 由 answers 的码还原结果占用,动它就要偏离真人作答的入账形状,notes 是同一次入账里唯一空着的留痕位;(c) 挂起卡在设置翻转后追溯代答——被否,与需求流同口径,代答只发生在卡到达的那一刻,事后不补。
