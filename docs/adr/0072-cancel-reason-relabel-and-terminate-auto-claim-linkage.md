# 终止原因「误发起」更名「无需处理」:协议值不动;完结原因终止联动自动接单排除

2026-11-03 拍板(与用户逐轮拷问定稿,当日实现):两件事一批落地。(1) 终止原因词表八项中的「误发起」(协议值 `accidental`)界面更名「无需处理」——协议值、码表顺序、统计口径一字不动。(2) 终止联动:会话以「问题已处理」或「无需处理」终止时,服务端自动把该单标进自动接单单级排除(ADR-0070);其余终止原因、无单会话、无原因取消不联动。

**理由**:误发起是低频概念,与「业务模块绑错」(登记错误大类)语义重叠,真手滑建错单的人选「无需处理」或「业务模块绑错」都够用;「无需处理」补上的是「问题是真的但不用做」这个更常见的退场语义。联动的真正靶子是 ADR-0070 开篇记录的实测循环:取消后去重闸只拦非终态会话,只要 DTS 状态还停在「开发人员实施修改」,下一拍定时扫描就把单**重新接走**、开出全新会话。单级排除本是这个循环的手动逃生门(还得用户自己去 DTS 列表标);而用户终止时选完结原因,正是亲口断言「这张单不再需要处理」的时刻——把逃生门自动化到这个时刻,时机零误差。

**决策(拍板)**:

- **更名只动文案**:`accidental` 的界面中文自 2026-11-03 起显示「无需处理」;协议值、`ISSUE_CANCEL_REASONS` 码表、负面码表(`ISSUE_NEGATIVE_CANCEL_REASONS` 不含 accidental,维持排除类)、一次解决率口径全部不动。历史数据零影响:盘上存的一直是英文协议值,中文只在前端词表一处;且 accidental 从不出现在统计页(服务端只下发负面原因行)与会话工作台(不渲染 cancel_reason),连历史语义歪曲的可见面都没有。误发起概念退役,下拉仍八项。CONTEXT.md 相关词条同步改写,ADR-0066 原文不改(历史拍板留档)。
- **联动规则——只联动「断言这张单不再需要处理」的原因**:即「问题已处理」「无需处理」两项。「业务模块绑错」不联动(单子还要做,只是换模块重开,绑定修好后自动接单接得对);负面原因(分析不准确/速度太慢/指令不遵从/方案未明确/其他原因)不联动(单子还要做,自动重试正是自动接单存在的意义)。无单会话没有可排除的对象,天然跳过。
- **无条件写,幂等**:有单即写,不看责任人当前是否开着个人自动接单开关——排除是对将来开开关的保险(今天关着,半年后打开,扫描器不会把名下早已处理完、DTS 状态却没流转的单一网打尽)。已排除的单重复写是幂等覆盖,无副作用。写入走服务端 `control` 取消收口内联(存储层直调,不绕 HTTP),操作人取归属账号——路由本就只允许归属人取消,归属人即操作人。终态已落盘后联动失败**不回滚取消**,只记日志:取消是不可逆主动作,不能因为伴生标记写失败就谎报「取消未完成」。
- **提示——事前,不做事后二次弹窗**:终止确认框内当选中原因属完结类、会话有单号、该单当前未被排除时,显示一行后果说明(文案拍板:「终止后将同时把该单的自动接单改为「排除」，见DTS列表自动接单列」)。已排除的单不显示(「将改为」对已排除者是误导噪音)。按下确认前已知情,零额外点击——ADR-0066 明确捍卫过「回车两秒退出」的低摩擦,二次弹窗(决定已不可逆还多点一次)与勾选框(绝大多数场景都该勾着的选项=纯摩擦)都不做。

**连带取舍(拍板,接受的成本)**:默认项逃生门叠加——「问题已处理」是下拉默认项,ADR-0066 已承认存在懒人回车两键顺手套默认退出的效应;现在懒退出也会顺手关掉这张单的自动接单,用户可能几周后疑惑「我的单怎么不被自动接了」。接受的理由与 ADR-0066 同源:缓解不靠加机制,靠透明(事前提示 + DTS 列表随时改回「允许」,选即存);且被懒退出关掉重试的损失,要用「忠实退场者的单被反复复活」的更大损失来换,方向不划算。另外注意 DTS 列表「自动接单」列默认隐藏,提示文案指路到列名,用户需先在列显隐里打开该列——按既有列显隐记忆机制,一次性动作。

**曾考虑**:(a) 新增协议值 `no_action_needed`、accidental 保留兼容旧数据但不进下拉——否,协议值从不示人(界面只见中文),改值是纯成本零收益,还留下长期双值维护;(b) 协议值改名并迁移历史 issue.json/metrics.json——否,metrics.json 是终态冻结快照,重写违背冻结纪律;(c) 保留「误发起」变九项——否,低频概念占下拉位,「无需处理」+「业务模块绑错」已覆盖其场景;(d) 负面原因也联动(用户气得终止,半小时后又被复活,体验更糟)——否,那等于替用户关掉他自己打开的自动接单,且抹掉自动重试这个自动接单的核心价值;复活体验问题是另一个话题,有痛点再议;(e) 仅个人开关开启时写——否,留下将来开开关的敞口,且「有时联动有时不联动」的行为不可预测;(f) 事后二次弹窗确认属性变更——否,决定已不可逆、纯告知还多点一次;(g) 确认框加「同时排除自动接单」勾选框——否,破坏回车两秒退出的低摩擦,几乎恒选的选项是摩擦不是控制。

**验收(实现期)**:定向测试——文案断言更新(误发起→无需处理);联动服务端契约(完结原因×有单→排除表落条目含操作人、负面原因不写、无单不写、幂等);提示行 UI 契约(条件渲染与文案、两入口传参);镜像字段 `auto_claim_excluded` 过线;根 typecheck。不跑全量(AGENTS.md 测试纪律)。可见控件新增走 1920×1080 截图走查。
