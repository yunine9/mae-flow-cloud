# 交付分析

页面保留“交付代码行数”“首次实现占比”和代码来源分布，总览、任务表及详情均不再展示“累计修改行数”。

入口为侧栏“交付分析”，代码改动页也提供当前任务入口。需求数据已接入；问题处理保留入口，暂不参与需求统计。

## 数字口径

- **交付代码行数与来源**：合入的源版本相对合入前目标分支共同祖先的 diff 中，新增及修改后的文本行。逐行使用 Git blame 查最后修改提交；首次实现占比 = 其中源自首轮实现的行数 / 全部最终新增及修改行数。不是“首次提交有多少没被删”的留存率，也不是编译通过率。
- **首次实现**：优先以首次实际修复区间为界，区间起点及之前的任务提交均计首轮实现。没有修复区间记录时，以首条明确提及检视反馈或流水线修复的提交为界；没有明确迹象则暂计全部为首轮实现并标注推断。配置和文档先提交不影响后续主体实现归入首轮；只收到但尚未处理的反馈不形成分界。顺序使用 Git 第一父链，不按提交时间排序。
- **内部提交增删记录（页面不再展示累计修改指标）**：首轮实现之后，非合并提交的代码新增行数 + 删除行数。改一行计两行，多次修改重复计数。此值和最终代码分母不同。纯重命名为零。合并提交中的冲突解决暂不计入返工，避免把引入的上游变化当成返工。
- **分类**：首轮实现单列；进入修复后的提交有流水线反馈、CI 修复轮次或提交说明中明确的 CodeCheck、编译失败、覆盖率修复等线索，就归流水线修复；其余全部归检视意见修改。没有“其他”“混合”“未归因”。已有历史区间和推送记录继续作为识别依据，提交说明作为补充；两类线索并存时流水线优先。旧统计中的其他项自动并入检视修改。
- **口径**：检视意见修改是非首轮实现、非明确流水线修复的剩余修改，不代表每个提交都有一条真实人工意见。提交明细保留分类依据，推断与平台记录可区分。代码行数仍由 Git 计算。

- **范围**：统计 Git 跟踪的交付文本，包含源码、测试、脚本、JSON/YAML/XML/INI 等配置、无扩展名文件及锁文件。排除 Markdown（md/markdown/mdx）、Git 判定的二进制、常见依赖和构建产物目录、明显生成文件及 `.mae-flow` 平台运行文件。纯配置需求正常统计，修改配置与修改代码采用同一行数和归因算法。删除行另计，不装进交付行数。
- **团队汇总**：仅纳入已完成且 MR 已合入、最终源 SHA 与采集快照一致的任务。按行数加权，不平均各任务百分比。主任务显示“子任务汇总”，指标聚合当前筛选范围内的子任务，状态显示已合入子任务数（含未合入数据时标为暂计），不表示主任务自身交付代码；团队汇总仅计实际交付任务一次，未拆分且直接交付的任务正常展示。时间按合入完成时间。squash / rebase 合入产生的目标 SHA 无需等于源 SHA；统计的是已确认推送的源版本，不将合入提交当作源版本，也不代表 squash 时额外修改的目标代码。

## 取证和运行

宿主确认推送事实后调用 `recordDeliveryPublication`，先在统计文件保存当轮起点、终点及来源，再异步调用 `observeDeliveryCode`。统计失败不会丢失已记录轮次；重启后页面采集可使用所有保存区间重算。历史任务可从现存 `.mae-flow.json` 的反馈批次补算，仅读取，不调用内核或增加流程判定。所有统计读 Git 都异步执行、全局单工作槽、单任务有提交数/文件数/输出/时间预算，不 fetch、不改工作树、不参与任何推进/审批/合入判断。恢复记录和页面读取也能触发缺失快照采集；失败不会重派 Agent。修复证据、内核现场文件变化或旧版缓存会自动触发更新；页面“刷新数据”可重算已有快照及重试失败的取证。同一源版本重算保留合入前基线，避免目标分支推进后把已有数字清空。工作区已回收时保留已有数字，但无法重新归因。

快照原子保存在任务目录旁 `.delivery-analysis/<任务与工作区哈希>.json`，不在 Agent 挂载目录内；采集失败保留上一份快照用于后续历史追踪，但不同版本的旧数字不会展示成当前结果。备份任务数据时需一起备份该目录。工作区回收不删除统计快照。

历史任务若没有合入前快照，且本地目标已经包含源提交，则使用任务创建基线补算交付差异；这可能包含期间吸收的上游变化，作为近似比例展示。存在外来提交不再拒绝统计。责任人直接推送的分支版本若就是最终合入版本且承接平台推送，则纳入统计，其增量按后续修改分类。Git 对象缺失或超过预算等确实无法计算的情况才显示原因。历史原因记录缺失会降低分类覆盖，缺失部分使用有明确线索的规则推断，不调用模型。

接口 `GET /delivery-analytics` 与团队任务使用同一登录可见范围；普通成员可读。`?refresh=1` 重新触发后台采集，请求本身不等待 Git。前端展示覆盖任务数，未知不是零。

## 交付改进报告

每次交付详情标题旁的小图标可以分析原因或查看报告。已有交付由责任人或管理员手动启动；部署此能力后新完成且已合入的交付默认自动分析。自动设置收在交付分析页的“自动交付分析”中，管理员可以关闭或调整阈值：100% 表示全部，低于100%时只分析有统计且首次实现占比严格低于阈值的交付。启用时间保存在数据目录的 `delivery-improvement-policy.json`，不会因开启功能补跑所有历史任务。失败不自动重复调用模型，保留上次报告并提供重试。

分析实际使用 [delivery-improvement skill](../skills/delivery-improvement/SKILL.md) 和其中的报告模板。三个只读子会话并行检查需求与业务知识、编码与验证、流程与协作，主会话回查原始证据后综合。一个任务分析期间最多三个并行维度会话；不同任务的分析排队运行。子会话失败会在主报告的覆盖限制中说明。分析只发布报告，不修改业务代码、知识、任务状态或交付决定，不执行构建或平台操作。

工具开放任务全过程、历史交付、父子/兄弟与上游依赖任务的文本材料，以及当前平台和内核源码；图片在已配置视觉模型时可只读分析。Git读取限定任务冻结的提交范围，支持中间提交、合并相对第一父提交的变化和指定版本源码。凭据目录及文件、链接越界和二进制文本读取不开放。资料按目录搜索及分段读取；搜索有预算，未命中不等于资料不存在。实际读取的脱敏文本保存在本次报告旁，报告中的证据引用可以点开核对，不会临时读取任意宿主路径。

任务目录下 `delivery-improvement/<交付标识哈希>/` 保存状态、每次分析的范围和指令快照、各维度报告、最终报告及已读取证据。分析前保存逐提交diff、基线/最终的变更文件及按需读取的源码缓存；64MiB预存预算耗尽时注明未保存范围。代码已回收的任务仍能读取已有统计、任务材料及此前代码缓存，没有保存的Git对象明确标缺失。报告生成不因缺失代码冒充完整分析。

新创建会话会在相应事件目录的 `analysis-context/` 保存创建时的有效系统提示、已加载规则正文与摘要、工具定义及公开模型标识；观测失败不会影响执行。这不是每轮压缩或动态扩展后的完整模型上下文。当前源码与checkout HEAD也不能直接证明历史进程运行版本；普通历史命令未绑定代码版本、未提交修改、旧知识缺失等仍作为报告限制，不补造事实。

接口：`GET/POST /tasks/:id/delivery-improvement?delivery_id=initial` 查看/启动指定交付分析；`GET /tasks/:id/delivery-improvement/evidence?delivery_id=...&ref=...` 读取该报告实际引用的证据；`PUT /delivery-analytics/improvement-policy` 由管理员保存 `{enabled, threshold_percent}`。报告读取沿用任务登录可见范围，启动沿用责任人/管理员权限，分析Agent的读取能力不扩大人的操作权限。

## 本地验证

```bash
npx tsx --test tests/deliveryAnalytics.test.ts
npm run gate
npx tsx scripts/seed-delivery-analysis-demo.ts
MAE_FLOW_UI_FIXTURE_MODE=1 npx tsx src/serve.ts --data .e2e-fixtures/delivery-analysis --port 8851
```

演示脚本只创建不存在的本地专用目录，包含真实 Git 首次提交、CI 修复、人工检视修改、未归因修改及缺证据任务，直接调用正式统计器。打开 `http://127.0.0.1:8851/?deliveryAnalysis=1`，本地演示账号 `admin / mae-flow-demo`。不要将演示账号用于正式服务。

旧版按单个 commit 计算的快照会自动重算；现场已回收而无法重新取证时，显示待重新采集，不把旧数字冒充首次实现占比。

## 需求所属业务模块与分布

创建需求时必须单选配置中心的业务模块；暂无模块时先到配置中心创建。父任务工作台顶部仍可修改归属或补全历史需求。所有已登录团队成员可编辑，历史记录保存修改前后模块、修改人和时间；修改不改变任务的知识快照或开发流程。子任务不单独填写，统计沿父任务链找到根需求，只使用根需求的单一归属。未拆分需求使用自身归属，历史未绑定显示“未关联模块”。

业务模块交付占比 = 模块已合入需求的交付代码行数 / 当前时间、代码仓和搜索范围内全部已合入交付代码行数。未关联模块也计入分母。按实际交付子任务汇总，父任务不再重复贡献行数；模块改名按配置中心当前名称展示，归档模块的历史归属保留。点击模块条形图筛选下方需求及左侧来源，右侧分布保持整体分母便于对比。
