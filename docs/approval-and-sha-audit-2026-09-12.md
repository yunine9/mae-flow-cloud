# 人工确认与 SHA 使用审查

基于 Cloud `0a85e1a` 审查随仓内核的 SHA、sha256、digest、fingerprint 使用点，并沿调用链检查 Cloud 推送、流水线裁决、收据登记和恢复。这里只记录代码策略与回归场景，不要求内网 Agent 编写脚本、修改源码或重配 adapter.json。

## 同类问题统一处理

| 场景 | 处理 |
|---|---|
| Spec、Story、代码检视的内容指纹变动 | 删除指纹生成、回答盖章/过滤、done 拒绝及 Cloud 自动补卡；真实回答按当前步骤读取 |
| 重新展示配置单或需求文件补充 | 删除配置摘要比对与回答指纹绑定；保留完整配置校验、真实确认、拒绝优先和单项回答隔离 |
| 暂存、提交、补登记清单、会话恢复 | 沿用原决定；Agent 说明实质变化，按用户授权继续，超出授权或业务歧义才提问 |
| Cloud 最终推送同一文件集合产生新 SHA | 不再因 SHA 变动重新确认；确认记录保留原 SHA，不伪造用户看过新版本 |
| 宿主同步远端导致提交 SHA 改变 | 沿用本次确认，仍检查明确排除的文件；排队后任意本地换 HEAD 属于待传输请求变更，仍拒绝错推 |
| 人正在查看 Diff 时出现新提交 | 阅读入口展示当前代码，不因 SHA 变化失效、要求另开确认卡 |
| 升级前已生成 kernel-review 重复卡 | 撤下该内部卡并恢复任务，不伪造肯定回答；普通问题、明确拒绝和暂停不自动放行；迁移中断可重放 |

文件清单仍代表用户的实际选择，新增/移除范围与明确“先调整”保留现有处理。流程元数据 `approval_subject.kind/artifacts` 只用于选择检视视图和展示材料，不再生成内容指纹。

## 保留的 SHA 及误用排查

| 用途、主要实现 | 结论与场景 |
|---|---|
| Git 传输：hostPush、taskHostTools、pipeline push receipt | 保留实际请求/远端提交核验和原子 ref 更新。网络重试复用收据，恢复不重复传输；宿主自身同步远端不作废确认 |
| 流水线：quality/external_verification、pipeline_commands、pipelineHandoff | 保留精确提交核验。旧绿不能核销新代码，缺失/无效结果不变绿；新结果接棒后旧流水线意见成为历史，不重派 |
| 过期红灯裁决：TaskService.pipelineVerdict、deliveryRecovery | **发现并修复**：旧红灯曾忽略内核 STALE，继续派修旧错误；现与旧绿走同一重验路径。重试定时器也允许 STALE+failed，避免修完判定却仍卡住 |
| 异步返回 | 核销返回后再次核对执行权和当前推送 SHA，迟到结果不能推进新版本 |
| 本地构建/UT：prePushVerification、application/hooks/receipts | 保留实际执行输入、任务卡和源码快照身份。相同提交重试保留结果；宿主证明 tree 相同的提交说明重写可迁移 PASS；代码变化仍须真实验证，不靠人工确认伪造成功 |
| 反馈收据：host_receipts、published_feedback | 保留签名/摘要及结果版本。结果 HEAD 与后续发布 HEAD 分别记账；发布不改写历史 result_head/result_digest，重启可补投影，不能让 Agent 伪造权威收据 |
| 独立 UT/CodeCheck 范围确认 | scope_sha 是创建该独立操作时的固定身份，后续提交不重新计算、不自动换卡；阻止别的独立操作回答串用。保留 |
| 风险豁免、危险命令许可 | 绑定特定风险/命令/步骤，不能泛化为未来所有操作授权；质量证据异常仍按既有提示策略呈现。保留 |
| 原文、执行日志、任务卡、归档与初始脏文件 | 用于完整性、重复执行识别、旧产物缓存和区分用户原有改动，不用于作废普通审批。保留 |
| 能力包、镜像、状态签名、面板快照 | 用于版本、缓存或可信来源身份，不是人工确认条件。保留 |

本地 Build-Fix 沿用已有产品策略：成功执行后又改动代码会如实提示，不作为最终质量通过证明；最终质量仍由对应提交的权威流水线核销。代码同 tree 并不代表远端流水线可以直接冒用另一 SHA 的结果。

## 场景回归

- 真 CloudSession + KernelHost + Python CLI：第一次确认直接推进；带“小鲁班手机审批”备注不拒绝；先调整不推进。
- 真 CLI：遗留指纹、文件变化、普通提交、清单登记、旧 approval_request、无指纹状态。
- 配置：重新展示/补充需求不重复确认，最新拒绝仍覆盖旧肯定，单项回答不能给完整配置背书。
- 真 Git + HTTP 流水线：旧 success/failed 且 HEAD 已前进，两者均由宿主推送新 HEAD 并验证，期间不追加模型请求。
- 同 SHA 网络重试、两次部署恢复、提交说明 tree 等价迁移、旧收据与新发布 SHA 分离、迟到回调、真实已排除文件。

本地回归不等于内网部署完成。更新 Cloud 时一并使用随版本发布的 kernel 快照；本次不新增 adapter 配置要求。

全内核 selftest 的唯一失败是已有体积约束：`cli_commands/delivery_commands.py` 在修改前后均为 572 行，超过 500 行上限；本次未改该文件或放宽规则。其他 selftest 检查通过。此项不属于本次审批/SHA 回归，保留原失败供后续独立处理。
