# 配置中心

所有已登录团队成员都可以维护配置中心的全部内容，无需管理员或模块 Owner 授权。

- **环境管理**：沿用现有 IP、端口、形态、密码和标签台账，支持新增、编辑、删除和探活。密码仍加密存储且不回显。
- **版本与分支**：团队统一维护产品版本与 Git 分支的一对一映射，不区分代码仓。名称不能重复，分支必须是合法 Git 分支名。新部署为空目录，不预填虚构的产品映射。
- **模块与代码仓**：维护模块及其关联仓库清单；多个仓库以标签概览，完整清单在居中弹窗中搜索。模块可归档、重新启用，知识和历史任务保留。

三个页签独立搜索和分页，不把全部配置堆成长页面。地址为 `/configuration`，可用 `?tab=versions` 或 `?tab=modules` 直达。原 `/environments` 链接继续有效。

## 使用配置

需求发起、手工问题登记和 DTS 批量发起共用版本目录。选择产品版本后，由服务端按配置中心解析分支并保存进任务；浏览器传来的分支不能覆盖所选版本的映射。DTS 未显式选择版本时，仅用单据版本与目录做精确匹配，不猜测相似版本。

已有任务使用创建时的分支与模块/环境快照，不随配置修改或删除漂移。旧客户端未传版本时继续兼容原基线；版本目录尚未建立时，需求仍可按原方式填写基线。显式选了已删除的版本时提示刷新选择，不静默切到默认分支。

模块目录仍由原 `/business-modules` 提供，环境台账仍由 `/environments` 提供，避免迁移造成双份配置。新增 `/product-versions` 提供版本映射 CRUD，持久化在数据目录的 `product-versions.json`。

知识在**团队资产**上传与维护，选择配置中心的模块作为范围。模块知识发布、修改、归档均向全体成员开放。历史 Owner 字段只作为旧数据兼容，不再决定谁能维护模块和模块知识。
