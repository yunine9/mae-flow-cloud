# 小鲁班通知文案模板(部署级配置)

三类小鲁班通知的**正文**可以用 `{占位符}` 模板自定义:待办通知
(waiting)、收口通知(outcome)、检视邀请(review)。不配置就是内置
默认文案,行为与引入模板机制之前一字不差——模板是给部署改口吻、
加前缀(如值班群规范)用的,不是必填项。

## 配置方法

旗标或 `--config` JSON 文件(键 = flag 名去掉 `--`,两种写法等价,
命令行压过文件):

```bash
npm run serve -- --luban http://127.0.0.1:8791 \
  --luban-template-waiting '【值班】{subject} 等人:{link}'
```

多行文案写进 serve.json:JSON 字符串里的 `\n` 是真实换行;shell
引号里的 `\n` 只是两个字符,**不会**被翻译成换行(刻意不做这种
隐式转义——所见即所得),要换行就走配置文件:

```json
{
  "luban": "http://127.0.0.1:8791",
  "luban-template-outcome": "任务 {task_id} 已 {status}\n{summary}\n详情:{link}",
  "luban-template-review": "{sender_account} 邀 {account} 检视 {task_id}\n{summary}\n{link}"
}
```

三个键互相独立,配哪个改哪个;没配的类别继续用默认文案。

## 占位符词汇表

占位符语法:`{字母数字下划线}`(同交付平台适配层 `adapter.json` 的
`{repo}` 系,两处写法一致)。**词汇表按类别白名单**——模板里出现
表外名字(包括别的类别才有的名字)就是配置错误,服务拒绝启动并在
报错里列出该类别全部可用占位符,不会带着 `{task_i}` 这种原文投出去。

### waiting(待办通知:任务等你决定)

| 占位符 | 含义 |
|---|---|
| `{task_id}` | 任务号,如 `T-17` |
| `{subject}` | 面向人的任务称呼(标题或需求原话);缺席时回落 `任务 {task_id}` 的成品文案,不会渲染成空 |
| `{step}` | 内核步骤原名(如 `delivery_review`),排障用 |
| `{stage}` | 步骤的人话名(如 `交付确认`),给业务用户看 |
| `{summary}` | 问题与被确认内容的定稿块(含选项列表;超长按 2400 字符截断并注明) |
| `{account}` | 收件人小鲁班账号 |
| `{link}` | 直达任务工作台的审批深链 |

### outcome(收口通知:完成/交付/失败)

| 占位符 | 含义 |
|---|---|
| `{task_id}` | 任务号 |
| `{status}` | 收口状态(`completed` / `await_merge` / `verifying` / `failed`) |
| `{summary}` | 说人话的收口摘要(失败时含原因或"原因见任务页") |
| `{account}` | 收件人账号(任务归属人) |
| `{link}` | 任务页链接 |

### review(检视邀请:责任人主动请 Committer 看)

| 占位符 | 含义 |
|---|---|
| `{task_id}` | 任务号 |
| `{summary}` | 邀请摘要 |
| `{account}` | 被邀请人账号 |
| `{sender_account}` | 发起邀请的责任人账号 |
| `{link}` | 任务页链接 |

## 边界:哪些内容不归模板管

以下内容由代码固定追加,**模板删不掉**:

- **`/mfc` 激活提示**:每条消息必须说明"手机端先输入 /mfc 激活插件,
  否则直接回复不会进入 Mae-Flow"——这是已验收的诚实承诺(README
  「内网能力模拟件」节),交给配置等于允许被不小心删掉。
- **手机审批指令与审批码**:是否提示"可直接回复序号"取决于
  `--luban-plugin-replies` 的部署验收状态与当张待办的上下文完整性,
  判定在代码里,模板无法越权承诺。

## 校验与失败语义

- 配错(表外/跨类别占位符)在启动时点名拒绝——部署配置语义,同
  `serve --config` 文件坏了拒启。错模板一次也别投出去。
- 通知**运行期**仍是旁路 fail-open:投递失败退避重试、不改流程状态,
  与模板无关(主 spec §14.4)。
- 占位符在渲染点永远有值(subject/link 等都有回落),不存在"渲染出
  一半"的通知。

## 默认文案(等价于不配置)

```
waiting: 【Mae-Flow】{subject} 等你决定
         阶段:{stage}
         {summary}
outcome: 【Mae-Flow】{summary}
         任务 {task_id}
review:  【Mae-Flow】任务 {task_id} 邀请你检视:{summary}
```

语义契约(幂等、退避、不阻塞流程)写在 `tests/notifier.test.ts`,
改模板实现时以测试为准。
