# 流程阻塞审计（2026-09-08）

本轮发现并修复了会话生命周期与首编异常恢复问题。代码检查和本地回归不能证明内网业务全链路已通过，尤其不能替代 FarsService 真实首编验收。

## 本轮修复

| 严重性 | 触发条件与原行为 | 修复后的行为 |
| --- | --- | --- |
| P1 | 需求修订、基线预热各自创建独立 CloudSession；取消任务或关闭服务只处理主会话，独立会话继续占模型资源，迟到结果可能写回旧状态 | 按任务登记辅助会话，取消、暂停、关停统一中止；异步创建期间发生取消的会话不能再启动；关停后不落迟到 Token 状态 |
| P1 | 预热尚未结束就进入 Build-Fix；旧预热仍可经 activeTaskContainer 重开编码容器，与 Build-Fix 争用工作区 | 切换构建前中止辅助会话，等待已发起的容器重建落定，再回收编码容器；失效预热不能再执行 Bash 或补交报告 |
| P1 | 问题单关停未失效主回合，取消未等待主会话 abort，独立预热也未中止 | 关停停止调度并使旧回合失效；取消/关停等待会话中止并保留清理失败原因；迟到的模型结果不能把终态改回 idle/failed 或继续催办 |
| P1 | 首编脚本创建锁目录后、写 owner.json 前退出；下次一直把空锁当作活构建 | 完整写好 owner.json 后原子发布锁；旧空锁可恢复；有效活进程锁继续互斥。非空损坏锁给出明确恢复指引，不冒充“正在执行” |
| P2 | 预热中断或服务重启后，旧 running 收据永久显示编译中 | 标记为基础设施中断，明确“基线是否编译通过尚未确认”，不伪造编译失败或成功 |

这些修复没有添加需求检视整轮计时器，也没有放开宿主编译回退。首编锁仍依赖平台的单任务容器所有权约束，不是跨机器共享工作区的分布式锁；非空锁元数据损坏时不能自动猜测持有者已退出。

## 横向核对

- 需求预检：批次串行，失败只恢复本批意见；排队及修订没有整轮五分钟计时。取消后的邀请关闭、迟到通知不会复活邀请。
- 检视队列随辅助会话一同失效：关停后的旧队列不能改批注账或回调失败通知；暂停/取消保留未完成意见；恢复后的新队列不会被旧轮收尾解除串行锁。
- 需求修改：重启恢复中断修订，长文原位修改及多人检视后作者复核行为保留。
- 会话恢复：已回答问题回放、未送达插话恢复、跨部署 Build-Fix 重新取得执行权均有回归覆盖。
- 交付：已有 MR 远端状态检查仍在 tryDeliver 交付链前；每个新 SHA 验证后才能 push；验证失败阻止 push/MR/流水线。同 SHA 的网络重试不重复跑验证。
- 问题单：有单完整流程、无单归档、流水线恢复、取消后证据重试停止及预热异常不阻塞主流程有定向覆盖。

## 验证与边界

所有测试从仓库根目录单进程执行。本轮使用真实 CloudSession/SDK 对接本地 ScriptedModelServer，在响应被挂起时取消或关停，再放回迟到响应，核对磁盘状态与模型请求数。模型网关是本地受控替身，不是内网真实模型。

定向测试覆盖 `auxiliarySessions`、`baselineWarmup`、`requirementReviewQueue`、`reviewCancellation`、`requirementEditing`、`recovery`、`idleContainerRelease`、`issueContainerLifecycle`、`prepushRecovery`、`prepushAgent`、`prepushIntegration`、`maeBuildSupport`；另筛选 `containerLifecycle` 与 `issueFlowFixed` 的取消、关停、恢复、预热、归档用例。类型检查与推送门禁另行执行。

`maeBuildSupport` 的真实 Docker 首编装配用例、`containerLifecycle` 的真实孤儿清扫用例因未指定 `MFC_REAL_BUILD_IMAGE` 显式跳过；本轮验证的是首编脚本与平台装配，不宣称跑通真实 C++/Java 业务编译。容器生命周期使用可控容器替身，测试拆除时需还原只读 Skill 快照目录权限。

仍需内网原子验收：用当前部署镜像、实际 Maven/npm 配置与真实辅助仓，在隔离验证工作区完成 FarsService 首编、增量编译和容器重建后重试。当前部署仍指定构建镜像，本轮没有增加按语言自动选镜像。已有运行进程需要更新代码并按正常流程重启才能取得本轮修复。
