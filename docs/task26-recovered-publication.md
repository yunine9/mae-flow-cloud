# task-26：结束后恢复的推送登记

## 结论与取舍

基于 Cloud main 812e4b0d 和配套内核 e70659f 复现。远端推送已成功，失败的是本地登记，不应要求重新推送或让 Agent 补造旧流程收据。

删除 `has_host_receipt` 及“曾有任意宿主收据才要求前驱链”的分支。它不能证明当前交付质量，却使 close 后恢复的任务永久卡死。不能只忽略 close：同时存在 pipeline/selection 历史收据的任务仍会失败。

当前没有反馈事实（未初始化或清空后的空反馈结构）时，已鉴权的宿主可直接登记新事实。存在反馈事实时，核验该事实的签名即可，close 与其他宿主动作一样可以证明反馈内容，工作步骤变化不撤销事实。Cloud 删除各入口重复维护的反馈动作白名单，统一调用内核反馈事实核验；终态与流水线核验仍各自保持原有语义。

保留的必要边界：当前宿主调用的任务绑定、载荷签名与 nonce；责任人目标和暂缓决定的防改写检查；非空反馈内容与逐条结果的防篡改；真实推送的 SHA/ref/remote；流水线结果对应的 SHA。推送登记不会生成 PASS，也不会关闭人工意见。

没有新增 reopen、收据删除、迁移凭证或审批。并非自动允许已完成任务继续写代码：由原有任务控制决定是否恢复，本次只解决恢复后的事实登记。

## 横向覆盖

- 普通交付、Agent 宿主工具推送、远端事实补登记及服务恢复共用 `recordPublishedPush` / `recordKernelPublishedPush`。
- 同源前驱限制：推送登记、目标调整、反馈开批、逐条结果登记。
- Cloud 消费反馈：活动批次读取、意见索引同步、回合结果收口、目标和暂缓项读取。
- `delivery attest` 的完整终态/流水线语义不变；反馈事实核验不再由调用方列举动作白名单。
- 同 SHA 的无状态重放保留幂等，不覆盖终态 close；新 SHA 保留旧验证历史但不冒充通过。
