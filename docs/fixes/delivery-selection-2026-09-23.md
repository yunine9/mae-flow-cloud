# 删除交付文件勾选机制（#432）

交付文件勾选已删除。用户漏看、漏勾不能成为后续修复的永久限制，也不再用自动
过滤规则代替人工勾选。Agent 在每次 commit 前检查暂存内容，宿主推送实际提交。

## 原因与证据

#432 报告 task-20 的文件从 12 个扩展至 15、16、19 个时反复阻塞。这些生产轮次
来自问题报告，本次没有直接读取生产任务的完整执行日志。代码核对确认：

- 自动交付和工具推送曾把后续文件集合与历史清单精确比较，增减文件即要求重新确认。
- `restore_delivery_paths` 要求额外恢复路径；同步后的整理还可能撤掉旧清单排除的业务修改。
- 未勾选文件曾被永久加入 `.git/info/exclude`，后续 Git 状态可能看不到它们。
- 前端必须加载并提交文件选择，文件快照和草稿状态也成为决定能否提交的前置条件。

原报告提出“文件集合变化就再次确认是合理的”，用户明确否定这一前提：不再让人
确认文件清单，不增加过滤器。此前仅改成“整理当次提交”的中间方案也已经撤销。

## 当前行为

1. 删除文件树勾选、全选、选择草稿、清单确认和清单变化后的编译选项。代码差异仍可
   浏览、搜索和批注。普通推送确认偏好与真实人工检视仍保留，不要求用户选择文件。
2. 删除宿主按勾选添加、剔除文件和重写提交的路径。旧客户端即使携带 `delivery_paths`
   也不再改变 Git 暂存区或提交；兼容字段只用于识别原请求的重试。
3. 已确认的推送沿用现有人工决定。新增、删除、重命名、同步或新 SHA 不要求扩大
   文件清单；旧的 `requested` 选择记录不会自行开启审批。新的明确返工意见仍处理。
4. 不再生成文件选择记录，不再向主会话、修复会话或 Build-Fix 注入历史选择。
   工具不再公开 `restore_delivery_paths`；旧的在途调用兼容返回“无需恢复”，不改写内核。
5. 启动和推送时清理 Cloud 标记区中能由旧记录确认的文件 ignore，保留用户自己的规则
   和平台目录规则。平台注入文件的现有边界、分支身份、并发修改和远端发布事实仍核对。
6. 已提交修复交给流水线时，不再因为工作区还留有未提交产物而反复唤醒 Agent；
   是否已推送以实际 HEAD 和推送结果判断，不要求清空工作区。

## 长会话中的提交方法

需求主会话和 Build-Fix 通过 `CloudSession.additionalSystemInstructions` 加载同一份
`COMMIT_CONTENT_GUIDANCE`。子会话继承，重启重新加载；它属于系统指令，不参与历史
对话压缩。问题单与知识萃取等其他调用方未注入这份任务指令。

固定指令要求每次 commit 前检查 `git diff --cached` 的文件列表和实际内容，并按本次
文件、需求查阅相关原始意见。无关产物只撤出暂存，保留本地文件；不按文件名或扩展名
维护自动黑名单，也不增加 Hook 或审批流程。

具体意见沿用现有任务记录，以及可重建的 `.mae-flow-work/owner-inputs.json` 阅读副本；
主会话也可用 `task_context(view=instructions, keyword=...)` 查询。Build-Fix 启动前刷新
副本。已处理意见保留原文和处置，标明“已处理”；未发送草稿不作为已交办要求。

**保存记录不等于让所有意见永久生效。** 已完成的单次修正不变成持续禁令；明确仍适用
的要求继续遵守，撤回或不采纳的意见不继续执行，用户改变要求时以最新原话为准。
按需查询，不把全部历史反复放进上下文。这是 Agent 的工作指令，不能声称机械保证
模型每次判断都正确；本次没有用新文件拦截规则换取这种保证。

## 验证与部署边界

- 真实本地裸 Git 远端和真实内核：旧清单 12→15→16→19，期间同步目标分支、重启，
  所有必要文件实际到达远端，无重复文件确认。旧选择请求不夹带暂存或未跟踪文件。
- 旧 ignore 迁移、中文及引号路径、业务暂存与未暂存内容保留、远端并发推进、失败重试、
  切错分支、实际发布 SHA 和原会话接续均有定向回归。
- 真实 Pi 会话接入脚本模型：主会话和 Build-Fix 实际压缩、重启后，请求的系统提示仍含
  提交方法；子会话继承，未配置的其他会话不注入。该测试证明指令到达，不证明模型判断质量。
- 追加 80 条后续输入并从磁盘重读后，已处理意见仍可按编号找回，不变为新待办。
- 前端构建、类型检查和受影响的交互测试验证文件选择已消失，差异阅读与批注仍保留。

`workspaceExecutionPanel.test.ts` 的 3 条存量源码断言仍失败：两条要求不带新参数的
旧差异读取调用，一条要求已不存在的 `localGroupOpen` 状态。本次没有改变这些调用
或组件结构；按仓库约定报告，不追查无关测试。

只修改 Cloud TS、前端及相关测试文档，不改内核源码，不需要同步内核快照。本次未部署
或远程改写生产任务。旧版本已实际删掉的业务代码仍需 Agent 按需求补回，不能凭文件名重建。
