# 中文交付路径引号导致 pathspec 失败

## 定位与取舍

`git add "中文路径"` 的 shell 引号不会写入文件名。Cloud 的 `deliveryContribution` 和整理后复核直接读取 `git diff --name-only`，Git 默认把中文输出为带引号的 UTF-8 八进制展示文本；随后路径归一化还会把转义反斜杠改成斜杠，错误可进入持久化交付清单。

按 kernel-simplification 排查：这是路径读取错误，不是需要新增审批或放宽授权的场景。保留用户选定/排除的范围，删除对 Git 人类展示格式的依赖，用 `-z` 读取机器路径。Cloud 专属修复在 TS；没有改动内核源码或快照。

## 修复覆盖

- 交付快照、MR 净贡献、整理后范围复核、检视文件清单与按文件读取统一用 NUL 分隔的名字；快照工作区状态使用 porcelain `-z`，重命名正确跳过旧名。
- 仍需读取展示格式的检视状态/统计，正确解码 Git 引号与 UTF-8 八进制，不再只剥掉引号。
- 旧交付清单的选中、排除、观测路径和推送检视路径，仅在当前 Git 事实能确定映射时恢复；兼容原始八进制、误转换后的斜杠和 UTF-8 外包引号。真实存在的带引号文件名优先原样保留。不会把 requested 改成 confirmed，也不会因此自动推送。
- 手动清单整理使用 literal pathspec，避免文件名里的 `[]` 等符号匹配到别的文件。
- 入队检查仅读取快照，实际范围整理仍在宿主既有入口执行。普通检视、重试与确认都复用该入口，没有新增 Agent 修复会话。

## 验证及恢复

真实临时 Git 仓覆盖：中文、空格、双引号、箭头、重命名、`[]` 文件名；requested/confirmed 两类历史清单；真实重组提交、重复执行、未选文件内容保留，以及精确剔除不误删其他文件。定向测试 48 项通过；另有一条既有 artifacts HTTP 测试创建任务时没有提供必填业务模块，在读取 waiting 前失败（server.ts 的创建接口已要求业务模块，HEAD 中测试仍只传 requirement），与 Git 路径无关。

内网更新部署后，对 task-20 使用现有“重跑”入口。运行中会修正有事实对应的历史路径，不必手动删引号或重新编辑代码。这里未连接或修改内网现场，也未把真实 CI 编译/UT 失败视为通过。
