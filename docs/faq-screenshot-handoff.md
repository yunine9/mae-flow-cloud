# FAQ 真实截图交接单

这份交接单给 Codex 桌面版直接执行。FAQ 页面、文案、富文本样式和图片位置
已经完成；桌面版只需要在脱敏演示环境中截真实页面、加编号圈注、保存到指定
文件，然后做一次页面验收。不要重写 FAQ，不要用设计稿或 AI 生成图代替实际
界面。

## 一、先准备脱敏演示环境

1. 在仓库根目录构建前端：

   ```bash
   cd web && npm run build
   ```

2. 回到仓库根目录，用全新的临时数据目录启动演示服务：

   ```bash
   npm run serve -- --port 8790 --host 127.0.0.1 \
     --data /tmp/mfc-faq-demo --web web/dist
   ```

3. 演示账号：

   - 开发成员：`dev / mae-flow-demo`
   - 管理员：`admin / mae-flow-demo`

4. 所有截图使用浅色主题、舒适密度、统一的 `1600 × 1000` 页面视口。只截网页
   内容，不要带浏览器标签栏、收藏夹、桌面或其他应用。

5. 只使用这个临时演示环境。不得打开正式服务，不得把真实用户名、任务标题、
   代码、Token、内网地址、客户数据或生产日志放进图片。

## 二、圈注的统一样式

- 在真实页面上临时叠加圈注后再截图；截完立即移除叠加层。
- 普通关键步骤：紫蓝色描边 `#655bd8`，2px，外加很淡的半透明底色。
- 编号圆点：紫蓝色实心圆、白字，编号 `1`、`2`、`3`、`4`。
- 危险或不能做的动作才用红色；成功结果才用绿色。不要为了热闹到处上色。
- 圈注不能盖住按钮文字、表单内容和状态。一个画面最多四个编号。
- 不要修改、重绘或美化页面本身；图片必须能和用户实际打开的界面对得上。

## 三、需要截的图片

### 1. `web/public/help/01-overview.png`

- 登录：开发成员。
- 页面：我的需求首页。
- 为了画面不是空的，先创建一条脱敏演示任务，让它运行到“待我核对”。标题可用
  `演示：补充订单状态提示`，不要使用真实仓库名。
- 圈注：
  1. 左侧“我的需求”。
  2. 左侧“问题处理”。
  3. 页面顶部“待我处理”区域或待办角标。
- 验收：一眼能看出“开发需求去哪里、查问题去哪里、需要我做什么在哪里”。

### 2. `web/public/help/02-launch.png`

- 登录：开发成员。
- 页面：点击“发起新任务”，保持表单打开。
- 使用脱敏示例文字，代码仓、模块和语言可以选择演示值；不要真的提交第二条任务。
- 圈注：
  1. 需求目标和验收说明。
  2. 代码仓选择。
  3. 业务模块与开发语言（知识自动匹配的依据）。
  4. 启动按钮；若工作流选择在同一画面可见，可用细线从编号 4 指过去。
- 验收：用户照着图就知道必填什么，且能看懂知识是自动匹配，不是手选每一条。

### 3. `web/public/help/03-task-workspace.png`

- 登录：开发成员。
- 页面：打开第 1 步创建的演示任务工作台。
- 圈注：
  1. 顶部当前状态。
  2. 阶段轨迹。
  3. 文档、代码、测试等材料区。
  4. 暂停、继续或交付操作区。
- 验收：不要截聊天长文占满屏，重点是“现在做到哪、看什么、下一步点哪里”。

### 4. `web/public/help/04-decision.png`

- 登录：开发成员。
- 页面：演示任务的“待我核对”决定卡。尽量让问题、选项、自由回复和提交按钮
  同屏；不要真的提交，以便重复截图。
- 圈注：
  1. 需要回答的问题。
  2. 现成选项。
  3. 自由回复或补充说明入口。
  4. 提交按钮和“意见已送达/状态已变化”等回执位置。
- 验收：明确告诉用户“选项不合适时可以自己写”，也不能让人误以为补充意见等于
  确认通过。

### 5. `web/public/help/05-issues.png`

- 登录：开发成员。
- 页面：问题处理。若演示服务不支持完整问题会话，就打开新建问题表单，不要伪造
  已完成的研究结果。
- 圈注：
  1. 发起问题研究。
  2. 历史会话列表或返回现场入口。
  3. 现象、日志、DTS 单号等材料输入区；若页面是空状态，则圈出页面给出的下一步。
- 验收：用户能看懂这里是“先查清问题”，不是一进来就强行改代码。

### 6. `web/public/help/06-team-dashboard.png`

- 登录：管理员。

- 圈注：
  1. “当前现场”页签。
  2. 可点击的阶段分布或阶段筛选。
  3. 需要行动的任务列表。
  4. “交付档案”页签。
- 验收：画面要回答“现在谁要行动”和“历史结果去哪里看”，不要圈重复信息。

### 7. `web/public/help/07-assets.png`

- 圈注：

  3. 工作流方案。
- 验收：这张图只讲三个抽屉分别放什么，不要塞编辑细节。

### 8. `web/public/help/07-knowledge-form.png`

- 登录：管理员。
- 页面：新建或编辑一条演示知识，表单保持未提交。
- 圈注：
  1. “业务 / 工程”二选一。
  2. 业务知识的业务模块多选；若选工程，则圈开发语言多选。
  3. 文档 / Skill / 规则 / 示例等呈现形式。
  4. 标签不完整时“不参与匹配”的明确提示。

  4. 进入详情或编辑入口。

  4. 保存草稿 / 发布版本。

## 四、把图片接回 FAQ

1. 图片文件名必须与上面完全一致。FAQ 已经引用其中主要图片；把新增的
   `07-knowledge-form.png`、`08-workflow-editor.png`、`11-administration.png`
   接到对应文章的 `screenshots` 数组里。
2. 打开以下文章逐篇检查：

   - `/help/getting-started`
   - `/help/launch-requirement`
   - `/help/requirement-workspace`
   - `/help/handle-waiting`
   - `/help/issue-flow`
   - `/help/team-dashboard`
   - `/help/knowledge-assets`
   - `/help/workflow-assets`
   - `/help/wish-wall`
   - `/help/personal-settings`
   - `/help/administration`

3. 验收要求：

   - 图片加载成功，没有破图、拉伸、文字糊掉或横向滚动。
   - 编号和图片下方说明完全对应。
   - 深色主题下图片仍有清楚边框，但图片本身保持统一浅色主题。
   - 搜索“暂停”“/mfc”“自动匹配”“工作流”“编译超时”都能找到正确文章。
   - 开发成员看不到管理员专属文章，管理员也不被开发成员专属文章干扰。
   - 浏览器前进、后退和直接打开文章链接都正常。

4. 完成后运行：

   ```bash
   npx tsx --test tests/helpCenter.test.ts
   npm run typecheck
   cd web && npm run build
   ```

不要因为截图暂时做不出来而提交占位图。图片缺失时 FAQ 会自动隐藏图片区域，
不会向用户展示破图；但对外分享前，上述 13 张图必须全部完成并通过实际页面验收。
