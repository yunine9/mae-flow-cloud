# DTS 问题单最小流程

这一入口用于“问题现象已出现，但根因和修改范围尚未确认”的任务。它和普通需求共用同一套任务、审批、代码检视、推送和流水线能力，不复制第二套交付系统。

## 当前闭环

1. 在“发起新任务”左侧选择“DTS 问题单入口”。
2. 手工填写问题单号、问题描述、一个代码仓；可选填一个日志环境和一个换库环境。
3. Cloud 只读分析代码，并通过已配置的环境适配器拉取日志。Agent 看得到环境名称、用途、地址和用户名，看不到密码。
4. Agent 将证据、根因、修改范围、验证与回滚方案写入 `issue-analysis.md`，不确定事项逐题询问。
5. 用户确认后，Cloud 结束诊断会话；同一个任务以 Mae-Flow 的“已定位问题修复”流程继续，确认过的诊断文档直接成为内核需求文档，不重复走完整需求澄清。
6. 后续代码检视、推送前编译与 UT、MR 和权威流水线仍沿用现有交付主链。

没有接日志适配器时也能发起问题单，Agent 会先依据问题描述和代码形成诊断，并对缺失证据明确提问。当前版本不自动访问 DTS 系统、不自动识别代码仓，也不自动换库。

## 环境凭据边界

- 每单最多配置一个日志环境和一个换库环境，二者分别填写，不使用混合环境。
- 一套环境只填写一次主机和端口，并在其下保存三套登录账号；界面固定提供
  `sopuser`、`ossuser`、`ossadm`。这三个账号不是三套环境。
- 密码使用宿主任务保险箱加密保存，`task.json`、API、模型提示和事件流中都不含密码。
- 只有环境适配器在一次调用期间拿到对应凭据；适配器返回的日志才作为普通现场材料交给 Agent。
- 任务取消、完成或进入等待合入后，临时凭据文件自动删除。
- 当前本机加密保险箱不是企业 KMS 的替代品；部署需要更高等级密钥治理时，可替换保险箱实现，不改变任务流程。

## 内网适配接口

部署集成可向 `TaskService` 注入 `IssueEnvironmentAdapter`。三个能力彼此独立，可先接日志，之后再接换库与回滚：

```ts
new TaskService({
  // ...现有参数
  issueEnvironmentAdapter: {
    async fetchLogs(request) {
      // 使用 request.environment + request.credentials 连接环境；
      // credentials 同时包含本环境的 sopuser/ossuser/ossadm。
      // 服从 request.signal 的取消/超时，返回文本日志。
      return { content: "...", source: "/path/to/app.log" };
    },
    async deployCandidate(request) {
      // 后续接入：部署 request.sha，并返回可审计 receipt。
    },
    async rollback(request) {
      // 后续接入：按上一次 deployment receipt 回滚。
    },
  },
});
```

接口定义在 `src/issueEnvironment.ts`。适配器不应把密码、远端完整命令或带密钥的异常文本写入返回值和日志。换库能力接入时还必须在 UI 增加目标确认、回执和一键回滚；不能仅凭 Agent 文本宣称部署成功。

## 后续对接顺序

1. DTS 适配器：按当前用户列出问题单并回填问题描述。
2. 仓库映射器：根据问题单字段给出候选仓，仍由用户确认。
3. 日志适配器：按环境和时间窗采集、截断、脱敏。
4. 换库与回滚适配器：返回机器可核对的部署回执。

这些都是 Cloud 外部能力；Mae-Flow 内核仍只负责确认后的代码交付语义。
