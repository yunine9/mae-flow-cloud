# Mae-Flow 前端体验与视觉基线

> 状态：v5，2026-09-05。工作台以已确认的 Studio 原型为实现方向：左侧完整材料，
> 右侧与 Agent 协作；材料批注与协作反馈共用记录，决定回复固定在协作栏底部。
> 本轮实际效果仍待用户验收。全站共享紫白配色令牌，工作台保留现有面板层次。
> 范围：`web/src/` 下的个人工作、团队总览、任务工作台、问题流、资产库、设置与 Agent 输出。
> 原则：旧页面不要求一次性重写；任何被改动的区域必须向本基线收敛，不得继续制造新的例外。

## 先读这一分钟

Mae-Flow 的“高级感”不是更多渐变、动效和卡片，而是五个词：

**克制、清晰、精确、安静、可信。**

任何页面都必须守住以下红线：

1. 一个页面只允许一个首要任务和一个主按钮。
2. 首屏优先展示“现在需要我做什么”，不是功能目录和全量数据。
3. 默认给结论，证据按需展开，原始日志最后查看。
4. 永久标签页最多 4 个；卡片最多嵌套 2 层；零值指标默认不展示。
5. 新增一个长期可见元素，必须说明它替代、合并或折叠了什么。
6. 状态颜色只表达状态，不表达业务栏目；危险红不得拿来做页面主题色。
7. 不允许为单个页面发明新的按钮、徽标、间距、圆角或阴影体系。
8. Agent 的长文不能直接倾倒到主界面：人先读结果，再读证据，审计时才读原始记录。

如果一个方案需要用户学习界面结构之后才能完成任务，它就还没有设计完。

## 1. 为什么会从“刚开始还行”变成失控

第一版通常只有一条主流程，信息层级天然清楚。功能逐渐增加后，如果每个需求都以“给它找个位置”为目标，产品就会出现可预测的退化：

- 每个能力都获得一个长期可见入口；
- 每种数据都获得一张卡片；
- 每个状态都获得一个徽标；
- 每次解释不清就增加一段辅助文案；
- 页面空间不足就继续增加标签页、折叠层和局部导航；
- 新模块用新的颜色和样式证明自己的存在。

这些决定单看都合理，合在一起却让界面失去编辑权。当前 Mae-Flow 已经出现了这些征兆：个人首页的零值统计与空状态重复表达，问题创建表单压在问题列表之前，任务页存在多层导航，资产页把能力分类直接变成大块界面，Agent 的输出和原始事件又在争夺同一阅读层级。

所以本基线首先约束的不是颜色，而是**信息进入界面的资格**。

## 2. 我们借鉴什么，不照抄什么

| 参考体系 | 借鉴的纪律 | 在 Mae-Flow 中的落点 |
|---|---|---|
| [Linear Method](https://linear.app/method/introduction) | 简单优先、清晰优先、拒绝忙碌感；问题描述应短而可扫描 | 首页围绕待办，任务标题与摘要短，详细上下文链接下沉 |
| [Linear Inbox](https://linear.app/docs/inbox) | 把需要用户处理的事项汇成一个可清空的队列 | “我的工作”以待我处理为核心，不以统计看板为核心 |
| [GitHub Primer](https://primer.style/product/getting-started/) | 一致、熟悉、安静；新增内容会稀释已有内容 | 优先复用原语，新功能不得自动获得新的视觉模式 |
| [Primer Layout](https://primer.style/product/getting-started/foundations/layout/) | 布局服务于稳定心智模型，复杂多栏在小屏退化为简单视图 | 任务页使用稳定的主区/侧区；小屏不挤压保留所有面板 |
| [Vercel Geist](https://vercel.com/geist/introduction) | 用少量基础规则形成高完成度，而不是页面各自发挥 | 收敛色阶、字阶、间距、圆角和组件变体 |
| [Geist Typography](https://vercel.com/geist/typography) | 字体样式按阅读目的组织；等宽字体只用于技术内容 | Agent 正文使用界面字体，日志、命令和代码才使用等宽字体 |
| [Geist Sheet](https://vercel.com/geist/sheet) | 相关但非主线的上下文留在侧层，不复制页面标题与导航 | 创建问题、查看日志、查看证据、编辑次要信息使用侧栏 |
| [Carbon Productive UI](https://carbondesignsystem.com/patterns/fluid-styles/) | 复杂工作界面应保守、稳定、高效；表现型视觉留给少数时刻 | 工作台避免大面积装饰，成功交付等关键时刻才允许增强表现 |
| [Carbon Empty States](https://carbondesignsystem.com/patterns/empty-states-pattern/) | 空状态本身有认知成本，应代替空壳而非叠加在空壳之上 | 无数据时不同时展示零值统计、空卡片和解释文案 |
| [Apple Disclosure Controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls) | 高频动作直接可见，高级选项渐进披露 | 凭证、执行参数、原始证据、低频配置默认收起 |
| [Atlassian Foundations](https://atlassian.design/foundations) | 设计 token 是跨页面的一致性来源 | 颜色、间距、排版、圆角、阴影都由 token 管理 |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | 对比度、键盘、缩放和焦点不是美化项，而是可用性底线 | 所有主题和密度模式必须通过同一套可访问性验收 |

我们不照抄任何一家产品的外形。Mae-Flow 是一个高信息密度、强证据链的人机协作工作台，目标不是“像 Linear”，而是吸收它们共同的纪律：**焦点少、层级稳、模式可复用、细节有依据。**

## 3. 信息架构基线

### 3.1 五层信息模型

所有信息必须被放入以下一层，禁止“因为重要”就全部放到首屏：

| 层级 | 用户问题 | 默认可见性 | 典型内容 |
|---|---|---|---|
| L0 全局 | 我在哪、还能去哪 | 始终可见 | 主导航、账号、全局搜索 |
| L1 任务 | 这个页面要完成什么 | 始终可见 | 页面标题、当前对象、唯一主动作 |
| L2 行动 | 现在需要我做什么 | 优先可见 | 待处理决定、失败、阻塞、下一步 |
| L3 证据 | 为什么、依据是什么 | 按需展开 | 摘要、变更、检验、关键上下文 |
| L4 审计 | 系统原始发生了什么 | 默认隐藏 | 完整事件、工具调用、日志、原始 JSON |

设计评审时若无法指出一个元素属于哪一层，它就不应进入界面。

### 3.2 首屏视觉预算

桌面端首屏（1440 × 900）默认预算：

- 1 个页面标题；
- 1 个主按钮；
- 1 个主要摘要或行动区；
- 最多 3 个需要立即辨认的状态；
- 最多 4 个一级标签页；
- 最多 2 个并行信息列；
- 最多 1 条非阻塞提示。

同步成功、保存成功、零值统计、长期说明、原始日志不占用首屏预算。成功应安静，异常才打断。

### 3.3 一进一出

新增任何长期可见入口、卡片、标签页、徽标或操作，PR 必须回答：

1. 它服务的用户任务是什么？
2. 为什么已有模式无法承载？
3. 它在哪个状态下才应该出现？
4. 它进入后，哪个旧元素会被删除、合并、降级或折叠？

没有第 4 个答案，不得合入。这条规则是防止界面持续膨胀的核心。

## 4. 视觉语言

> 2026-09-05 定稿。所有取值只在 `web/src/tokens.css` 一处，组件不得复制数值。
> 一句话概括：**全站紫白主题，保留面板层次，语义色只表达状态。**

### 4.1 色彩：紫白画布与统一的控件层次

- 导航、个人总览、团队总览和工作台共用淡紫灰画布、白色面板与紫色主动作。
- `canvas → surface → surface-2` 保持表面层次，保留 Studio 的边框、阴影和立体感。
- 主色使用恢复的 `#5b5bd6`；旧 `ink` 命名和 `accent` 别名兼容保留，前景走 `--accent-fg`。
- 琥珀表达需要人处理，蓝色表达推进，绿色表达完成，红色表达失败；不把状态统一涂紫。
- 深色主题使用对应深色表面和高对比文字，功能及层级一致。
- 全部共用颜色放在 `tokens.css`。顶部进度按用户要求恢复旧版节点连线与阶段名样式。

```text
canvas  surface  surface-2  surface-3  overlay
text-strong  text  muted  faint
line  line-strong
ink / ink-fg     active  attention  success  danger  merge     focus
```

### 4.2 表面、边框和阴影

- 列表与首页：画布层不描边；分区靠标题与留白，分隔靠一条发丝线（`--line`）。
- 工作台：一级区块是**面板**——`--surface` 底、`--line` 发丝边、12px 圆角、
  48px 的 `--surface-2` 题头（左标题右动作，可折叠的题头就是整块）。
  面板里最多再套一层 `--surface-2` 的引用块（Agent 回应、决策背景、代码），
  不再往下套。这是 v3 对 v2"只用分割线"的勘误：深色下 2–3% 亮度差的
  分割线让面板、批注卡、展开区全部沉进背景（2026-09-05 用户实锤）。
- 表面台阶必须可辨：深色 canvas #0f0f0e → main #141413 → surface #1c1c1b →
  surface-2 #252524，线 #30302e；浅色线 #dededa / 强线 #c4c4bd。
- 阴影只给浮层（悬浮抽屉 `--shadow-lg`、弹窗 `--shadow-md`）与被选中的
  导航项（`--shadow-sm`）。停靠态的检查器没有阴影，它是一栏不是浮层。
- 渐变、玻璃拟态、发光全部退出日常工作流。

### 4.3 间距、圆角和密度

统一 4px 网格，取值只从 token 拿：

```text
space:   4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64
control: 28（sm）/ 32 / 36（lg）
radius:  6（控件）/ 8（面板）/ 12（对象卡、浮层）/ 16（登录卡）
```

- 页面区块间距 32，相关内容 8–16；工作台正文栏 880px 居中，两侧 `clamp(24px, 5vw, 64px)`。
- 紧凑密度整体切换 `--fs-14/--fs-15/--control-h/--space-*`，不再局部改字号。
- 主交互目标不小于 32 × 32px；图标按钮 26–32px 并带可访问名称。

### 4.4 排版

| Token | 尺寸 / 行高 | 用途 |
|---|---:|---|
| `--fs-30` | 24–30 / 1.25 | 工作台"当前"标题（`clamp(24px, 2.1vw, 30px)`） |
| `--fs-24` | 24 / 1.25 | 页面标题、登录标题 |
| `--fs-17` | 17 / 1.45 | 分区标题、决定卡标题 |
| `--fs-15` | 15 / 1.75 | 正文阅读：需求原文、Agent 说明、Markdown |
| `--fs-14` | 14 / 1.6 | 界面正文、按钮、导航 |
| `--fs-13` | 13 / 1.5 | 辅助信息、表单标签 |
| `--fs-12` | 12 / 1.4 | 单号、计数、时间戳（等宽或 tabular） |

- 标题字重 600、正文 400、强调 500——不再用 700/800，中文回退字体下更稳。
- 12px 是下限；11px 及以下已在全站样式里批量抬到 12px。
- 英文大写 kicker（`NEXT ACTION`、`ACTION REQUIRED`…）全部退出：中文标题
  只保留一套，`letter-spacing` 与 `text-transform: uppercase` 已从样式表移除。
- 单号（`UI0005`）、内部编号、计数用等宽 + `tabular-nums`，是全站唯一的
  "技术感"笔触；正文、按钮、Agent 说明一律界面字体。
- 中文正文每行 32–42 字；Markdown 容器最大 78ch。

### 4.5 图标和动效

- 只使用一套图标语言，常用尺寸 16/20px，线宽与视觉重量一致。
- 图标按钮必须有可访问名称和悬停提示。
- 状态切换 120–160ms，面板进入 180–220ms；不做无意义的持续动画。
- 遵守 `prefers-reduced-motion`；禁用动画后不能丢失状态信息。

## 5. 组件基线

新增页面必须优先由以下原语组成：

`AppShell`、`PageHeader`、`Toolbar`、`Button`、`IconButton`、`Badge`、`Status`、`Tabs`、`Section`、`DataList`、`EmptyState`、`Disclosure`、`Drawer`、`Dialog`、`FormSection`、`Toast`、`AgentResult`。

共同规则：

- **Button**：`primary / secondary / ghost / danger` 四种足够。一个作用域只出现一个 primary。
- **Tabs**：只表示同级视图切换，不承担按钮、筛选器和状态徽标的全部职责；一级永久标签最多 4 个。
- **Badge**：只显示短状态或数量，不放句子，不用作普通说明标签。
- **Section**：靠标题和间距建立结构；不是每个 Section 都需要边框与背景。
- **EmptyState**：代替空内容，不叠加在零值指标、空表格和空卡片下面；只给一个明确下一步。
- **Drawer**：承载相关但非主线的创建、编辑、证据和日志；不得在抽屉内复制整套页面导航。
- **FormSection**：常用字段直接展示，高级配置与凭证渐进展开；说明紧贴字段，不在顶部堆成长篇教程。
- **Toast**：保存、同步等成功反馈短暂出现；持续异常进入页面状态区。
- **Status**：同一状态只表达一次，避免标题、徽标、提示条和卡片重复播报。

禁止事项：

- 为单页复制一套“几乎相同”的按钮、标签、空状态或表单样式；
- 用可点击的卡片替代所有导航；
- 在标签页里继续放标签页，除非第二层确实属于对象内部且无法用筛选替代；
- 用胶囊形状包裹每一段元数据；
- 以“更突出”为理由同时增加颜色、加粗、描边和阴影。

## 6. Agent 内容阅读基线

### 6.1 核心原则

> 人读结果，必要时读证据，审计时读原始记录。

Agent 输出不能被当作一条任意长度的聊天消息直接渲染。前端与服务端应逐步收敛到结构化结果：

```ts
type AgentResult = {
  headline: string;              // 一句话结论
  state: "running" | "waiting" | "succeeded" | "failed";
  changed?: string[];            // 做了什么
  verification?: string[];       // 如何确认
  risks?: string[];              // 剩余风险或未知项
  nextAction?: { label: string; owner: "user" | "agent" | "system" };
  detailsMarkdown?: string;      // 完整说明
  traceIds?: string[];           // 原始事件与日志索引
};
```

默认呈现顺序固定为：

1. 一句话结论；
2. 需要用户处理的动作；
3. 变更、验证和风险；
4. “查看完整说明”；
5. “查看原始记录”。

长文不允许只按字符数机械截断。必须优先按标题、列表、代码块和语义段落折叠；服务端尚未提供结构化结果时，前端解析出“结论 / 变更 / 验证 / 风险 / 下一步”，无法识别的内容再进入完整说明。

### 6.2 运行中

- 以阶段归并活动，如“理解需求”“修改代码”“验证结果”“准备交付”。
- 默认显示当前阶段、已用时间和最近一条有意义进展。
- 工具调用、重复重试和内部思考不逐条进入主时间线。
- 超过 8 秒没有可见变化时给出诚实状态，不用无限旋转图标掩盖等待。

### 6.3 已完成

- 首先回答“结果是什么”和“是否验证通过”。
- 文件、测试和交付链接放在对应事实旁边。
- 成功结果不需要一大块绿色背景；一个清晰状态和结论即可。
- “完整内容”保持可复制、可搜索；“原始记录”保留时间戳和事件类型。

### 6.4 等待用户

- 决策问题置顶，并明确“为什么现在需要你”“不处理会怎样”。
- 推荐选项可以说明理由，但不得替用户制造已经决定的错觉。
- 证据折叠在决策卡内，原始日志不应先于选项出现。

### 6.5 失败

- 先说失败发生在哪一阶段、已造成什么影响、哪些结果仍然有效。
- 提供一个主要恢复动作；诊断包和完整日志作为次要入口。
- 禁止只显示异常堆栈，也禁止用泛化的“发生错误”隐藏事实。

## 7. 关键页面的目标结构

### 7.1 我的工作

默认只保留两块：

1. **待我处理**：审批、补充信息、失败恢复、被点名事项；
2. **当前任务**：正在进行及最近有变化的任务。

零值统计隐藏；统计仅在非零且能触发行动时出现。同步成功不常驻，失败才进入状态区。创建任务是唯一主按钮。

### 7.2 团队总览

先展示阻塞、等待和风险，再展示吞吐量。数字必须能下钻到对象列表，不能只做装饰。默认视图解决“哪里需要干预”，完整报表下沉到分析视图。

个人与团队任务默认采用 44px 单行总览，点击整行进入工作台；列表不展开决定表单、日志或进度。
宽屏保留编号、名称、状态、负责人、更新时间，窄屏优先名称和状态。主任务显示去重后的子任务数，
子任务按树序紧跟父任务并缩进，提供独立的父任务跳转。筛选不补入未命中的父任务，但归属使用完整的
有权限任务集合解析；无法打开的父任务明确禁用入口。团队问题会话使用同样的单行样式。

### 7.3 任务工作台：产品的第一现场

任务工作台不是普通详情页，而是 Mae-Flow 最核心的产品界面。首页只负责把人送到正确任务；真正的审美、效率和信任都在工作台里接受检验。因此它是全部前端治理的第一优先级。

#### v5 实现结构

```text
任务头：任务身份 / 状态 / 进度 / 任务控制
┌ 完整材料（自适应宽度）────────────┬ 与 Agent 协作（340–430px）─────┐
│ 需求原文 / 过程文档 / 变更 / 活动 │ 状态 / 当前决定或异常操作       │
│ 文档目录或文件树 │ 阅读与代码差异 │ 反馈、实际送达状态、Agent 回应  │
│ 圈选 → 原位写意见 → 保存或提交   │ 同一条记录，可定位、编辑和复检  │
│ 点已有批注 → 原位查看这条讨论    ├─────────────────────────────┤
│ 搜索、全屏、下载与材料操作保留   │ 固定的决定回复或运行中补充入口 │
└───────────────────────────────┴─────────────────────────────┘
```

- 左侧文档、diff 和复杂工作区始终是完整阅读器，不塞入聊天卡。跨仓场景继续提供模块依赖图。
- 右侧优先显示当前待办。背景、选项、意见在一条滚动区域内；真正的回复与提交控件通过 React portal 停靠底部，保持同一份状态。
- 单问题卡把自定义答复与整卡备注合并为一个回复输入：有选项时文本为备注，无选项时文本为自由答复。多问题和需求确认保留各自流程。
- 正常视图的反馈提交只登记意见，不自动选返工或放行。全屏检视保留明确标注的“提交并返工”快捷动作。权限和排队/中断时机仍由后端决定。
- 原位保存后，材料旁与协作栏复用同一个批注 ID。创建成功但送达失败时保留已保存记录，允许在该记录重试，不重复创建。
- 交付清单仍只在代码树修改，决定卡保留可展开的摘要与定位入口；最终推送继续绑定当前版本和真实选择。
- 无待办时，右侧仍承接进展和协作。失败突出原因与重跑，暂停保留恢复与助手接管，原始事件默认折叠。
- ≤900px 材料与协作上下排列，阅读区域独立滚动；回复区保留粘性位置。≤600px 文档目录横向排列、文件树位于代码上方。
- 全屏阅读隐藏协作栏，意见通过侧栏查看；退出后恢复普通布局。Escape、搜索、下载和键盘快捷键继续保留。
- `workspace-studio.css` 仅作用于工作台；`tokens.css` 是配色令牌来源。浅色与深色 diff 都必须保证增加、删除、行号及正文可读。
- 普通视图不再同时存在第三个意见抽屉。已有 `focus/materials/execution` 内部状态兼容保留，不重建旧导航。

### 7.4 我的问题

问题列表和当前问题是主任务；“创建问题”进入独立页面或抽屉。环境、凭证和高级采集参数按需要展开，不允许一张巨型表单长期压在列表上方。

问题可以有语义上的危险状态，但整个栏目不得用危险红换肤。

### 7.5 团队资产

采用“简洁二级导航 + 列表/详情”结构。知识、模块、工作流、洞察、记忆如果无法在首屏形成不同的高频任务，就应先归并为筛选或资产类型，不自动各占一个大标签页和说明卡。

### 7.6 设置与管理

按对象分组，而不是把所有开关铺满页面。常用设置直接可见，低频配置、危险操作和技术参数分别下沉。危险操作独立分区并明确影响范围。

## 8. 内容与文案

- 标题说对象或任务，不说系统模块名：优先“待你确认的方案”，少用“决策管理中心”。
- 按钮使用“动词 + 对象”：`创建任务`、`批准方案`、`重试验证`。
- 状态写事实：`等待你确认`，不写含糊的 `处理中`。
- 避免标题、英文 kicker、副标题连续三遍解释同一件事。
- 默认长度建议：按钮不超过 8 个汉字，标签页不超过 6 个汉字，页面副标题不超过 36 个汉字，空状态说明不超过 2 行。
- 技术名词只在它能帮助用户判断时出现；内部事件名、模型参数、trace ID 默认进入证据或审计层。
- 标点、空格、大小写和时间格式全局一致，不在组件内各自格式化。

## 9. 响应式与可访问性

必须同时验证 1440 × 900、1280 × 720、390 × 844，以及 200% 浏览器缩放。

- 宽屏最多两列主信息；小屏转为单列与可切换面板，不把桌面布局等比缩小。
- 除代码、diff 和真正的数据表外，不允许页面级横向滚动。
- 所有操作可用键盘到达，焦点样式清晰且不被裁切。
- 弹窗和抽屉正确管理焦点，`Esc` 可关闭非破坏性浮层。
- 表单错误与字段关联；颜色之外必须有文本提示。
- 加载、空、正常、长中文、失败、等待人工、50 条以上数据都要验收。
- 明暗主题共享同一语义 token，不允许浅色主题靠大段覆盖样式“补丁式兼容”。

## 10. 新功能准入清单

涉及界面的 PR 必须附上以下答案和截图；任一项缺失，视为设计未完成：

- [ ] 这个改动服务的单一用户任务是什么？
- [ ] 它属于 L0–L4 的哪一层？默认为什么必须可见？
- [ ] 复用了哪个现有组件或模式？若新增原语，为什么值得全产品复用？
- [ ] 新元素进入后，删除、合并、降级或折叠了什么？
- [ ] 页面是否仍然只有一个主按钮、一个主要摘要区？
- [ ] 是否覆盖加载、空、正常、长内容、失败和无权限状态？
- [ ] 是否验证键盘、焦点、对比度、200% 缩放和小屏？
- [ ] 是否提供明暗主题截图，以及默认/高密度数据截图？
- [ ] Agent 内容是否区分结论、证据和原始记录？
- [ ] 是否引入裸色值、任意间距、一次性 CSS 类或重复组件？

新增全局导航、第五个一级标签页、新状态颜色或新的页面布局范式，需要独立设计决策记录，不能在普通功能 PR 中顺带加入。

## 11. 工程约束与自动化守门

`web/src/style.css` 仍有约 1.17 万行遗留样式（09-05 起颜色全部经由 token，
硬编码字号已抬到 12px 下限，但页面级特例仍多）。治理顺序如下：

1. ✅ `tokens.css` 已是颜色、排版、间距、圆角、阴影、动效的单源，先于一切样式加载；
2. 建立上述基础组件，业务页面不再直接手写同类交互；
3. 按布局、原语、领域拆分全局样式，禁止继续向单一巨型样式表追加整页样式；
4. 为组件建立可视样例，覆盖全部状态、长中文、明暗主题与密度；
5. CI 检查新增裸色值、非 token 间距、重复组件和不可访问交互；
6. 对关键页面做视觉回归截图，并运行键盘与可访问性检查。

遗留代码采用“触碰即收敛”：改动某区域时，把该区域用到的重复样式迁入 token 或原语；不为了追求一次性纯净而进行高风险大重写。

## 13. 验收定义

一个页面只有同时满足以下条件，才算达到本基线：

1. 用户在 5 秒内能指出页面主任务和下一步；
2. 默认视图不依赖阅读 Agent 长文或原始日志；
3. 相同状态、操作和信息在不同页面使用相同模式；
4. 空状态比有数据状态更简单，而不是更啰嗦；
5. 新能力没有增加不必要的永久视觉入口；
6. 明暗主题、小屏、键盘、缩放和长中文均可用；
7. 实现使用共享 token 与组件，没有留下新的页面级特例。

这份基线的最终目的不是让所有页面“长得一样”，而是让用户始终感到：**系统知道什么最重要，也知道什么此刻不必打扰我。**

## 14. 工作台场景基线

视觉验收不能依赖临时造任务或只截一个“最好看”的正常态。仓库必须长期保留
一套可复位的真实任务目录，覆盖下面 16 个场景：

| 类别 | 固定场景 |
| --- | --- |
| 推进 | 排队、运行中、正在暂停、已暂停/助手接管、跨仓协同 |
| 人工决定 | 需求确认、长文多问题、模块拆分、推送前代码检视 |
| 交付 | 验证中、验证停机、范围越界、等待合入 |
| 终态 | 失败、完成、取消 |

每次重构至少完成以下矩阵，不允许只验证页面能打开：

- 逐场景触发“当前 / 产物 / 活动 / 批注与检视”，打开所有折叠层；
- 实际操作搜索、结果跳转、全屏、快捷键、代码范围、行批注、检视筛选和邀请；
- 实际走一次决定提交、暂停/恢复、取消确认、重试、诊断导出和删除确认；
- 验证深夜/云昼、舒适/紧凑，以及 1440、900、390 三档宽度；
- 分别以责任人、受邀检视人和只读旁观者登录，确认能力按权限消失而非事后报错；
- 破坏性或会推进状态的操作在可复位样本上执行，验收结束后恢复标准样本。

场景清单以 `scripts/ui-workbench-scenarios.ts` 为单一事实源。新增任务状态、
新按钮或新的内容层级时，必须同时补场景、动作清单与契约测试；否则视为功能
尚未完成。持久样本只允许在 `MAE_FLOW_UI_FIXTURE_MODE=1` 且任务带
`ui_fixture` 标记时冻结，不能改变正式任务的恢复语义。
