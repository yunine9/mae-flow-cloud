# 演进底稿:业界理念对照与优先级(2026-08-17)

目标不变:为团队真提效,不是做样子。每条记三件事:业界谁验证过、
我们已有什么、可借的增量是什么。实战(WSL 首跑)之后按此推进。

## 优先级(用户拍板:除 IM 入口待确认,其余都要)

1. **平台自证提效**(评测思维,SWE-bench 私有化)
2. **修复先定位**(Agentless)
3. **分类月光**(Cline/Roo 的审批粒度)
4. **repo map**(Aider)
5. **环境即代码**(devcontainer)
6. **recipes 众筹**(goose)——与已拍板的"skill git 收编"合流
7. IM 入口(Devin/Cursor 的群内派活)——**待内网确认**:WeLink 是否
   有机器人/回调能力;没有也不亏,通知深链(点开直达决策卡)已是半程

## 各条细账

### 1. 平台自证提效 —— 最高优先

- **业界**:SWE-bench/verified 的评测纪律:改动是否更好,跑一遍就知道。
- **已有**:PG 投影(事件/外部动作台账)、.pilot 归档现场、
  run-report 对拍脚本。
- **可借**:
  - 指标看板页:下单→await_merge 周期、一次通过率、修复轮均值、
    每单人工触碰次数——数据都在投影里,缺一张页面;
  - 归档任务变回归评测:内核/提示词改动后重放 .pilot/archive 的
    真实任务对拍,防"越改越差"。
- **为什么第一**:它既是提效的证据,也是与团队/领导沟通最硬的语言。

### 2. 修复先定位

- **业界**:Agentless(论文)——"定位→修复→验证"的固定管线在修 bug
  上打赢复杂 agent 循环,成本可预测;GitLab Duo 的流水线修复按钮同构。
- **已有**:修复环分诊使命(列全类别、按类派专职)。
- **可借**:分诊之后、动手之前,把"先定位到文件/函数,说出定位依据"
  写成使命的显式一步——别拿着日志全仓乱撞。

### 3. 分类月光

- **业界**:Cline/Roo 的 auto-approve 按动作类别勾选,不是总闸。
- **已有**:月光模式(全有全无)+ 交付方式预答,自动交卷通路(decide 同路)。
- **可借**:月光演进为按卡类别的粒度(如:文档确认类免批,交付/配置
  类保留)。识别类别要小心红线——按内核卡自带的语义字段来,宿主不猜。

### 4. repo map

- **业界**:Aider 的 tree-sitter 排序代码地图,大仓上下文效率的关键。
- **已有**:AGENTS.md 索引 docs/ 的知识约定(pi 稳定消费已验证)。
- **可借**:大仓(内网巨型 Java 仓)自动生成 repo map 注入会话;
  另一半是 OpenHands microagents 式"带触发词的知识块"——命中才注入,
  与"知识在仓不在平台"路线一致。

### 5. 环境即代码

- **业界**:devcontainer / E2B / Daytona——环境声明进仓。
- **已有**:`--isolate-image` 已是正式内核模式的必选边界，普通 Agent、
  子 Agent、修复与 prepush 的 Bash 共用统一加固运行时。
- **可借**:未来可评估仓内 devcontainer 声明，但必须先转换成平台审批过的
  镜像与资源契约，不能让业务仓直接放宽当前安全边界。

### 6. recipes 众筹

- **业界**:goose 的 recipes(可分享任务配方)。
- **已有**:用户已拍板 skill 收编进 git、众筹修改;两个内网 UT skill
  待进场收编。
- **可借**:形态即"配方文件在仓、平台只消费",无平台配置面。

### 7. IM 入口(待内网确认)

- **业界**:Devin/Cursor 后台 agent 的 Slack 派活——采纳率最高的入口。
- **已有**:WeLink 通知出口 + 深链直达决策卡(半程)。
- **前提**:WeLink 是否有机器人接收消息/回调的能力,进场确认;没有
  就停在半程,不硬做。

## 刻意不抄的

- 复杂 agent 编排框架(状态机化的多 agent 图):用户已拍板"提示词
  就行",Agentless 的结论也站这边;
- 平台侧知识库/技能市场:知识在仓(AGENTS.md+docs),skill 在 git;
- 全自动合入:MR 合入永远留给人,交付点是人机边界。
