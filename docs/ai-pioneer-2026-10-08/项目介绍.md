# Mae-Flow Cloud 项目介绍

**面向研发全过程的 AI 协作与交付平台**

项目名称：Mae-Flow Cloud

参评人：廖翔｜参评方向：AI 先锋个人参评

## 项目概述

Mae-Flow Cloud 是我设计并实现的 AI 研发平台，将 AI Agent、研发工具和团队知识组织在统一工作台中，覆盖需求开发、问题单处理与知识管理。平台以研发任务为单位，连接需求理解、方案设计、代码实现、评审验证和知识积累，让人的判断、AI 的执行与实际交付结果保持关联。

一次研发任务的完成，需要理解业务背景、协调代码改动、处理验证结果，也需要团队作出判断。Mae-Flow Cloud 将这些环节纳入统一的任务过程：AI 承担研究、设计、编码与检查，人在关键节点确认方向和质量，平台保存执行记录，并对接代码仓、合并请求和流水线。任务中形成的组件用法与团队经验，经过审查后进入知识库，供后续研发使用。

## 面向三类研发工作

| 工作场景 | 主要能力 | 业务价值 |
| --- | --- | --- |
| 需求开发 | 组织澄清、规格、设计、编码、评审与交付验证；支持较大需求拆分为关联子任务，共享需求和架构背景。 | 为较长、涉及多个仓库的研发任务提供连续的上下文和执行记录，方便团队判断进展、检视结果和继续推进。 |
| 问题单处理 | 根据问题单和现场材料分析定位，支持修复、代码提交与流水线反馈处理；没有正式问题单编号时，也可先开展研究并形成结论。 | 将现场信息、分析结论、代码改动和验证结果联系起来，支持问题处理过程的复查与协作。 |
| 团队知识管理 | 组织领域知识、组件用法、技能和团队经验的研究、审阅、发布与人工归档。 | 将分散在代码和任务过程中的经验整理成有来源、有版本、可复用的团队资料。 |

## 核心设计与创新

### 将人工判断纳入 AI 执行过程

在需要人作出决定时，系统保存问题和背景，暂停相应会话，收到回答后继续执行。恢复过程中，已回答的问题直接复用原决定，失效问题不再重新生成人工待办。人工判断有明确的发生位置和记录，任务也能在中断后继续。

### 让交付状态有事实依据

平台对接代码仓、合并请求和流水线。以问题单推送为例，系统执行 Git 推送后，再读取远端分支的提交号，核对一致才返回成功结果。流水线失败时，系统把当前提交对应的失败摘要、检查明细和可取得的完整产物交给 AI 处理；同一提交反复失败或修复次数用尽时，停止自动修复，保留执行记录和已有诊断，供人接手。

### 将知识生产做成可审查的工作

组件研究按能力盘点、规划、接口契约、使用示例、误用边界和汇总逐步展开，各项工作按依赖执行并经过独立评审。研究过程持续保存进度，单次运行中每项失败工作最多尝试三次，再次继续时保留已完成成果。专家审查草稿、提出修改意见，并选择正式发布的内容。

### 为长期使用考虑版本与恢复

知识发布会核对所选内容、所见版本、最新修改建议，以及建议中的源码引用和调用证据。系统先记录本次发布的内容与目标版本，再写入正式知识和研究记录，使中断后的发布可以恢复；如果正式知识的版本或修改历史与本次操作的预期冲突，则提示并拒绝覆盖。需要进入代码仓的知识，由人另外发起归档。

## 项目价值

Mae-Flow Cloud 提供了一套围绕真实研发任务使用 AI 的工作方式。研发人员可以把研究、实现和检查工作交给 AI，同时保留对方向、方案与质量的判断；团队可以依据代码提交、验证结果和过程记录检查任务进展；经过审查的知识可以继续服务后续任务。

项目的技术积累集中在 AI 执行组织、人工协作、交付验证和知识复用之间的衔接。通过将这些能力落实为可运行的系统，为团队持续扩大 AI 应用范围、评估交付效果和改进研发方式提供基础。
