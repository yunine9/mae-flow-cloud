# 跨仓联合知识萃取与专家审核

全量萃取以所选语言下全部启用的组件仓为一次研究范围，不再为每个仓创建独立任务。仓库是源码来源，审核清单中的“组件”是可独立理解和复用的能力；一项能力可以涉及多个仓。

## 研究与产物

联合分析接口、协议、发布配置、构建目标、测试与调用关系，细分面向使用方的能力及值得核对的候选，不要求先证明对外发布才开始研究。没有“十几个组件”或固定主题数量上限；有独立语义的同步、异步、取消、批量等用法需要分别识别，但不能为了数量拆分内部实现。

对外提供不等于 `public` 可见、能导入或能链接，也不等于公网开放。重点关注 `interface/`、`idl/` 等目录，与 SDK/POM、文档、安装清单及导出配置相互核对，不规定固定阅读顺序，目录名不是白名单。IDL、`.proto` 等协议要继续追踪生成入口及对应构建产物。Java 的 public 类、JAR 内部实现、测试专用入口或历史上的跨仓内部调用，都不能自动成为推荐 API。允许多分析：有价值但对外属性未确认的候选可进入默认全选的审核清单，在标题及接口说明标注“待核实”和证据缺口；相关内部机制标注“内部实现参考”。默认勾选不等于专家认可。推荐用法应有对外依据；候选示例说明未确认条件，不能冒充可直接用于生产的方案。

不同仓的约定可写在配置中心的“组件说明”中，例如“重点关注 interface/、idl/，结合 sdk/pom.xml 分析；impl/ 仅供内部参考”，无需新增硬编码目录规则。这些提示不会放宽配置路径的读取范围。相同规则应用于全量研究、主题研究、历史任务继续执行和专家局部返工。

对外 SDK 的重点入口是 `sdk/pom.xml`：在配置读取范围内存在时必须读取，继续追踪 `modules`、子模块 POM、父 POM、属性和 profile，并结合发布插件、跳过发布条件、发布目标及发布脚本判断哪些模块对外提供。不能把聚合模块列表或依赖列表直接视为发布清单，也不能把父 POM/BOM 当作运行时 JAR。产物应给出“SDK POM → 模块发布配置 → 制品坐标 → 对外接口”的证据链，说明版本、打包类型及必要分类；推荐示例使用对外制品，候选示例就地说明尚未确认的依赖。发布配置本身不证明某版本已经成功发布。缺失文件、范围受限或发布条件不明时如实记录，不能猜补，也不因此排除有研究价值的候选；其他目录和非 Maven 构建按实际约定处理，研究过程不执行构建或发布命令。

最终生成一篇 Markdown：跨仓关系概述、组件目录、各能力章节与关联组件。正文通过 `research_document` 工具分段保存，不依赖一次模型回复容纳整篇长文；联合研究的采纳容量为 16 MiB，普通手册上传仍为 2 MiB。

每项必须包含：

- 用法、适用条件、错误处理、资源生命周期等。
- 对外接口及依据：例如随 SDK 发布的 C/C++ 头文件及关键 API，Java 受支持的 API 包、类与接口，说明哪些内部入口不应直接依赖。
- 集成产物与依赖：例如 `.so`、`.a`、DLL、CMake target，或 JAR、Maven/Gradle 坐标，以及其他语言的包、模块和导入方式。必须从构建定义核对，不能猜名称。
- 最佳示例：必须有实际代码块，说明依赖、初始化、调用、错误处理与清理；不能只有 API 列表。C/C++ 示例必须包含实际 `#include`，按使用方安装或 SDK 导出的布局写头文件路径，尽量附 `CMakeLists.txt` 代码块及真实链接库名或导出 target（`find_package`、`target_link_libraries`，必要时 `target_include_directories`）。优先使用导出 target 传递依赖，并说明 target 与 `.so`/`.a`/DLL 的对应关系；纯头文件库说明无需链接二进制库，非 CMake 项目给出等价构建配置。Java 给出 `import` 与 POM/Gradle 依赖，其他语言同样给出导入及包依赖。名称须由构建、安装、发布配置或真实示例核对并附来源；查不到时说明缺口，不猜名字或使用作者机器的绝对路径。没有编译验证的示例必须明确标注。
- 来源与相关能力，保留实际读取的仓库、路径、行号和版本。

字段完整和代码块存在只证明内容没有缺项，不代表示例一定正确。研究指令要求对照实现、测试和真实调用，最终仍由专家审视。

## 审核与局部对话

清单默认全选，支持搜索、全选、全不选与单项排除。下载和采纳只包含勾选的章节，跨仓概述保留；被排除但仍被引用的依赖会标明未纳入，不能误认为依赖已消失。采纳只创建一篇知识文档，草稿不进入正式知识检索。

选中一项后可连续对话：

- “仅讨论”回答问题并保留对话，不修改任何章节。
- “按意见返工此组件”核对源码并仅修订所选章节，不重跑全量，不改其他组件和跨仓概述。涉及其他组件的修改建议由专家另行选中处理。
- 返工先保存本轮临时修订，成功后替换所选章节；失败、停止或服务重启均保留原稿与勾选状态。失败后的重试仍处理同一个组件、同一条意见。

同一研究只执行一轮操作，避免并发修订互相覆盖；执行期间可先填写下一条意见，完成或停止后发送。原研究的源码版本保留，局部返工不会悄悄改用其他版本。已采纳文档保留研究来源和对话，重新研究请新建任务。

## 兼容与验收

历史逐仓批次继续按原结构查看、采纳及重试，不会自动转换或覆盖旧知识。新建的全量任务使用联合研究；指定主题的研究保持原有行为。

定向测试涵盖真实 Git 与研究会话工具调用、HTTP 接口、单篇长文、默认全选、缺示例拒绝完成、限定章节返工、失败与停止保稿、重启恢复，以及 1920×1080 和 1366×768 桌面浏览器交互。
