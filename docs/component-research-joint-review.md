# 跨仓联合知识萃取与专家审核

全量萃取以所选语言下全部启用的组件仓为一次研究范围，不再为每个仓创建独立任务。仓库是源码来源，审核清单中的“组件”是可独立理解和复用的能力；一项能力可以涉及多个仓。

## 研究与产物

先联合识别对使用方提供的受支持接口，再结合构建目标、测试与调用关系细分能力。没有“十几个组件”或固定主题数量上限；有独立语义的同步、异步、取消、批量等用法需要分别识别，但不能为了数量拆分内部实现。

对外提供不等于 `public` 可见、能导入或能链接，也不等于公网开放。优先研究 `interface/` 等对外目录，结合各仓的文档、安装清单、导出及发布配置判断，目录名不是固定白名单。Java 的 public 类、JAR 内部实现、测试专用入口或历史上的跨仓内部调用，都不能自动成为推荐 API。每项接口说明必须附对外提供的依据；未确认的候选只留在研究记录，不进入默认全选清单。最佳示例只使用受支持入口和正常发布依赖。

不同仓的约定可写在配置中心的“组件说明”中，例如“优先研究 interface/；impl/ 仅供内部使用”，无需新增硬编码目录规则。这些提示不会放宽配置路径的读取范围。相同规则应用于全量研究、主题研究、历史任务继续执行和专家局部返工。

最终生成一篇 Markdown：跨仓关系概述、组件目录、各能力章节与关联组件。正文通过 `research_document` 工具分段保存，不依赖一次模型回复容纳整篇长文；联合研究的采纳容量为 16 MiB，普通手册上传仍为 2 MiB。

每项必须包含：

- 用法、适用条件、错误处理、资源生命周期等。
- 对外接口及依据：例如随 SDK 发布的 C/C++ 头文件及关键 API，Java 受支持的 API 包、类与接口，说明哪些内部入口不应直接依赖。
- 集成产物与依赖：例如 `.so`、`.a`、DLL、CMake target，或 JAR、Maven/Gradle 坐标，以及其他语言的包、模块和导入方式。必须从构建定义核对，不能猜名称。
- 最佳示例：必须有实际代码块，说明依赖、初始化、调用、错误处理与清理；不能只有 API 列表。没有编译验证的示例必须明确标注。
- 来源与相关能力，保留实际读取的仓库、路径、行号和版本。

字段完整和代码块存在只证明内容没有缺项，不代表示例一定正确。研究指令要求对照实现、测试和真实调用，最终仍由专家审视。

## 审核与局部对话

清单默认全选，支持搜索、全选、全不选与单项排除。下载和采纳只包含勾选的章节，跨仓概述保留；被排除但仍被引用的依赖会标明未纳入，不能误认为依赖已消失。采纳只创建一篇知识文档，草稿不进入正式知识检索。

选中一项后可连续对话：

- “仅讨论”回答问题并保留对话，不修改任何章节。
- “按意见返工此组件”核对源码并仅修订所选章节，不重跑全量，不改其他组件和跨仓概述。涉及其他组件的修改建议由专家另行选中处理。
- 返工先保存本轮临时修订，成功后替换所选章节；失败、停止或服务重启均保留原稿与勾选状态。失败后的重试仍处理同一个组件、同一条意见。

同一研究只执行一轮操作，避免并发修订互相覆盖；执行期间可先填写下一条意见，完成或停止后发送。原研究的源码版本保留，局部返工不会悄悄改用其他版本。已采纳文档保留研究来源和对话，重新研究请新建任务。

## 兼容与验收

历史逐仓批次继续按原结构查看、采纳及重试，不会自动转换或覆盖旧知识。新建的全量任务使用联合研究；指定主题的研究保持原有行为。

定向测试涵盖真实 Git 与研究会话工具调用、HTTP 接口、单篇长文、默认全选、缺示例拒绝完成、限定章节返工、失败与停止保稿、重启恢复，以及 1920×1080 和 1366×768 桌面浏览器交互。
