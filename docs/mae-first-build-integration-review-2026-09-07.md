# MAE 首次构建接入（2026-09-07 已实现）

以用户内网实测 Skill 为依据，适配需求流预热、问题流预热与 Build-Fix。

## 已接入

- MAE CodeHub HTTPS 仓自动由宿主准备四个辅助仓，并将首次解析的 SHA 固定到任务。
  凭据留在宿主，克隆失败的临时目录不会当成成功现场；既有辅助仓的来源、HEAD、
  已跟踪文件变化会被核对。辅助仓缺失/污染如实报构建资源问题，不换版本继续。
- 需求流以四个只读卷和一个可写缓存卷保留脚本要求的同级布局。
  问题流沿用会话内 repo/ 布局，宿主可在 pull_repo 后补齐辅助仓；其文件随现有
  工作区可写挂载，不扩展到其他任务。辅助仓的 AGENTS.md 不进入业务仓上下文。
- 每个容器恢复 HOME 中的 npm 配置和 scope 路由，覆盖 MAE 任务继承的旧默认源。
  Maven 保留平台只读 settings，构建缓存属主按容器用户准备，ccache 仍可选。
- 内置 mae-first-build 通过现有只读 Skill 快照进入会话；同名旧版本不重复装载。
  问题流预热也加载团队 Skill，后续可用语言专项 Skill。
- 容器内包装器调用 pre_build.sh 和 Agent 根据仓库事实选择的真实编译命令。
  首次成功才写准备记录；主要构建配置、辅助仓版本、镜像或工具链变化会失效，
  普通源文件变化不触发全量。保留构建输出，后续按语言 Skill 与 build-notes 增量。
  包装器每次 run 都执行传入命令，不会用准备记录冒充当次编译成功。
- 修正完整 POM parent 解析、cgroup v1/v2/max/小于一核，以及跨 Bash 的 source 误用。
  Java 预热跑 package -DskipTests；JS 先装依赖；C++ 遵循仓库脚本，不强制全部走 Maven。
- MAE 预热默认 90 分钟，Build-Fix 默认整轮 90 / 重型命令 75 分钟；包装脚本可识别为
  重型命令。部署显式预算仍有效，用户取消与既有失败收口保留。

## 验证与边界

本机已验证辅助仓固定/失败重试、Skill 只读可达、首编成功与失败记录、配置失效、
源文件增量、路由恢复；真实 Docker 已验证只读辅助仓、跨容器 HOME 恢复和准备记录复用。
Docker 使用本地镜像与受控脚本/JS 语法检查，未连接内网制品库，未完成真实 FarsService 编译。

上线后需用 FarsService、一个 Java 仓、一个 JS 混合仓各跑一次首编和一次增量。
确认四个辅助仓读取权限及 pre_build.sh 在真实镜像下的输出。不能把所有只读错误视为
良性：SDK、签名工具或业务依赖仍以实际构建需要为准。

用户提供的配方只验证了 euleros_x86；其他架构需由部署提供已验证的
MFC_MAE_BUILD_PLATFORM，平台不会假定 ARM 与 x86 等价。

未限定 scope 的内部 npm fork 可能需要安装命令显式使用 product_npm；Skill 给出
仓库级处理方式，不对所有业务仓强改全局源。记录只覆盖主要构建输入，子模块配置和
生成目录是否可增量仍需结合仓库检查。首编准备状态不替代真实编译、定向 UT 和远端流水线。
