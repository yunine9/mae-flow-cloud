# 新流水线接棒后停止重派旧失败

问题发生在 Agent 的 `task_pipeline trigger` / `task_control trigger_pipeline` 路径：远端已接收新 SHA 的流水线，宿主只把响应拼成操作结果，再通过通用 resume 带着旧 mission 重开会话。任务的 delivery.sha、pipeline、loop.state 没有更新，旧失败继续被显示为当前待修。

修复：

- 正常交付和 Agent 主动触发共用流水线结果接收入口，更新实际验证 SHA、检查结果和验证状态，移交现有轮询/终态裁决；不经通用 resume 重开旧 CI 使命。
- `loop.last_sha/failure` 保留原始派单证据，不写成新 SHA，也不伪造 fixed/PASS。新 SHA 的失败才进入现有的新一轮派修。
- 新验证已接棒时，旧流水线反馈在 Agent 查询中标记 historical，不再生成旧回执补交任务。工作台批注与 MR 意见不受此分类影响。
- 流水线收据先持久化再登记；恢复可以复用收据，响应丢失则先查询对应 SHA，不盲目重触发。
- 升级前已成功触发、仍 repairing 且最后宿主操作为该次触发的任务，在会话恢复时重新查询当前推送 SHA 后接回验证，不修改真实失败历史。
- SHA 不匹配、is_valid=false 和空查询不能当作本次有效结果。仅推送而未触发流水线，不冒充已验证。
- 同 SHA 轮询标记同时绑定会话 epoch，旧轮询退出不会抹掉新轮询标记。

验证包括：脚本模型驱动实际主会话→真实本地 Git 推送→HTTP 流水线触发→验证接棒，不再次请求模型修旧告警；正常交付红→修复→新绿→待合入回归；收据恢复、历史批次、SHA 选择和轮询换代测试。没有连接内网 task-7，需部署后验收现场。
