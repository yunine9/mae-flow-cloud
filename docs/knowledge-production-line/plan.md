### 0.3 工作纪律（来自 CLAUDE.md 与本仓记忆，违反即返工）

- **共享工作副本**：
  - 不用 `git stash`、`git checkout -- <file>`、`git reset`。
  - 工作区里有别人的未提交文件（`docs/mae-flow-external-sharing*.md`、`scripts/benchmark-*tps.mjs`、`.claude/` 等），一律不碰、不提交。暂存只加自己改的路径，必要时按 hunk 选择。
  - 推送前 `git fetch`。如果 origin/main 已经前进，先 rebase；冲突解不干净时推到 topic 分支，不动 main。
- **测试串行**：同一时间只允许一个测试进程，跑之前先 `pgrep -fl "tsx --test"`。两个进程会互删临时现场，症状是全量测试无输出地卡住。
- 不 `colima start/stop`，不起真模型，不改 `.pilot/`。
- **不留兼容**：
  - 删就删干净，不写迁移垫片，不保留旧深链的重定向，不为旧数据写回退分支。
  - 旧数据目录用一次性清理脚本删除（放 `scripts/`，跑完即可删）。
- **不卡死红线**：
  - 新引入的等待一律带预算。
  - 基础设施故障先带预算重试；重试用完，如实写 failed，原因写进 detail，并通知人。
  - 不无预算干等，也不静默放行。
- **前端不推断状态**：文案、分组、下一步动作全部来自后端字段，前端只负责渲染。
- **卡片自述使命**：等待人处理的卡片用动词开头说核心动作（如"请审查草稿"），并说明操作在哪、提交后会发生什么。
- 注释写为什么，尤其是踩过的坑；实测结论注明来源（例如 "repros/r3 实测"）。
- 提交信息格式：`type(scope): 中文一句话——机制/教训`，正文讲语义和实锤，不逐文件罗列。
- 改界面前后各跑一次 `npm run visual -- --out <目录>`（先 `cd web && npm run build`），再用 `--compare` 逐像素比对；每一处差异都要能说出对应哪条规则。
- `web/src/tailwind.css` 是唯一样式文件。行数棘轮在 `tests/tailwindCssIntegrity.test.ts`，确需上调时要同票写明理由。

## 5. 验收清单（每条至少一个测试，测试名带条目号）

1. 服务启动后不访问任何接口，N 秒内排队或运行中的研究开始接续，running 批次被重排（F4）。
2. 执行体不响应 abort：停止后在预算内释放槽位，状态如实写 failed 并附原因，任务可以继续；其他人排队的任务能开始跑（F3）。
3. 任意一条记录损坏：其余任务照常可用，任务中心的告警点名这个文件（F5、F20）。
4. 多篇发布第 k 篇失败（含模拟 kill -9）：要么一篇都没生效，要么已生效的每一篇都在磁盘记录里，并有待归档批次（F6）。
5. 归档的每个失败终态都有能真正推动进展的动作：MR 关闭后可以重试并开新 MR；"合入后远端被改"无论经发布还是刷新发现，核对后都能继续；未配置归档仓时直接指向设置页（F1、F2、F24）。
6. 同一任务的刷新、重试、发布、读远端、清理预览两两并发时，publication 记录不出现 lost update，也不会建出重复 MR（F7）。
7. 已开的 MR 在没人操作的情况下，T 时间内被自动刷新到 merged 或 closed；清理型合入会停用对应正式知识（F9）。
8. 状态投影只有一个来源：sync failed、diverged、closed、研究失败叠加归档失败等组合下，任务中心和详情页的文案、分组一致，都归到"需要处理"（F10–F12，7 处判断）。
9. MR 平台返回 400/401/403/5xx、git 鉴权或网络失败时，错误里有平台原因和下一步：确定性错误不提示"重试"；暂时性错误先带预算自动重试，用完后标 failed 并通知发起人（F13–F15）。
10. 组件发布由服务端一次调用完成；中途失败时，任务中心能看出"已入库 · 未归档"（F8）。
11. 批注所在那一轮失败、被停止或建议被放弃时，批注回到可提交状态（F16）。
12. 增量更新由不同的人发起、或换了令牌之后，来源差异仍能算出来；算不出来时如实说明"基线不可得"（F17）。
13. 重复点"创建研究"或"提交 Skill"不会产生第二个实体（F21、F20）。
14. 第 3 节"必须守住"列出的回归项全部仍有测试且通过。
