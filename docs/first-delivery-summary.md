# 首次交付摘要

首次代码已推送且 MR 创建成功后，Cloud 旁路启动独立 Pi 子会话，使用任务主模型。主任务不等待摘要，照常进入流水线和 MR loop。这里只生成首次交付快照：后续提交、检视修复、流水线更新以及服务重启都不重新生成。

子会话通过 `delivery_source` 读取固定首次提交和目标分支共同祖先之间的 diff、源码和搜索结果，不读可变工作区，不开放 Bash、写文件、人工提问或继续派发子 Agent。已有测试记录在启动时冻结；设计文档仅作背景，执行结果不足写“未确认”。

提示词在 `src/deliverySummaryAgent.ts` 的 `DELIVERY_SUMMARY_MISSION`：必须有 PlantUML 图、最多三条改动要点、主要测试场景短表。按 4+1 思考，但不凑五张图。正文尽量 300～500 字。图使用现有本地 PlantUML 渲染器校验；缺图或语法错误仅给一次修图机会，不重新分析代码。摘要旁路最多运行 10 分钟，失败不影响交付。

成功后原子发布任务根目录的 `交付摘要.md`，通过现有产出文档入口读取，不写业务仓、不提交代码。工作台显示“首次交付摘要已生成”的查看入口；小鲁班通知责任人联系对应 Committer 审视，链接带 `deliverySummary=1`，直接打开文档。通知使用既有 Notifier 的幂等和失败投递机制，不增加确认卡。未配置通知器或责任人时仍发布文档。

任务目录 `delivery-summary/` 保留首次输入、子会话事件/记录及 `state.json`。首次领取标记防止重复生成；失败或服务中断不会随 loop 自动重试，避免重复消耗。生成失败没有摘要通知，原因保存在状态及服务日志。历史上已经创建 MR 的任务不回补。

验证覆盖固定版本读码、非阻塞执行、循环与重启去重、失败/关停不影响交付、文档列表及读取、小鲁班通知隔离、真实 Pi 工具调用及修图、真实 PlantUML 渲染、浏览器提醒及通知直达。
