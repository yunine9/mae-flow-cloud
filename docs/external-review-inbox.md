# MR 外部意见由责任人交办

数字人或检视人提出建议不等于责任人同意修改。需求与问题单均把新意见同步为批注，保留原文、作者和 MR 入口；不再因为讨论门禁未通过而自动开启检视修复。冲突与客观 CI 失败仍按原修复入口处理，实际 MR 门禁仍以平台结果为准。

责任人可以自行答复、本地闭环或删除，也可以先保存每条意见的补充修改要求，再批量提交给 Agent。保存说明不派发修复，提交只包含当次批次，不包含后来新增的草稿。运行中追加意见沿用当前会话；等待真实用户决定时保存批次，答复后接续，不撤销决定卡。并行与进度反馈见 [并发交办说明](concurrent-review-delivery.md)。

本地处置与远端讨论分开记账。重复轮询、重启或提交 SHA 变化不会使已删除、已答复、已闭环的同一意见重新出现。同一讨论有新正文会产生新的待判断批注；不同报告 ID 的正文、作者、文件与位置完全相同时去重，不让相同报告反复打扰。语义相近但正文不同仍保留，平台不替责任人猜测。

每五分钟汇总尚未通知的新意见，通过现有小鲁班通知入口发送。首次发现可立即通知；之后只发上次成功通知以来的新增，成功后持久化记账，失败下轮重试。旧意见一直未处理也不会重复提醒。多条意见合并为一条数量与简短预览通知，正文仍在工作台。

长报告默认显示三行预览，展开后在最多 480px 的区域内滚动阅读完整原文。需求工作台不再重复显示独立的 CodeHub 长报告清单；问题单提供同样的批注入口，并按每页八条展示。

升级不清空历史批次、在执行的会话或已入队回复，既有外部发送继续使用原 outbox 的幂等与版本校验。新发现的原始意见不再自动派发修复；旧通知标志不再唤醒问题单 Agent。需求侧读取已有完整观察材料时会补入批注账，旧摘要不会复活本地已删除的报告。

验证覆盖：长报告完整性与折叠、重复报告和新追问、本地处理后重新拉取、补充要求和批次隔离、五分钟通知及失败重试、重启续挂、人工交办与 CI 并发、旧 outbox 发送。变更均在 Cloud TS 与前端，未修改 mae-flow 内核快照。
