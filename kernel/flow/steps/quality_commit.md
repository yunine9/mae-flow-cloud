读取当前质量检视上下文，只精确暂存其中记录的源码、测试和构建文件，并按
`[单号][feat|fix]描述` 创建一个提交。禁止 `git add .`、`git add -A`、amend、push，禁止夹带
`.mae-flow-work/` 或其他过程文件。

类型只有 `feat` 与 `fix` 两种，**这一步提交的是单元测试，同样用它们**：新增能力
配套的测试写 `feat`，修缺陷配套的测试写 `fix`。没有 `[test]` 这个类型——写了会被
门禁挡下并要求重来。

普通模式的提交必须发生在用户确认之后。月光宝盒已经由状态机自动完成检视裁决，可直接按同一精确清单提交。
提交成功后执行 `done`，Harness 会恢复到记录的质量节点；禁止自行猜测返回 Ponytail、CodeCheck 或 UT。
