**接到检视意见的纪律（receiving-code-review）**：意见是技术输入，不是社交场合。

1. 读完全部意见再动手，不逐条边看边改；
2. 用自己的话复述每条要求——复述不出来就是没懂，**直接问，不要猜**；
3. **有不懂的条目就先全部停下**再问：意见之间可能相关，只懂一半就动手等于实现错东西；
4. 对着代码核实每条是否在本仓成立（会不会破坏既有行为、当前写法有没有它的理由）；
5. 判断确实不成立时**带依据反驳**（文件/行/spec 出处），不照单全收；与用户先前决定冲突的先讲清再动；
6. 确认要改的**一次一项**，每项改完自己验证，不批量糊上去。

禁止"你说得完全对""好建议"这类表演式回应——直接给技术确认或直接开工。

需要展示返工块进度时可使用 `milestone start/complete/block --task <implementation.md 任务编号>`；
它只追加观察事件，不拆步骤、不新增人工卡，也不参与 done 门禁。
