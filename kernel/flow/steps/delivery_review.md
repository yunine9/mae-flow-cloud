实现与领域归档已结束。执行 `manifest set` 生成当前尚未提交改动的精确交付清单
（源码通常已在编码步提交，这里多半只剩归档产生的领域文档等收尾增量。检视中
发现真实缺陷可以直接改码修掉——改动作为新的未提交候选进清单即可，本步不存在
源码冻结）。

有真实增量时，使用
`manifest set --file <精确路径> [--file <精确路径>...] --message <提交说明> --target <目标分支>`。
清单只能包含当前尚未提交的真实候选增量，禁止把已经提交的源码再次加入清单。

归档结果明确为 `unchanged` 且没有新增待交付文件时，使用
`manifest set --unchanged --target <目标分支>`。该命令生成已确认的空操作清单，直接执行 `done`；
无需询问用户，也无需创建空提交。COMPILE 证据能够证明的本地构建产物会按
路径与内容指纹记入“不交付现场”，不阻塞本命令，也不需要改业务仓 `.gitignore`。
若命令仍点名文件，说明它们不是可证明的构建产物：检查是否漏交源码或资源；
不要用宽泛忽略规则强行消音，确实判断不了时才按目录汇总后明确询问一次。

清单与完整 diff 用户会在工作台与 MR 上看到。

{{#LOCAL_HOST}}
月光宝盒：禁止询问用户，使用 `manifest confirm --auto` 绑定同一精确清单，并把自动裁决、
完整 diff 和质量证据写入晨间报告。
普通终端模式向用户展示清单，只确认一次；收到回答后执行 `messages`，再用
`manifest confirm --message-id <消息ID>` 绑定文件、提交说明和目标分支。
{{/LOCAL_HOST}}

非空清单确认后执行清单给出的精确 `git add -- <文件...>`，再按 `[单号][feat|fix]描述` 创建一个提交；
禁止目录、glob、全量暂存、amend 或夹带过程文件。提交成功后执行 done；非空清单没有真实提交不能进入 push。
