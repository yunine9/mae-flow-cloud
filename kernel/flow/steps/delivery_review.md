整理这次实际要交付的文件和检视依据。清单可以包含已提交文件和待提交文件；代码与领域文档可以一起提交，不按阶段强制拆分。

有交付文件时使用：
`manifest set --file <路径> [--file <路径>...] --message <提交说明> --target <目标分支>`。

没有新增待提交文件时，使用 `manifest set --unchanged --target <目标分支>`；已有提交仍继续交付，不创建空提交。无需等待 domain-archive 记录变成特定状态。
如果工作区仍有源码或构建产物，先核对哪些要交付：要交付的明确列入清单，其余原样留在工作区。不要为了通过内部检查删除构建缓存或回退已经正确的改动。

确认后提交尚未提交的改动，再执行 `done`。提交说明建议带单号，但格式、暂存方式、内部文件分类都不会否决人工选择。相同内容仅暂存或提交不使确认失效；实际交付内容变化仍需让人知情。
质量失败和未执行的检查如实呈现；不能编造通过。推送与流水线状态来自实际执行结果。
