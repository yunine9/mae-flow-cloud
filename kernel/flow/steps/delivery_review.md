整理这次实际要交付的文件和检视依据。清单可以包含已提交文件和待提交文件；代码与领域文档可以一起提交，不按阶段强制拆分。

有交付文件时使用：
`manifest set --file <路径> [--file <路径>...] --message <提交说明> --target <目标分支>`。

先查看 `manifest show`；清单已准确包含本次交付文件时直接复用，不因已提交或已推送而改成空清单。只有确实没有新增待登记文件且工作区无未归类残留时，才使用 `manifest set --unchanged --target <目标分支>`；它不表示“当前 HEAD 已经推送”。已有提交仍继续交付，不创建空提交，无需等待 domain-archive 记录变成特定状态。
如果工作区仍有源码或构建产物，核对后用 `--file` 明确列出本次要交付的文件（包括已提交文件），其余原样留在工作区。不要为绕过 `--unchanged` 的检查删除构建缓存、回退正确改动或反复尝试空清单。

确认后提交尚未提交的改动，再执行 `done`。提交说明建议带单号，但格式、暂存方式、内部文件分类都不会否决人工选择。沿用已记录的用户确认，不因暂存、提交、清单登记或会话恢复重复提问。确认后有实质修改，由 Agent 简短说明变化，按用户既有授权继续；只有超出授权或确需业务裁定时才集中提问。内核不再以内容指纹作废人工决定。
质量失败和未执行的检查如实呈现；不能编造通过。推送与流水线状态来自实际执行结果。
