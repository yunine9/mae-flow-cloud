# 内核职责（2026-09-09 用户决定）

内核是执行协调和事实账本，不是质量裁判。默认生效，没有增加部署开关。

## 撤掉的否决权

- done 的模板、关键词、产物存在性、指定 Agent 回执、任务清单、规格校验、范围档位、领域归档、提交格式与本地验证结果：记录真实失败或检查异常，作为提示继续推进。
- 本地 Git add/commit 的宽暂存、命令包装、别名、pathspec 文件、单命令多次提交、文件来源、构建产物分类、精确修复批次：由 Agent 按人的任务执行，不另签许可证。
- 文件交付的过程文档禁入、领域归档凭证必备、候选增量归属、逐文件采用证明及领域文档原子组：保留选定文件，提示疑虑，交给人检视。
- 推送验收的文件来源与本地残留否决：只核对实际推送事实，不重复裁决人选择的文件。
- 子 Agent 必须先有指定任务卡、按角色文件清单活动：任务卡作为指导，仍记录真实生命周期。
- 同样内容因暂存/提交而改变 HEAD、索引状态：审批继续有效；提交说明变化也不作废文件选择。

## 保留的职责

- 记录和恢复流程位置、人的实际回答、检视意见和交付事实。
- 不代替人确认，也不把质量检查失败或缺失改成 PASS。
- 工作区访问边界、真实权限、取消和接管控制由既有执行链保留。
- 强推、清空未提交工作、伪造状态/流水线事实等明确危险动作的边界保留。
- 发布阶段真实分支与远端 HEAD、权威流水线结果仍核对；已有人在平台合入时继续采用原有可信人工合入处理。

历史流程文字若要求因上述已撤权检查反复征求许可，以本文及 current 输出的减权说明为准。
原检查器可用于诊断，但不因它们的失败阻止 done。记录未完成的检查和实际风险，供人阅读。

## 验证范围

使用真实临时 Git 仓和生产 CLI 验证开发动作、归档缺失时推进、人工文件选择、审批跨 add/commit 稳定；
保留危险命令、真实推送事实、人工回答和内容变化的回归检查。内网真实业务任务需部署后继续验证。
